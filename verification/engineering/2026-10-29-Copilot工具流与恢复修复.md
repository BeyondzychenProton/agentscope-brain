# Copilot 工具流与恢复修复

2026-10-29，基于 `065857f`，分支 `codex/issue-45-agui-copilotkit`。用户先报告“调用工具时显示工具标签，随后没有消息”，在设计审查后明确要求修复。本记录只报告本次实现和实测，不关闭 #46/#41，不代表阶段验收或部署完成。

## 原因与修复

原文本 Agent 未装载后端工具，transport 拒绝原生工具调用；正文工具标记则由另一个非流式执行器补做。补做取决于标签后文字是否为空，SDK `RunError` 又绕过异常补救入口。前端另外解析正文画工具外观，存储只保存合并文字，无法恢复真实工具过程。

本次将执行收回同一个请求级 Agent：

- `ReadonlyAgentTools` 仅装载固定员工发布版本中的既有只读工具，操作者来自已接纳线程的可信平台用户；工具以安全名称别名注册，MCP 使用可信用户当前手机号签名。
- 原生模型工具调用进入 SDK 工具循环。模型使用同一员工发布配置，多次工具调用后继续流式回答，取消通过同一订阅传播。
- 兼容旧模型的 `<tool_call>` / `<tool>` 输出仅在模型 transport 内转换。分片标记不会进入正文；名称必须匹配本次实际发布给模型的工具，JSON 无效、调用未发布、截断或混用格式明确失败。带尾随过程文字的标记也进入同一工具循环。
- 删除 `CopilotToolReply`、`LeakedToolCalls` 及其字符串实现测试，替换为真实执行接口测试。没有第二次非流式补救调用或隐式模型切换。
- `RunDisplay` 统一归并文本与工具事件，正文增量与结构化展示在同一短事务写入。刷新恢复保留 SDK 消息 ID、工具调用 ID、参数和结果。
- 新增 schema 14 的可空 `display_json` 列，保留旧正文；重新从独占 MySQL 生成精确就绪基线。无自动迁移。
- 前端工具卡片只依赖结构化工具事件。旧正文清理仅移除历史控制标记，不生成执行状态；同时修正保留下划线的工具名称别名映射。
- 输出受到正文、结构化展示及事件数量上限控制。工具执行后的空收尾明确失败，错误不会再被记为成功。

reasoning 仍关闭。此次只接入既有只读工具，没有新增会议预约、取消会议等写工具。

### 回归结果

原有文本浏览器回归在同一合成链路检查登录/改密门槛、分段显示、多轮唯一历史、进行中刷新、停止关闭模型连接、未完成回复不进入下一轮、撤权/版本停用只读、退出取消，所有断言通过，模型请求 5 次。

全量验证同时发现并修正两项既有兼容问题：改名响应中的 `Timestamp` / `LocalDateTime` 强制转换；原浏览器夹具停用初始化发布时没有同步设置 USER_ACTION 来源。后者只修改隔离夹具，保留数据库约束。

## 追加：MCP 客户端联调修复

同日对 `MeetingMcpClient` 做了一次真实端点核对后的修复，与上面的工具流改动同属一个变更集。

**真实端点核对（2026-10-29）**

- `docs/对接文档/MCP身份查询联调说明 (2).md` 中的 `https://cms-test.shsets.com/stage-api/mcp` 整站返回 `502`（tengine/CTYun LB），配置内的 `https://cms-test-k8s.shsets.com/stage-api/mcp` 才可连。
- 按文档逐请求重签后，用 `13636528157` 调用：`initialize` 即返回 `HTTP 401 {"error":"Invalid MCP user"}`。对照实验为同一手机号配错 Secret 时返回 `Invalid MCP signature`，`+86` 前缀同样报签名错误，说明签名算法、App Key、毫秒时间戳和号码归一化都与服务端一致，被拒的是账号本身。
- JDK 17 `HttpClient` 与 curl 均可完成 TLS 建连并完成请求，排除客户端传输问题；本机与服务端时间差约 1 秒。账号问题已交服务端核对，未在本记录中推定已解决。

**修复项**

- `MCP-Protocol-Version` 由“仅 initialize”改为 initialize 之后所有请求都携带，符合 MCP `2025-03-26` 要求。
- HTTP 状态与 JSON-RPC 错误不再折叠成单一 `MCP_CALL_FAILED`：抛 `MCP_HTTP_401: Invalid MCP user` 这类含服务端原因的码，并记录 WARN 日志；`ReadonlyAgentTools` 用 `onErrorResume` 把真实错误码交给模型，同时记录工具名与 userId。日志不含签名、Secret 或完整手机号。
- SSE 解析按事件块处理：拼接多行 `data:`、跳过通知帧、优先返回带 `id` 的 JSON-RPC 响应。
- 按签名手机号复用 `Mcp-Session-Id`，服务端 404 时丢弃会话并只重建一次；每轮工具调用不再重复三次握手。
- 工具结果依次取 `structuredContent`、`content[].text` 内的 JSON、原信封，模型不再解析一层转义包裹。
- 校验握手返回的 `protocolVersion`，不一致时报 `MCP_PROTOCOL_MISMATCH`。
- `ReadonlyToolCatalog` 在契约缺 `inputSchema` 时记录 WARN；仍保留原来的空 schema 回退，不改变工具注册、事件结构和前端渲染。
