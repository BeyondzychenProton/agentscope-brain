# 思考过程不展示与用户消息重复（2026-10-29）

## 现象

1. 模型思考时不展示思考过程。
2. 用户发送一条消息后，模型开始思考时页面底部又出现一次同一条用户消息。

## 根因

1. `TextAgentExecution` 的 AG-UI 适配器配置为 `enableReasoning(false)`（SDK 默认值即关闭），推理事件在出站前被丢弃，前端 `messageView.reasoningMessage` 永远收不到 `REASONING_MESSAGE_*`。
2. 用户消息入库时使用服务端生成的 UUID（`CopilotThreadStore.accept`），与浏览器乐观渲染的消息 id 不一致。AG-UI 的 `MESSAGES_SNAPSHOT` 按 id 合并：快照里不认识的 id 会被**追加**，于是同一条用户消息出现两次。（助手消息不受影响：`display_json` 里保存的是适配器事件 id，与实时流一致。）

## 修复

- `TextAgentExecution`：`enableReasoning(true)`，推理事件恢复下发；`RunDisplay` 已有推理折叠与恢复逻辑，无需改动。
- 前端运行时 `route.ts`：把浏览器最后一条用户消息的 `id` 作为 `userMessageId` 送给 Java。
- `CopilotRuntimeController.Start` → `CopilotTextRuns.start` → `CopilotThreads.accept` 透传该 id。
- `CopilotThreadStore`：用户消息改用浏览器 id 落库；只有规范 UUID 才沿用，其余（含空值、大写、非 UUID）退回随机 UUID，避免与既有 `UNIQUE(thread_id, message_id)` 冲突或与前端 id 不一致。

## 验证

- `CopilotToolRunTest#reasoningStreamsVerbatimAndRecoversSeparatelyFromAnswerHistory`：修复前失败（思考文本为空），修复后通过；同一线程恢复时快照携带 `role=reasoning` 原文。
- 新增 `CopilotThreadStoreTest`：规范 UUID 原样保留，大写/非法/空值均替换为新 UUID。
- `mvnw test`：125 个用例全部通过；`formal-web` `tsc --noEmit` 通过。
- 浏览器端到端（真实模型思考展示、重复消息消失）仍需在具备模型与 MCP 环境的验收机上复核。
