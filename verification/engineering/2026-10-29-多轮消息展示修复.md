# 多轮消息展示修复

## 复现与原因

用户反馈：新回复后旧回复看起来消失，连续发送的历史用户文字被再次带到当前轮，消息和正文留白偏大。

在已登录的隔离浏览器中，发送一次“你好”后断言聊天区仅有一个同文气泡，修复前得到 `Actual value: 2`。随后记录合成事件和 DOM，确认 SDK 的 `RUN_STARTED.input.messages` 携带模型重放历史。AG-UI 客户端会按 ID 将这些消息追加到聊天区，而本轮模型输入的用户 ID 是另生成的 UUID，历史工具消息也可能与实时工具卡片使用不同 ID，形成重复用户消息与工具卡片。已有回答使用原 ID，因此不会随这些重复内容一起追加，造成“历史回答缺失”的视觉效果。实际浏览器 DOM 中原回答仍在原位置。

另发现结构化历史的 `reasoning` 被重放给 SDK 后会变成模型请求中的用户文字，违反思考仅作展示的既定边界。

## 修复

- `CopilotTextRuns` 在转发 SDK 运行开始事件时只保留平台线程与运行身份，不把模型内部重放输入传回浏览器；持久历史仍通过 `connect` 的平台快照恢复。
- `RunDisplay` 使用与 AG-UI 客户端一致的工具消息 ID：无父消息时用工具调用 ID，有父消息的 chunk 用父消息 ID。工具不会再被错误挂到前一条正文上。
- `TextAgentExecution` 从后续模型输入中排除思考展示块，保留用户、助手正文和工具调用／结果。
- 局部收紧用户消息顶部、思考区、助手正文、段落和列表间距。

## 验证接缝

`db/tests/执行Copilot文本隔离验收.py --multi-turn` 与 `--multi-turn --tools` 使用真实登录、React/CopilotKit Runtime、Java、独占临时 MySQL、合成模型及签名 MCP。连续三轮不刷新，逐轮检查旧回答、用户气泡数量、顺序和运行事件，再刷新核对；检查模型历史没有思考文本，工具每轮只执行一次。

验证结果：

- 后端 `mvnw.cmd -B -ntp -Dbrain.build.directory=target/chat-render-fix verify`：125 项单元／集成测试和 1 项产物隔离检查通过。
- 前端 `next build`（含 TypeScript 检查）通过；`node --test app/assistant-content.test.ts` 4 项通过。
- `--multi-turn`：通过，3 次模型请求；三轮消息无重复，旧回答保留，刷新前后 ID 完全一致。
- `--multi-turn --tools`：通过，6 次模型请求、3 次工具执行；三轮消息和工具卡片无重复，刷新前后 ID 完全一致。
- 浏览器页面无 JavaScript 异常；截图见 [普通多轮](chat-render-multi-turn.png) 和 [带工具多轮](chat-render-multi-turn-tools.png)。

真实共用数据库没有迁移或修改。运行中的本地后端需要重新加载修复后的代码，页面刷新后从持久历史恢复。
