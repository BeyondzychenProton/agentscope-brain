# 登录就绪基线修复

日期：2026-10-28，Asia/Shanghai。代码基点：`cc99e18`。

## 原因与修复

用户报告 CSRF 请求返回 `APPLICATION_NOT_READY`；启动日志列出
`STRUCTURE_MISMATCH:business_session` 和 `STRUCTURE_MISMATCH:session_projection_event`。
只读复现发现实际数据库已应用 schema 12，源码及编译目录的工作台基线仍是 01～10：
会话过程流的列、约束、CHECK，以及投影事件协议 CHECK 共四项不一致。

使用 `python db/tests/生成工作台结构期望.py` 在新建独占回环 MySQL 8.0.45 中执行
仓库 DDL，生成 01～12＋原生表的完整基线。生成环境共 52 张元数据表；
基线 SHA-256：`dedb0330a676861e86c83556e5f6e0900880f8c81b2f18c2039564b2914b9091`。
生成器只使用自建临时实例，不读取共用配置。实际数据库仅作只读元数据核对，没有执行 DDL、回滚结构或重置账号。

新增 `ReadinessBaselineSourceTest`，在默认 Maven 测试中核对工作台基线记录的
完整 DDL 集合和每个文件的 SHA-256。修复前定向运行失败，指出遗漏 schema 11、12；
修复后通过。生成器头部修订范围改由实际脚本列表确定，README 补充再生成流程。
