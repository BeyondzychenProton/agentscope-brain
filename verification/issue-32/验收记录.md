## 结构与证明边界

无物理外键、触发器、存储过程、真实密钥或 SDK 状态正文。单表 CHECK／唯一键负责结构；跨行引用与动态状态由巡检和探针中的条件事务共同证明。`recovery_status` 具体落为 MISSING／AVAILABLE／UNAVAILABLE；AVAILABLE 只表示完整副本字段，密钥或 GCM 可用性不在此结论中。

不可变展示与不可逆生命周期遵循受控 SQL，不宣称数据库能阻止具有任意 UPDATE 权限的操作者同时篡改正文和摘要、重置版本或密钥代次。真实服务实现及其事务测试留在后续阶段。

MySQL `BINARY(12)` 会对短输入补零，无法仅凭列类型证明原始参数恰为 12 字节。本次验证列类型、超长拒绝及一类短输入补成非法 counter=0 的巡检；阶段 4 必须在绑定参数前严格检查原始字节长度。JSON 草稿／回答的 SQL 大小检查针对数据库重表示，不能替代 HTTP 原始字节及 form-v1 校验。

nonce 的固定 keyId／前缀／代次在预留 SQL 条件中核对，游标只递增；没有实际加密。真正的独立提交后再加密、预留提交不明、崩溃、备份回退换钥仍未证明。合成调用／checkpoint 只证明关联约束，字段齐全或 VERIFIED 不冒充 SDK 持久消费证明。
