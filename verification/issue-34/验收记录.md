## 实现和可复现行为

1. `GET /api/auth/csrf` 建立／读取会话 CSRF；登录只接受手机号与密码，经参数化 SQL 查当前号码／稳定 UserId，验证限定 `{bcrypt}` cost=12。不存在的号与错误密码均为 `401 AUTHENTICATION_FAILED`；缺凭据、认证数据或 Session JDBC 表为受控 503。
2. 登录轮换匿名 Session ID、清除原 CSRF，并把只含服务器身份版本与原认证截止时间的上下文立即保存至 JDBC。密码不进入 Session、日志或浏览器持久存储。`me` 忽略客户端 owner／UserId／号码选择，只返回当前必要受限身份、掩码号码及空员工列表。
3. 受限身份仅开放 CSRF、me、首次改密及退出入口；历史、素材、能力／订阅、普通提交均在服务端拒绝，客户端直达 `/workbench` 重新读取 me 后返回受限页。业务接口整体保持关闭，没有 Run、模型或工具装配。
4. 启动只读比较平台 01～06 登录基线、SDK 三表、Session 两表的实际列、类型／默认值／排序规则／生成列、索引、CHECK 正文、引擎及原生外键；再核验必要预置引用、发布／绑定／Skill／资源摘要和本机受控配置引用。缺项记录具体受控码，`/readyz`、认证入口和 Boot 内部可接流量状态均拒绝。合法停用／撤权不被视作结构损坏。
5. 启动与登录均不探测模型、MCP、MinIO。隔离环境把这些目标指向返回 503 的计数服务，全部验证结束调用数仍为 0。生产 Cookie 的 Secure／HttpOnly／SameSite=Lax／Path=/／无 Domain 及 `__Host-ASSESSION` 在隔离 prod profile 验证；真实开发只使用回环开发 Cookie。

复现：前端依次 `npm ci --ignore-scripts --no-audit --no-fund`、`npm run typecheck`、`npm run build`；后端运行 `scripts/检查工程规范.ps1` 与 Wrapper `verify`。随后从仓库根目录显式运行 `python db/tests/执行Web受限登录隔离验收.py`。结构修订用独立 `生成登录结构期望.py` 在自建实例重建期望，不能在真实库重跑初建。
