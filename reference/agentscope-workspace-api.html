Workspace API 速查

定位入口、理解路径和分桶、判断写入后端。依据固定版本官方文档与源码。
第 1 课：API 调用链 第 2 课：隔离范围 第 3 课：调用时装载与应用直写 第 4 课：路径、后端与分桶 第 5 课：上传文件与 Agent 产物

1. 关键入口

API用途
HarnessAgent.builder().workspace(Path)设置逻辑工作区根目录。
.filesystem(FilesystemSpec)选择本机、远端共享存储或沙箱文件后端。
RuntimeContext.userId / sessionId提供当前运行身份与会话上下文；用户身份应由平台认证层提供。
agent.workspaceFor(userId, sessionId)应用侧按请求取得绑定该用户/会话的 WorkspaceManager view。
WorkspaceManager.writeUtf8WorkspaceRelative(...)通过 workspace-relative path 写入；按当前 AbstractFilesystem 路由。
WorkspaceContextMiddleware每次进入推理阶段时，根据当前上下文和配置重新装载需要注入的 Workspace 内容。

2. Workspace 根目录的解析顺序

  1. Builder 显式设置的 workspace(Path/String)
  2. 系统属性 agentscope.workspace
  3. 环境变量 AGENTSCOPE_WORKSPACE
  4. 默认值 ${user.dir}/.agentscope/workspace

路径指定根目录；它本身不等于用户授权策略，也不单独定义 AgentState 的持久化位置。

3. 常见逻辑目录

workspace/
├── AGENTS.md                 # Agent 人格与规则
├── tools.json                # 可选的工具/MCP 配置
├── knowledge/                # 领域知识入口与参考资料
├── skills/<name>/SKILL.md   # 可复用技能
├── subagents/<id>.md        # 子 Agent 声明
├── MEMORY.md                 # 长期记忆
├── memory/YYYY-MM-DD.md      # 记忆流水
├── plans/                    # Plan Mode 工作产物
└── agents/<agentId>/         # Session log、Task 等运行文件

目录是逻辑布局，可以映射到本机、Remote KV 或沙箱。Workspace 内容按生命周期有静态资产、运行产物和长期记忆；AgentState 不在这棵 Workspace 树中。

4. IsolationScope

Scope命名空间共享者备注
SESSION同一 sessionId按对话隔离
USER同一 userId 的所有会话v2.0.4 默认；缺 userId 时退到 sessionId
AGENT同一 Agent 的所有用户与会话适合明确共享的知识
GLOBAL同一个 store 实例共享最大；谨慎选择

IsolationScope 控制 Workspace/filesystem 分桶；不要把它推导成平台授权、业务 Session 或 AgentState 隔离已经全部满足。

5. 三个数据面

数据面典型内容主要责任
Workspace定义文件、知识、技能、计划、长期记忆、会话日志Harness 文件能力与 filesystem 后端
AgentState当前 Agent 执行恢复用的结构化上下文AgentStateStore
平台业务存储账号授权、业务 Session/Run、预约与审计本项目数据库与业务服务

会议预约事实应以会议系统或平台业务记录为准；Workspace Memory 适合表达可更正的个人偏好，不能作为交易事实来源。

6. I/O 边界

  • 运行时文件读写走 WorkspaceManager 的相对路径方法，避免后端路由失效。
  • 在 Remote/Sandbox 模式中，直接用 java.nio.Files 可能落到宿主磁盘。
  • 启动前写本地模板文件是例外；那时没有运行时 filesystem binding。
  • 路径 traversal 校验不等于业务授权；仍要在应用边界检查当前用户能否访问目标内容。

7. Agent 调用与应用直写是两条入口

  • agent.streamEvents(message, context) 发起一次 Agent 调用；Harness 在推理阶段装载相应的 Workspace 上下文。
  • agent.workspaceFor(userId, sessionId) 返回请求级 WorkspaceManager 视图；用于应用代码显式读写文件，本身不触发推理。
  • writeUtf8WorkspaceRelative(context, relativePath, content) 使用逻辑相对路径，并通过当前 filesystem 写入。

关键文件会在后续调用中重新装载。知识目录通常注入入口和路径清单，具体文件由需要它的 Agent/应用按需读取；目录存在不等于其中全部正文已进入模型提示词。

8. 文件系统后端与 scope 分开读

  • filesystem(FilesystemSpec) 选择 Local、Remote 或 Sandbox 等文件 I/O 模式。
  • IsolationScope 选择 Workspace/filesystem 运行时数据如何分桶。
  • RemoteFilesystem 默认只把规则指定的路径路由到共享 KV；其他路径可以仍走本地文件系统。
  • 跨副本可见性还要求各副本连接同一个共享后端；仅配置同一个 scope 不会自动创建共享存储。

9. 上传素材与 Agent 生成文件

  • 正式上传原件由平台私有对象存储保存，SQL 保存消息归属和稳定对象元数据。
  • Workspace/filesystem 可提供 Agent 的受控工作副本或生成暂存区。
  • writeUtf8WorkspaceRelative 适合 UTF-8 文本；不要拿它存任意二进制。
  • 用户可下载的产物还需由平台收集、校验、写入私有对象存储，并建立正式消息或 Run 引用。
