# #28 Memory／Workspace 固定版本接缝

日期：2026-10-26，Asia/Shanghai。工单：[阶段 0 / 05](https://github.com/BeyondzychenProton/agentscope-brain/issues/28)。只依赖已关闭的 #24，与 #25–#27 探针分开。完整用例表见 [验收记录.md](验收记录.md)。

隔离验证用 H2 上的真实 `JdbcStore`（`H2Dialect`，`initializeSchema=true`）。这不是 MySQL 8 的 `VARCHAR(512)`／排序规则验收，阶段 2 仍须在开发隔离 Schema 上复验。

| 观察 | 结果 |
| --- | --- |
| `MemoryConsolidator.WATERMARK_NAMESPACE` | `memory` / `consolidation`，键 `watermark` |
| 默认 `RemoteFilesystemSpec` 写入 `memory/{today}.md` | namespace 为 `agents` / `room-agent` / `users` / `user-7` / `memory`，实际键为 `/{today}.md`。前缀被拆成路由段，键留下前导斜杠。该键不是平台日记输入 |
| 平台记忆 namespace | `memory/employees/{employeeId}/users/{userId}/generations/{generation}` |
| 平台运行 namespace | `runtime/employees/{employeeId}/users/{userId}/sessions/{businessSessionId}` |
| 只读发布资产 | `employees/{employeeId}/releases/{releaseId}`，写入被拒绝 |
| `putIfVersion` | `false` 既可能是已存在，也可能是目标缺失；必须独立读回。空文档与缺失分开 |
| 原生写 | 无受控准入时不抛错、不改已有正文；随后的手工保存仍可提交。全局水位键和 `memory/.consolidation_state` 都重定向到当前代次，不进入全局键，也不读到其他代次或其他用户 |
