AgentScope Java · Lesson 03

一次 Agent 调用里，Workspace 内容怎样进出

分清 Agent 自动装载上下文，和应用代码直接读写工作区文件。
约 5 分钟版本基线：v2.0.4先修：第 1 课 · 第 2 课

同一个请求上下文，可以有两条用法：传给 Agent，让 Harness 在推理前装载工作区上下文；或者传给 workspaceFor(...)，让应用代码直接操作文件。

workspaceFor 不会启动模型推理，也不替平台保存一条永久的“用户/会话 → Workspace”业务关系。它返回一个供后续文件 I/O 使用的 WorkspaceManager 视图，并把传入的用户与会话信息交给该视图的文件系统/命名空间绑定。单是取得这个视图，不代表已经创建文件或物理目录。HarnessAgent 源码

实际分桶还要看配置的 IsolationScope：例如 USER 让同一用户跨会话共享，SESSION 则按会话分开。因此“带着 userId 和 sessionId”不等于这两个值总会同时成为存储键。IsolationScope 的键规则

场景：先记下用户偏好，再让 Agent 使用它

会议室员工已经由 Builder 建好。Alice 登录后，平台从可信登录态取出 userId，再为当前业务 Session 选出 Harness 使用的 sessionId。

RuntimeContext context = RuntimeContext.builder()
    .userId(authenticatedUserId)
    .sessionId(harnessSessionId)
    .build();

// 路径 A：让 Harness 执行 Agent 调用
agent.streamEvents(new UserMessage(userText), context).blockLast();

// 路径 B：应用代码自己写工作区文件
WorkspaceManager workspace = agent.workspaceFor(
    authenticatedUserId, harnessSessionId);
workspace.writeUtf8WorkspaceRelative(
    context,
    "memory/2026-10-20.md",
    "偏好：预订会议室时优先选择靠窗房间。"
);
① 已建好的 AgentBuilder 持有员工配置、逻辑根目录和 filesystem。
② 本次 RuntimeContext带入平台确认的 userId 与当前 sessionId。
③ 两种入口Agent 调用由 Harness 装载上下文；应用直写用 workspaceFor 取得请求级视图。
④ 文件系统WorkspaceManager 用相对路径交给 AbstractFilesystem，由后端决定物理落点。

Agent 调用时，哪些文件会进提示词？

v2.0.4 的 WorkspaceContextMiddleware 在每次 call() 进入推理阶段时拼装工作区上下文。已配置文件的修改会在下一次调用重新读取；这不是 Agent 启动时只读一次。

工作区内容进入模型上下文的方式
AGENTS.md正文注入为 Agent 规则。
MEMORY.md按上下文预算注入；更早内容可由记忆工具继续查询。
knowledge/注入入口文件和其他文件的路径清单；领域资料正文按需读取，不会全量塞入提示词。
其他文件不会因为它们“在 Workspace 目录里”就自动全部注入；Agent 或应用需要通过文件能力读取。

读取关键文件时，WorkspaceManager 先问当前 AbstractFilesystem，没有覆盖内容时再回退到本地 Workspace 模板。写入走当前 filesystem；写入后，下一次 call() 会按配置重新装载相关上下文。官方文档：推理时装载与两层读

三个容易混淆的名词

名词它是什么它不是
RuntimeContext本次调用携带的运行上下文。用户认证系统；可信 userId 仍由应用提供。
workspaceFor(userId, sessionId)绑定该请求身份的 WorkspaceManager 视图，适合 Controller 或服务层做显式文件 I/O。创建 Agent、发起推理，或改变共享 Agent 的全局绑定。
writeUtf8WorkspaceRelative(context, path, text)以 Workspace 相对路径写 UTF-8 文件，并路由到当前 filesystem。写入 AgentState，或替业务数据库提交事务。

工作区相对路径例如 memory/2026-10-20.md；它不是把 C:\ 或宿主机绝对路径交给 Agent。

小练习：给这行 API 定位

你在 Web Controller 中调用 agent.workspaceFor(userId, sessionId)。这一步属于“调用 Agent”，还是“应用直接取一个可用于文件 I/O 的视图”？再说出真正触发一次推理的那行代码。

展开核对答案

这是应用直接取得请求级文件 I/O 视图，不会触发推理。真正触发 Agent 推理的是例如 agent.streamEvents(message, context)；Harness 随后在推理阶段按上下文和文件系统配置装载需要的工作区内容。
