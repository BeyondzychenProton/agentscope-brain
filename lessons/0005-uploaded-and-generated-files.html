AgentScope Java · Lesson 05

上传文件、Workspace 工作副本与 Agent 产物

分清原件、临时工作文件和正式交付文件，才能知道保存在哪一层、由谁负责恢复。
约 7 分钟版本基线：AgentScope Java v2.0.4项目映射：当前会话/消息设计规格

先分成三种东西：用户上传的原件是正式历史素材；Workspace 里的文件是 Agent 执行时的工作资料；要给用户下载的 Agent 产物，则要被平台登记成正式附件或 Run 产物。

是什么权威保存位置Workspace 的角色
用户上传原件平台控制的私有对象存储；SQL 保存所属消息、类型、大小、摘要和对象定位。需要路径式处理时，可提供受控工作副本；不是原件的唯一副本。
Agent 的中间文件当前调用所用的 Workspace/filesystem 后端。临时输入、解析结果、草稿或运行过程文件；可依保留策略清理或从权威数据重建。
正式交付文件私有对象存储保存不可变文件；平台记录它属于哪个已完成回复/Run。可作为生成与暂存位置，不能单靠 Workspace 路径证明用户拥有可下载的正式附件。

这是本项目当前素材设计的责任划分：对象存储保存原件，SQL 保存可查询、可鉴权、可恢复的关联元数据；AgentScope 的 Workspace 是运行资料层。项目素材与对象存储设计 · Workspace 与平台责任边界

用户上传：先成为正式素材，再交给 Agent

① 认证与校验确认当前用户、目标员工、文件类型与大小。
② 上传原件服务端分配不复用的对象键，写入私有对象存储并核对长度与 SHA-256。
③ 接纳消息SQL 事务写正式消息、MEDIA 内容块、素材元数据和 Run。
④ 提供模型输入Adapter 按授权重新读取原件，再转换为模型支持的输入或受控工作副本。

对象上传与 SQL 事务不是一个原子提交：先把全部原件准备并验证好，再接纳正式消息和 Run；只有明确未被引用的失败上传才能延迟清理。若 SQL 提交结果不明，要先核对引用状态，不能马上删对象。项目的接纳、失败、读取与清理规则

保存什么：原始字节放私有对象存储；SQL 保存稳定 storage_profile + object_key、可选对象版本、MIME、字节数、SHA-256、消息归属和展示文件名。不要把文件内容 Base64 塞进 SQL，也不要把临时签名 URL 当成永久定位。

Agent 处理文件：Workspace 是工作区

如果 Agent 需要用 read_file 等工具按路径处理输入，平台可以把已鉴权素材投影或复制到某个受控的 Workspace 相对路径，例如 inputs/current/image-01.png。文件操作走当前 AbstractFilesystem，这样 Remote 或 Sandbox 模式也会路由到正确后端。运行时不要把宿主机路径当作通用工作区路径。官方 Filesystem 抽象 · 官方 I/O 规则

// 这是 UTF-8 文本文件写入，不是任意二进制文件上传
workspace.writeUtf8WorkspaceRelative(
    context,
    "outputs/summary.md",
    markdownText
);

writeUtf8WorkspaceRelative 接收字符串并按 UTF-8 编码，再交给 filesystem 写入，所以适合 Markdown、JSON 等文本。PDF、图片、压缩包等二进制内容不能先转成普通文本再调用它；应由文件工具/后端的字节 I/O 能力或平台素材 Adapter 处理。WorkspaceManager 写入实现

Agent 生成文件：工作产物怎样变成正式附件？

Harness 可以让 Agent 在 Workspace/filesystem 中创建文件；这只表示文件出现在运行工作区。要作为正式回复附件供用户回看或下载，平台还要执行一次“收集并登记”的交付流程：

  1. Run 在受控的输出目录生成文件，例如 outputs/report.md。
  2. 平台从配置的 filesystem 读取该相对路径，校验允许的路径、格式、大小和内容摘要。
  3. 把原始字节上传到私有对象存储，使用新的不可变对象键。
  4. 正式员工消息的有序内容块引用素材元数据；消息关联成功 Run。确认对象与 SQL 记录一致后，再显示下载入口。

对象存储和 SQL 仍是两个系统。若对象已上传但消息事务失败，先核对是否已被引用，再清理孤儿对象；若保存状态不明，不要给用户一个看似成功但实际不可恢复的下载链接。

项目规格边界：当前建模可表达正式员工回复携带通用 FILE 素材，但交付文件的收集、扫描/校验策略和恢复生命周期还没有单独形成验收契约。一期产品验收范围仍是文字与图片，不能据此宣称任意文件上传、解析、生成和下载已经实现。

如果产物属于正式员工回复，优先考虑复用 business_message + 有序 MEDIA 内容块 + message_media；这样文件跟着正式消息和 Run 回看。如果要做独立的文件库、跨消息引用或工作区外的 Run 下载中心，需要单独设计其业务记录与权限，不能只保存一条路径。消息素材表职责 · 消息、Run 与提交顺序

把三个存储层记成一句话

原件进私有对象存储，归属和引用进平台 SQL，Agent 工作副本进 Workspace/filesystem。当 Workspace 文件要变成对用户承诺的正式产物，平台再把它收集到私有对象存储并建立正式消息或 Run 引用。

小练习：同一个文件会经过哪几层？

用户上传了一张图片，Agent 要读取它，并最终生成一份可下载的 Markdown 报告。请分别说出：图片原件放哪里？Agent 的工作副本放哪里？报告以什么条件成为正式可下载回复？

展开核对答案

图片原件放私有对象存储，消息和 message_media 在 SQL 中保存关联；Agent 需要路径访问时，受控地投影到 Workspace/filesystem。报告先在受控工作路径生成，再由平台收集、校验并保存为新的私有对象，最后在成功 Run 对应的正式员工消息中登记媒体引用。当前项目的一期图片可进入产品验收；Markdown 作为正式文件附件的端到端交付仍需单独验收。
