Workspace 路径、文件系统后端与隔离范围

读一段 filesystem 配置，判断文件从哪读写，以及哪些请求共享同一份运行时文件。
约 6 分钟版本基线：v2.0.4先修：第 3 课

读 Workspace 配置时分开问三件事：读写哪个逻辑文件？由哪个文件系统处理？哪些调用共享同一桶运行时数据？

问题API / 概念例子
Agent 访问哪个逻辑文件？Workspace 相对路径memory/2026-10-20.md
文件操作由谁执行、数据放到哪里？filesystem(FilesystemSpec) → AbstractFilesystemLocal、Remote、Sandbox
哪些调用共享运行时数据？IsolationScopeUSER 跨会话共享同一用户的数据

这三项有关联，但不是同一个设置。相对路径告诉系统“要操作哪个逻辑文件”；后端负责处理 I/O；scope 再决定运行时命名空间如何分桶。Harness 的文件工具和应用侧 Workspace I/O 都经过文件系统抽象。官方 Filesystem 文档

三种常见后端模式

Local：本机 + shell

不配置时的默认模式。文件和可选命令在运行 Agent 的主机上执行；适合单机开发或受信任的环境。

Remote：共享存储

把部分 Workspace 文件路由到 Redis、JDBC 等 BaseStore，让多个服务副本看到共享数据。这个模式本身不提供 shell。

Sandbox：隔离执行

文件操作与 shell 在沙箱环境里执行，适合需要把执行环境和宿主隔开的场景；跨调用如何保留工作区要看沙箱状态、快照或持久卷配置。

同一套逻辑路径

例如 memory/... 可以交给不同后端处理。应用依赖 Workspace API，而不是把宿主机绝对路径当成唯一位置。

官方把 filesystem(...) 作为声明式配置入口；完全自管时才使用 abstractFilesystem(...)。三种常见模式和差异见模式总表。

读配置：Remote + USER

HarnessAgent agent = HarnessAgent.builder()
    .name("meeting-room")
    .agentId("meeting-room")
    .model(model)
    .workspace(workspaceRoot)
    .distributedStore(sharedStore)
    .filesystem(new RemoteFilesystemSpec()
        .isolationScope(IsolationScope.USER))
    .build();

RemoteFilesystemSpec 说明用共享文件系统模式；distributedStore 提供共享存储；USER 说明同一用户跨 Session 的运行时数据落在同一个用户命名空间。Remote 模式按路径规则路由文件：例如 memory/、skills/、knowledge/ 会进入共享 KV；未被规则覆盖的路径会落到本地文件系统。因此，“选了 Remote”不等于所有工作区路径都自动变成远端文件。Remote 配置与路径路由规则

再区分运行时文件和静态资产：USER scope 会分桶运行时数据，例如会话日志、任务和记忆；AGENTS.md、knowledge/ 等静态资产默认对所有用户共享。需要用户自己的版本时，要使用明确的用户覆盖机制。官方文档：运行时数据与静态资产

把运行时路径映射到后端

WorkspaceManager wm = agent.workspaceFor(userId, sessionId);
wm.writeUtf8WorkspaceRelative(
    context,
    "memory/2026-10-20.md",
    "偏好：会议室优先选靠窗的。"
);
① 逻辑路径memory/2026-10-20.md
② 请求上下文userId / sessionId
③ 分桶规则IsolationScope.USER 等
④ 物理 I/ORemote 的规则路径 → 共享 KV

这条路径是否真的跨机器共享，还取决于该路径是否命中 Remote 路由规则，以及多个副本是否连接同一个共享存储。Scope 决定逻辑分桶，后端和部署决定数据能否被其他副本读到。

一个项目设计检查点：员工维度在哪里？

Remote 的命名空间会结合 Agent 与 scope 键组织数据。不同 agentId 可以形成不同命名空间；但若两个业务员工实际上共用同一个 Agent 身份、Workspace 根和命名空间，USER 只表达“按用户分”，不会自动多出 employeeId 这一维。

平台侧检查：需求若是“同一用户 × 不同员工分别保存偏好”，就要指出员工维度实际由哪个根目录、命名空间前缀或独立 Agent 身份承载。不要只看到 USER 就认为员工隔离也完成了。

小练习：从需求选配置

一项服务运行三个副本；Alice 的偏好需要跨她的多个 Session 保留、跨副本可见；Agent 不需要执行 shell。你会选择哪种 filesystem 模式和 scope？配置里的哪一部分负责“放到共享后端”，哪一部分负责“同一用户共享”？

展开核对答案

选择共享存储模式 RemoteFilesystemSpec，连接所有副本共用的 BaseStore，再设 IsolationScope.USER。Remote + 共享 store 负责跨副本访问；USER 负责在框架命名空间里按用户跨 Session 分桶。还要确认目标文件路径命中了 Remote 的路由规则。
