读懂 Workspace API：从 Builder 到文件读写

看一遍会议室员工怎样装载定义、识别当前请求，并把一份工作资料写到正确的存储位置。
约 7 分钟版本基线：v2.0.4目标：读懂一次 Workspace API 调用

先记住一句话：Workspace 是 HarnessAgent 的逻辑文件空间；Builder 选它的根和文件系统，RuntimeContext 带入本次用户与会话，WorkspaceManager 再把相对路径交给配置好的文件系统。

这三个位置回答的是不同问题：.workspace(...) 回答“从哪棵工作区树开始”，RuntimeContext 回答“谁正在以哪个会话运行”，WorkspaceManager 回答“怎样按当前配置读写文件”。官方把 Workspace 定义为 Agent 定义与运行产物的逻辑布局，而不是固定的一条磁盘路径。Workspace 官方文档

一个请求经过哪些地方？

设想登录用户林岚正在 Web 上让会议室员工保存一条“会议默认安排 30 分钟”的偏好。

① Builder配置员工身份、工作区根目录和文件系统后端。
② RuntimeContext本次调用带入平台认证得到的 userId 与稳定的框架 sessionId。
③ WorkspaceManager按工作区相对路径处理文件读写，并应用覆盖规则。
④ AbstractFilesystem把逻辑文件放到本机、共享存储或沙箱对应的位置。

注意：工作区路径与用户/会话命名空间不是同一个参数。IsolationScope 决定文件系统怎样用运行上下文生成共享桶。

先读懂调用形状

var builder = HarnessAgent.builder()
    .name("meeting-room")
    .agentId("meeting-room")
    .model(model)
    .workspace(Path.of("/srv/agents/meeting-room"));

try (var agent = builder.build()) {
    var context = RuntimeContext.builder()
        .userId(authenticatedUserId)
        .sessionId(harnessSessionId)
        .build();

    agent.streamEvents(new UserMessage(userText), context).blockLast();
}

Builder 上的 workspace

.workspace(Path) 设的是工作区根。v2.0.4 的解析顺序是显式 Builder 值 → 系统属性 → AGENTSCOPE_WORKSPACE 环境变量 → 默认的 ${user.dir}/.agentscope/workspace。显式值优先。

调用上的 RuntimeContext

平台认证身份决定可信的 userId，平台 Session 绑定决定 sessionId。不要让模型输出或浏览器请求参数替代这两个身份来源。

从 API 名称追到读写实现

读到的入口它解决的问题接着看哪里
HarnessAgent.builder().workspace(...)设置逻辑工作区根目录。Workspace 文档：Builder 与路径优先级
RuntimeContext.userId / sessionId把本次调用的身份与会话传进 Harness，供状态恢复和文件命名空间使用。Workspace 文档：多用户覆盖
agent.workspaceFor(userId, sessionId)为应用侧单次请求拿到绑定用户/会话的 WorkspaceManager 视图，避免改动共享 Agent 上的可变绑定。HarnessAgent 源码
writeUtf8WorkspaceRelative(context, path, text)用工作区相对路径写入，并路由到当前 AbstractFilesystem。WorkspaceManager 源码
 
var workspace = agent.workspaceFor(authenticatedUserId, harnessSessionId);
workspace.writeUtf8WorkspaceRelative(
    context,
    "notes/preferences.md",
    "默认会议时长：30 分钟"
);

同一 WorkspaceManager 在本机模式下可能写本地文件，在 Remote 或 Sandbox 模式下则写远端 KV 或沙箱。运行时读写应经过 WorkspaceManager；直接调用 java.nio.Files 在 Remote/Sandbox 模式会写错到宿主机器。例外是启动前创建本地模板文件。官方写入规则

别把三个数据面合并成一个

Workspace 文件

静态定义、知识、技能，以及长期记忆、会话日志、计划和任务等文件产物。

AgentState

Harness 运行中恢复 Agent 所需的结构化上下文，由独立的 AgentStateStore 管理，不属于 Workspace 文件树。

平台业务事实

在本项目中，预约 ID、预约状态、用户授权和审计由平台的业务存储负责。Workspace 或 AgentState 都不能替代它们的业务事务。

本机、共享存储、沙箱

同一份逻辑 Workspace 布局可落在不同后端；物理路径不是 Workspace API 的全部含义。

前三者的边界在官方 Workspace 文档和本仓库的 v2.0.4 调研中分别核对过。项目文档中的业务责任是本项目设计约束，不是 AgentScope 自动提供的功能。官方数据生命周期说明 · 本项目静态调研

试着沿调用链复述

如果林岚换了一个 Web Session：哪些信息应该仍属于她，哪些信息应属于新会话？先用自己的话说，再展开核对。

展开一个核对答案

若文件系统选用 IsolationScope.USER 且工作区/员工根相同，她跨 Session 的个人偏好可以仍在同一个用户 Workspace 命名空间中；新的 sessionId 仍是另一个 AgentState 恢复槽。会议预约状态属于平台业务记录，并由会议系统核验。Workspace 的范围和 AgentState 的键各自独立。

有不清楚的 API 名称、路径或边界，直接追问我；下一课会专门比较 IsolationScope 与文件系统后端。
