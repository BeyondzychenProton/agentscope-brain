# AgentScope Java v2.0.4 SQL 多模态消息持久化能力调研

> 核对基线：官方 `v2.0.4` 标签所指源码提交 `0b6743b263ba8e39eb417e35048026f1e0196548`。本文只核对框架能力，不展开本项目业务表和素材存储设计。结论来自该版本源码与同仓库测试的静态核对；未对本项目的 MySQL、PostgreSQL 或素材服务做端到端验收。[官方版本发布记录](https://github.com/agentscope-ai/agentscope-java/releases/tag/v2.0.4)

## 结论

AgentScope Java 的 SQL `AgentStateStore` **可以把当前 `AgentState.context` 中的多模态 `Msg` 作为 JSON 整体保存并按类型读回**。MySQL 专用实现和通用 JDBC 实现都走同一类 JSON 序列化/反序列化链路。这里的“保存”是保存**当前 Agent 状态**，不是自动生成一份可永久回放的、逐条独立存储的原始业务消息库。[状态字段](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/state/AgentState.java#L57-L68)、[MySQL 写入与读取](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-mysql/src/main/java/io/agentscope/extensions/mysql/state/MysqlAgentStateStore.java#L363-L421)、[JDBC 写入与读取](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-jdbc/src/main/java/io/agentscope/extensions/jdbc/state/JdbcAgentStateStore.java#L127-L139)

因此，用户所说“多模态消息保存在 SQL 数据库”与框架能力并不冲突；但不能据此认定框架状态表已满足“全部原始对话消息及素材长期保留、跨版本严格全量续接”。具体业务持久化方案留到后续设计。[压缩会替换当前状态的消息列表](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/main/java/io/agentscope/harness/agent/middleware/CompactionMiddleware.java#L217-L229)、[Harness 会话日志的媒体占位转换](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/main/java/io/agentscope/harness/agent/memory/session/SessionTranscriptWriter.java#L193-L249)

## 源码链路：消息怎样进入 SQL

1. `AgentState.context` 是 `List<Msg>`；每条 `Msg.content` 是有序的 `List<ContentBlock>`。`ContentBlock` 用 JSON `type` 字段区分文本、`DataBlock` 及旧版图片/音频/视频等类型；`DataBlock` 自身保留 `source`、稳定 `id` 和可选 `name`。`Source` 又用 `type=url|base64` 区分两种媒体来源。这些注解提供反序列化所需的类型信息。[AgentState](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/state/AgentState.java#L95-L107)、[Msg](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/message/Msg.java#L50-L67)、[ContentBlock](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/message/ContentBlock.java#L45-L68)、[DataBlock](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/message/DataBlock.java#L35-L61)、[Source](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/message/Source.java#L27-L32)
2. `ReActAgent` 以 `(userId, sessionId, "agent_state")` 读取状态，保存时将整份 `AgentState` 传入状态后端。MySQL 的实际表字段包括打包后的 `session_id`、`state_key`、`item_index`、`state_data LONGTEXT`、`version` 等；写入调用 `toJson(value)` 后 `setString`，读取调用 `fromJson(json, AgentState.class)`。通用 JDBC 后端同样把 JSON 存入 `state_data`；其 MySQL 方言为 `LONGTEXT`，PostgreSQL 方言为 `TEXT`。[状态加载](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java#L427-L435)、[状态保存](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java#L543-L571)、[MySQL 实际建表与读写](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-mysql/src/main/java/io/agentscope/extensions/mysql/state/MysqlAgentStateStore.java#L238-L247)、[JDBC 方言](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-jdbc/src/main/java/io/agentscope/extensions/jdbc/dialect/vendor/PostgresDialect.java#L100-L113)
3. `URLSource` 中是 URL 字符串和可选 MIME 提示，因此状态表只存引用，**不会自动把 URL 所指的图片、音频或文件抓取为 SQL 二进制内容**。`Base64Source` 中是 MIME 和 Base64 数据字符串；若它仍在当前 `Msg` 中，该字符串会随整份状态 JSON 写入 `state_data`，而不是单独的 BLOB 列。这一结论是字段结构与 SQL 序列化路径的组合推断。[URLSource](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/message/URLSource.java#L45-L69)、[Base64Source](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/message/Base64Source.java#L39-L57)、[MySQL 序列化](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-mysql/src/main/java/io/agentscope/extensions/mysql/state/MysqlAgentStateStore.java#L380-L386)

## 两个不能混同的存储边界

- **当前状态与完整历史不同。** Harness 的压缩中间件会清空并以“摘要消息 + 保留尾部”替换 `AgentState.context`；后续 SQL 状态保存得到的是替换后的工作上下文，不能从这一行状态恢复所有早期原始消息。[压缩实现](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/main/java/io/agentscope/harness/agent/middleware/CompactionMiddleware.java#L217-L229)
- **Harness Session Transcript 的“全历史”不是完整的多模态 `Msg` 副本。** `HarnessAgent` 默认挂接 `TranscriptMiddleware`（可禁用），该中间件将当前 `Msg` 交给 `SessionTranscriptWriter`，再写为 Workspace 的 `.jsonl` / `.log.jsonl` 或 `TranscriptStore` 段。`SessionTranscriptWriter.deriveEntries` 把文字拼成 `MessageEntry.content`；文字与媒体混合时媒体块被略过，仅媒体消息才留下 `blockTypes` 占位。图片 URL、Base64 数据及内容块的原始交错顺序没有进入该条日志。仓库测试也明确断言图片独占消息的内容为空、只含 `image` 类型。因此 `.log.jsonl` 的“full history”指它保存的 `SessionEntry` 历史，不能直接当作完整原始多模态消息的回放源。[默认挂接](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L2543-L2560)、[转换实现](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/main/java/io/agentscope/harness/agent/memory/session/SessionTranscriptWriter.java#L193-L249)、[图片测试](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/test/java/io/agentscope/harness/agent/memory/session/SessionTranscriptWriterTest.java#L129-L149)
- **SQL Workspace 也是另一个组件。** `JdbcDistributedStore` 分别组装 `JdbcAgentStateStore`（状态）与 `JdbcStore`（Workspace KV），还组装快照及锁；`RemoteFilesystem` 可以把 Workspace 文件内容写入 `JdbcStore`，二进制文件会编码为 Base64。但这不是“收到一个 `DataBlock` 后自动将其素材另存为受控文件”的承诺。是否将素材写入何处、引用是否长期可读，须在后续具体设计与验收中明确。[组件组装](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-jdbc/src/main/java/io/agentscope/extensions/jdbc/JdbcDistributedStore.java#L31-L43)、[Workspace 上传编码](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-harness/src/main/java/io/agentscope/harness/agent/filesystem/remote/RemoteFilesystem.java#L496-L523)、[JdbcStore JSON KV](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-jdbc/src/main/java/io/agentscope/extensions/jdbc/store/JdbcStore.java#L92-L116)

## 文档差异与验证范围

- 同一 `v2.0.4` 标签的[分布式 MySQL 文档](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/docs/v2/zh/integration/distributed/mysql.md#L39-L53)称状态表有 `user_id`、`state_value`、`state_type`；但[该版本 `MysqlAgentStateStore` 实际建表 SQL](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-mysql/src/main/java/io/agentscope/extensions/mysql/state/MysqlAgentStateStore.java#L238-L247)是打包 `session_id` 加 `state_data`、`version` 等。[同标签旧版 MySQL 状态存储文档](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/docs/v2/zh/integration/session/mysql.md#L71-L89)也更接近源码，不过省略了 `version`。实际 DDL 以源码及部署时数据库实物核验为准。
- 仓库的 [`DataBlockTest`](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/test/java/io/agentscope/core/message/DataBlockTest.java#L37-L101)覆盖 `URLSource` 的 JSON 往返与 `Base64Source` 构造；检查的 [MySQL 状态存储测试](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-extensions/agentscope-extensions-mysql/src/test/java/io/agentscope/extensions/mysql/state/MysqlAgentStateStoreTest.java)主要验证版本控制，未见 `DataBlock` 经 MySQL 写入再读出的专门测试。因此“多模态可经 SQL 往返”目前是由源码类型注解与读写链路支持的**静态判断**，不是本次已经跑通的 MySQL 端到端结论。

## 本轮已确认的业务边界

Q24a 当时确认多模态消息目标存放在 SQL 数据库，具体素材方案后续设计。2026-10-19 后续决定：正式消息及素材元数据保存在 SQL，素材原件统一保存在私有对象存储，详见[通用素材与工具操作设计](../../数据库设计/会话运行与消息/通用素材与工具操作设计.md)。框架能力核对结论不因此改变。Q24b：一期端到端验收文字和图片；音频、视频和通用文件纳入能力核对，实际验收范围待模型、Web 和渠道能力确认。以上是本轮讨论结论，不是 AgentScope 的产品承诺。
