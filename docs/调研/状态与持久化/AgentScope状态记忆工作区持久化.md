## 二、默认值、恢复与后端

1. **状态默认落本地 JSON，不自动进入业务 MySQL。** `HarnessAgent.Builder.build()` 未收到 `.stateStore(...)` 或 `DistributedStore` 的状态后端时，构造 `JsonFileAgentStateStore`，根为 `~/.agentscope/state/<agentId>/`；`agentscope.state.home` 可改基础目录。`InMemoryAgentStateStore` 只适合测试或单进程演示。官方文档列出 Redis 与 MySQL 扩展；源码另有通用 JDBC 实现。MySQL 实现默认库表为 `agentscope.agentscope_sessions`，状态内容以 JSON 存放，其 `session_id` 列实际编码 `userId:sessionId`，并没有独立数字员工列。因此若多个员工共用同一状态表，平台必须安排互不冲突的状态槽或独立后端/表；不能把业务 Session 主键的唯一性当成框架多员工隔离的完整证明。[默认构建源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L2376-L2429)、[默认路径源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L1122-L1141)、[后端文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/building-blocks/context.md#L81-L110)、[MySQL 槽位编码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-extensions/agentscope-extensions-mysql/src/main/java/io/agentscope/extensions/mysql/state/MysqlAgentStateStore.java#L879-L892)、[JDBC 实现](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-extensions/agentscope-extensions-jdbc/src/main/java/io/agentscope/extensions/jdbc/state/JdbcAgentStateStore.java#L49-L81)。
2. **调用级恢复。** `ReActAgent` 每次调用开头按本次 `RuntimeContext` 的 `(userId, sessionId)` 从状态存储重新加载；没有记录时创建新状态，缺少 `sessionId` 时退回默认 ID（通常是 agent 名）。调用结束会保存整份状态，失败时会尽量保存已形成的安全状态；并非每条消息后都做持久提交。生产入口必须显式提供 session ID，且同一业务 Session 的轮次应串行，不能把缺省 ID 用于不同用户的多段会话。[调用加载源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java#L648-L706)、[保存与失败处理源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java#L470-L526)、[Harness 缺省 ID](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L1008-L1019)。
3. **并发版本不是业务幂等。** `AgentStateStore` 提供可选的版本读写；未实现版本控制的后端会退化为无条件写入。`ReActAgent` 冲突策略默认 `OVERWRITE`，即使后端支持 CAS，也可能在冲突后覆盖。平台仍需自己的 Session 顺序控制、Run 状态和工具写操作幂等记录。[接口版本契约](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-core/src/main/java/io/agentscope/core/state/AgentStateStore.java#L63-L137)、[默认策略](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java#L346-L352)、[冲突分支](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java#L568-L642)。
4. **Workspace 有独立的物理后端。** 默认是本地 filesystem；`RemoteFilesystemSpec` 可接共享 `BaseStore`，官方列出 Redis/JDBC，沙箱模式则依赖相应快照或持久卷。`AgentStateStore` 与 Workspace 是两套存储，部署时都要能在目标恢复场景中读到。源码在 RemoteFilesystem 搭本地 JSON/内存状态时构建失败；在 SandboxFilesystem 搭本地状态时只记录警告，并未构建失败。[filesystem 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/filesystem.md#L19-L25)、[共享存储后端](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/filesystem.md#L31-L104)、[构建检查源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L2426-L2465)。
5. **隔离键的缺失会降级。** `USER` scope 在无 `userId` 时以 `sessionId` 回退；两者都缺少时命名空间为空。`SESSION` 也会在无 `sessionId` 时落入空命名空间。`AGENT` / `GLOBAL` 的本地路径命名空间都为空；是否跨员工共享取决于 Workspace 根或共享存储前缀。不能让匿名回退成为企业用户或员工隔离机制。可写的 `MEMORY.md` 位于 Workspace 根的用户命名空间下，并非天然带员工 ID；本项目须为不同员工明确分根或分前缀。[scope 转换源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/IsolationScope.java#L90-L125)、[路径解析源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/workspace/WorkspaceManager.java#L232-L262)、[Workspace 多用户说明](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/workspace.md#L241-L280)。
6. **长期记忆是异步的。** 有模型且未关闭 Memory hooks 时，默认每次调用完成后调度 Flush，从当前上下文提取到日记；维护任务默认最短间隔 30 分钟，负责合并、归档较旧日记（默认 90 天）并清理较旧会话日志（默认 180 天）。这些工作在后台执行，当前回复完成不代表提炼和合并已经成功。`MEMORY.md` 每轮按预算加载；工具可检索日记。`disableMemoryHooks()` 关闭 Flush 和维护，`disableMemoryTools()` 则关闭检索/保存工具，两者作用不同。[Memory 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/memory.md#L52-L62)、[后台维护默认值](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/memory/MemoryConfig.java#L54-L64)、[后台运行源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/middleware/MemoryFlushMiddleware.java#L153-L211)、[维护步骤源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/middleware/MemoryMaintenanceMiddleware.java#L45-L57)、[关闭开关说明](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/memory.md#L253-L268)。

## 三、平台 MySQL 必须自持的业务事实

依据已确认的[一期总体设计](../../一期总体设计.md)，平台 MySQL 至少要记录：账号、管理员角色与账号状态；数字员工草稿及不可变发布版本、员工对用户的授权；业务 Session 与每次 Run（调用者、渠道、发布版本、生命周期）；需在业务界面查询的消息/结果索引；写操作确认、工具调用与稳定 `requestId`、预约关联及审计。会议预约是否最终生效由会议系统核验。框架的 `AgentState` 是恢复上下文，Memory 是可被模型修改、且异步生成的个人偏好，Workspace 是文件资产；三者均不提供这些业务事实的事务、授权或对账语义。[一期边界与责任](../../一期总体设计.md#2-架构与责任边界)、[Run 与版本](../../一期总体设计.md#3-数字员工定义发布与运行)、[记忆与预约事实](../../一期总体设计.md#6-记忆会话与预约事实)。

设计映射建议：业务 Session 使用平台生成的稳定 ID；另存 `userId + employeeId + definitionVersion + agentStateSessionId + workspaceRoot/namespace` 的绑定，并在每次 Run 固定发布版本后传入 `RuntimeContext`。同一用户、同一员工、不同 Web 会话可共享 `USER` scope 的长期偏好，同时保持不同的 AgentState 会话槽；跨渠道默认新业务 Session，新会话若要继续旧状态由平台显式建立关联。这里是基于上述框架键空间与一期要求的**平台设计建议**，不是 AgentScope 自动创建的关系。[状态寻址](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-core/src/main/java/io/agentscope/core/state/AgentStateStore.java#L25-L40)、[Workspace 隔离](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/IsolationScope.java#L90-L125)、[一期总体设计](../../一期总体设计.md#6-记忆会话与预约事实)。

## 四、文档与源码差异、待验证点

- v2.0.4 [Workspace 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/workspace.md#L158-L167)称 `disableSessionPersistence()` 可关闭自动持久化，但同版本[方法源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L2269-L2273)明确标注“2.0 起 no-op”。不能靠这个开关实现停写或隐私删除。
- v2.0.4 [Context 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/building-blocks/context.md#L113-L117)把 RemoteFilesystem 和 SandboxFilesystem 都描述为搭本地状态会直接抛错；[构建源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java#L2431-L2465)只对 RemoteFilesystem 抛错，对 SandboxFilesystem 是警告。沙箱的重启恢复需单独实测。
- v2.0.4 [filesystem 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/filesystem.md#L134-L137)称沙箱 scope 默认 `SESSION`，但 [SandboxFilesystemSpec](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/filesystem/spec/SandboxFilesystemSpec.java#L44-L65)未设默认值，[SandboxIsolationKey](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/sandbox/SandboxIsolationKey.java#L58-L90)把空值按 `USER` 解析。设计不能依赖文档中的沙箱默认 `SESSION`；应显式配置并验证。
- v2.0.4 [Workspace 文档前段](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/workspace.md#L29-L39)把会话日志写为“不自动清除”，但同版本 [Memory 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/memory.md#L241-L251)和[维护源码](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/middleware/MemoryMaintenanceMiddleware.java#L45-L57)有默认 180 天清理。不能据“永不压缩”推断业务消息永久留存。
- 仍需在本项目固定依赖后实测：单节点重启后同一用户/会话的状态与记忆恢复；两用户、两员工及新旧定义版本之间的隔离；异步 Memory 完成/失败时的可观察性；MySQL 状态后端与 Workspace 后端的表结构、迁移管理和备份恢复；同一会话并发与 CAS 冲突策略；用户更正或删除记忆后旧日记重新合并的行为。源码与文档只能证明存在接口与路径，不能证明这些项目级验收已经通过。
