# AgentScope Java v2.0.4 多渠道消息与会话能力核实

> 对应 [议题 #3](https://github.com/BeyondzychenProton/agentscope-brain/issues/3)。核对范围固定为官方仓库 `v2.0.4` 标签；以下区分框架契约、适配器实现和平台应保存的业务事实。本文是源码调查，不代表已完成实际渠道联调。

## 1. 路由、身份与会话

1. `Channel` 将平台消息归一化为 `InboundMessage`，`ChannelRouter` 解析目标 Agent 和 `MsgContext`，再由 `Gateway.run/runStream` 执行。路由优先级是显式 `preferredAgentId`、peer、父 peer、guild+roles、guild、team、account、channel、渠道默认、全局默认；匹配的 binding 也可决定 DM 会话范围。参见 [ChannelRouter](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/ChannelRouter.java#L24-L60) 与 [resolveRoute](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/ChannelRouter.java#L82-L117)。
2. `InboundMessage.peer` 是对话位置，`senderId` 是发言人；群聊两者不同。路由器把 `senderId`（DM 缺省时退回 peer id）放入 `MsgContext.userId`，把选中的 `agentId` 放入 `extra`。这**不是平台用户绑定或授权**：渠道外部标识只有经过平台可信映射后，才能作为平台 `userId` 使用。参见 [InboundMessage](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/InboundMessage.java#L24-L75) 与 [ChannelRouter](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/ChannelRouter.java#L110-L117)。后一句是基于源码的数据流作出的平台设计推论。
3. `MsgContext.canonicalKey()` 由 `channel/group/room/threadId/threadTs/extra` 组成，**不含 `userId`**。`extra.agentId` 因而使不同 Agent 默认落在不同键；DM、群与线程如何取 room/group 由 `DmScope` 和 peer 类型决定。Gateway 对键计算 `gw-` 前缀的确定性 session id，并将它与 `userId` 写进本轮 `RuntimeContext`。因此同一个群 peer 可以共用 Gateway 会话键，但不同发送人会进入不同 `(userId, sessionId)` Agent 状态命名空间，不能直接推定有一份群共享记忆。参见 [MsgContext](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/MsgContext.java#L22-L90)、[ChannelRouter 上下文生成](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/ChannelRouter.java#L179-L210)、[Gateway session 生成](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L535-L536) 与 [Harness 状态寻址说明](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/architecture.md#L49-L61)。
4. Web 可用 `SendOptions.userId(u)`（默认每用户一段）或 `SendOptions.of(u, businessSessionId)`（一人多段），并用 `withAgentId` 选 Agent。显式 session id 是 ChatUI 的**路由键输入**，最终 AgentScope session id 仍由 Gateway 生成；ChatUI 构造路由键时只将显式 session id 置于 room，`userId` 不进入 canonical key。平台必须保证传入的业务会话标识全局不冲突，并先核验该会话属于当前用户与目标员工。参见 [SendOptions](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/chatui/SendOptions.java#L24-L35)、[ChatUiChannel](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/chatui/ChatUiChannel.java#L432-L456)、[Gateway](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L203-L230)。末句为平台设计推论。
5. Gateway 默认 `LocalSessionTurnGate` 使用进程内公平信号量串行同一 canonical key 的轮次；可替换 `SessionTurnGate` 做跨节点协调。分布式 gate 的接口允许忙时抛 `TurnBusyException`，Gateway 会把该轮变成空结果，而非可靠排队。不能把这一能力当作跨进程消息队列或业务 Run 持久化。参见 [LocalSessionTurnGate](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/LocalSessionTurnGate.java#L21-L46)、[SessionTurnGate](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/SessionTurnGate.java#L20-L45)、[Gateway 执行](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L694-L747)。

## 2. 消息、事件和回送地址

- `InboundMessage` 携带渠道/账号、peer/发言人、父 peer、guild/team/roles、`List<Msg>`、显式 Agent、调用方 `RuntimeContext`；后者不参与会话键。Gateway 的上下文合并顺序为调用方、可选 resolver 替换、Gateway 覆盖 `sessionId/userId/msgContext/gateKey/outboundAddress`。要传平台可信身份，不能仅在调用方 `RuntimeContext.userId` 里覆盖渠道原始发言人。参见 [InboundMessage](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/InboundMessage.java#L45-L75) 与 [Gateway 合并实现](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L279-L329)。
- `OutboundAddress(channelId, accountId, to, threadId)` 是回复目标；Router 从入站 peer 生成，Gateway 缓存该 session 的“最近路由”，可在配置 `BaseStore` 时持久化。它是回送定位信息，不是用户身份或发送成功凭证。参见 [OutboundAddress](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/OutboundAddress.java#L22-L79)、[Router](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/ChannelRouter.java#L214-L221)、[Gateway route 存取](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L787-L845)。
- `runStream/sendStream` 返回 `Flux<AgentEvent>`，包含文本块、数据块、工具调用/结果和结束等事件；Gateway 使用与非流式相同的 session 与 gate。`Msg` 可装多个内容块，ChatUI 接受 `Msg`/`List<Msg>`，所以框架层支持多模态；外部渠道映射能力需逐个核对。参见 [Channel 文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/harness/channel.md)、[消息与事件文档](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/zh/docs/building-blocks/message-and-event.md#L136-L184)、[Gateway stream](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L233-L276)。
- 钉钉、飞书、企微的入站映射器可识别若干图片/语音/视频/文件类型，但把平台素材 ID 放在 `Msg.metadata`、正文放中性标记；**不会直接下载并转换成模型可读的 `DataBlock`**。素材下载、对象存储、权限和过期处理是应用策略。GitHub/GitLab 评论映射为文本。参见 [ChannelMediaMetadata 契约](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-extensions/agentscope-extensions-channel/agentscope-extensions-channel-common/src/main/java/io/agentscope/extensions/channel/common/ChannelMediaMetadata.java#L22-L38)、[飞书映射](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-extensions/agentscope-extensions-channel/agentscope-extensions-channel-feishu/src/main/java/io/agentscope/extensions/channel/feishu/FeishuInboundMapper.java#L174-L201)、[钉钉映射](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-extensions/agentscope-extensions-channel/agentscope-extensions-channel-dingtalk/src/main/java/io/agentscope/extensions/channel/dingtalk/DingTalkInboundMapper.java#L75-L116)。

## 4. 平台数据库需要自持的消息事实

基于上述边界以及[一期总体设计](../../一期总体设计.md)，平台至少应独立保存：**渠道实例与凭据引用**、**外部发送人到平台用户的可信绑定及状态**、**外部对话位置与平台业务 Session 的映射**、**入站消息 ID/渠道实例组合的唯一去重记录及接收处理状态**、**用户与助手的消息及附件元数据/受控素材引用**、**每轮 Run 的版本、状态和事件摘要**、**出站投递意图、重试、平台回执与最终状态**。这是一组设计推论，后续议题需确定字段和生命周期，不能把 Gateway 的确定性 session id、最近路由、进程内去重或 AgentState 快照误认为上述业务事实。直接依据见 [Gateway 存取边界](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/HarnessGateway.java#L750-L845)、[去重接口](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-extensions/agentscope-extensions-channel/agentscope-extensions-channel-common/src/main/java/io/agentscope/extensions/channel/common/InboundEventDeduplicator.java#L20-L49) 和 [投递接口](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/agentscope-harness/src/main/java/io/agentscope/harness/agent/gateway/channel/Channel.java#L108-L129)。

## 5. 待实施验证

- 实际钉钉/飞书/企微账号、回调和素材接口未联调；各平台的消息 ID 唯一域、重试窗口、回执语义、群/线程路由要以目标租户和当前平台 API 验收。
- 飞书 `event_id` 去重的文档与本标签回调源码不一致，需确认项目实际采用的是直接 `FeishuChannel` 入口，还是另有先持久入站再分发的控制面。
- `BaseStore` 与分布式 `SessionTurnGate` 只是可替换接口；一期单节点可先按本地串行实施，但多节点、重启恢复和投递保证必须通过指定后端与故障测试证明。
