| 层次 | 官方事实 | 对本项目的适用判断 |

## 3. 两条受控表单路线

### A：JSON Forms Vue 绑定 + 平台自定义 renderer

JSON Forms Vue v3.8.0 接受 data、schema、uischema、renderer 注册表、自定义 Ajv 和 readonly，通过 change 事件给出数据及校验错误；binding 提供 control 状态和 handleChange，可由平台 Vue 组件实现控件。来源：[固定 Vue README](https://github.com/eclipsesource/jsonforms/blob/v3.8.0/packages/vue/README.md)。

Vue 根组件还支持 additionalErrors，可映射后端字段错误；renderer 按已注册 tester 的排名选择。来源：[固定根组件](https://github.com/eclipsesource/jsonforms/blob/v3.8.0/packages/vue/src/components/JsonForms.vue)、[固定 Vue README](https://github.com/eclipsesource/jsonforms/blob/v3.8.0/packages/vue/README.md)。

维护方官网仍把 Vue integration 标记为 preview，并提供 vanilla／Vuetify renderer。不能由 React 生态能力推定 Vue 的所有控件或行为等价。来源：[官方 Vue 集成页](https://jsonforms.io/docs/integrations/vue/)。

本项目若选择 A，仍需将受控 form-v1 映射到 JSON Forms UI Schema，只注册允许组件，并在交互壳实现草稿、候选、提交及历史状态；不能利用默认生成 Schema／UI 或通用 fallback 绕开平台校验。这是结合固定接口与现有规格的工程建议。

### B：平台 form-v1 有限组件 renderer + Ajv

Ajv 默认导出支持 draft-07，格式校验可注册 ajv-formats；它负责数据校验，不提供界面。来源：[Ajv 方言说明](https://ajv.js.org/json-schema.html)、[格式插件](https://ajv.js.org/packages/ajv-formats.html)。

本项目可直接按已接纳的 form-v1 字段／分组分派 Vue 组件，用 Ajv 复用数据校验；此处是基于有限契约的实现选项，不是声称 Ajv 已提供表单引擎。UI Schema 校验、控件映射、数据绑定、错误路径与布局由平台维护。

| 比较项 | A：JSON Forms Vue | B：有限 renderer + Ajv |
| --- | --- | --- |
| 可复用收益 | 通用数据绑定、renderer 分派、布局 binding、校验与错误接入。[固定 README](https://github.com/eclipsesource/jsonforms/blob/v3.8.0/packages/vue/README.md) | 复用 draft-07 校验；平台只实现 form-v1 已允许的有限展示。[Ajv](https://ajv.js.org/json-schema.html)、[本地契约](../../正式应用设计/动态表单与交互请求生命周期设计规格.md) |
| 适配成本 | 维护 form-v1 到 UI Schema 的适配及自有控件，并评估 Vue preview 依赖。 | 维护分派、绑定、布局、错误展示、只读等表单基础能力。 |
| 视觉控制 | 自定义 renderer 可以接平台视觉；不能把默认 renderer 风格视为已满足 Q1。 | 可围绕指定原型直接组织组件；仍须验证一致性。 |
| 平台责任 | 两者均不代管请求修订、草稿 CAS、可信人员、一次回答、确认授权或可恢复投影。依据：[交互规格](../../正式应用设计/动态表单与交互请求生命周期设计规格.md)、[投影规格](../../正式应用设计/消息渲染运行事件与恢复投影设计规格.md)。 | 同左。 |
| 适合后续评估的条件 | 确实需要通用表单引擎的扩展收益，并愿意维护其适配与版本验证。 | 长期保持一期有限字段，优先让实现与平台契约直接对应。 |

比较中未附外部来源的成本／适用条件是工程判断，不是性能测量或维护方承诺。

## 4. Element Plus 可扮演的角色

固定 2.11.8 的 Form 支持常见输入、选择、复选及字段容器、标签和错误展示；rules 基于 async-validator。它可以提供 PC 基础控件，但不能据此替代 draft-07 的 Ajv 校验。来源：[固定 Form 文档](https://github.com/element-plus/element-plus/blob/2.11.8/docs/en-US/component/form.md)。

Element Plus 具有自己的组件结构和 BEM／SCSS 主题，支持样式变量定制。因而可以接在平台“无界面的 Schema／校验层”之下，但它自身不是无头库；从所查 Form API 也不能推出存在可直接消费 form-v1 的 Schema renderer。后两项为基于 API 与样式职责的判断。来源：[固定 Form 文档](https://github.com/element-plus/element-plus/blob/2.11.8/docs/en-US/component/form.md)、[固定主题文档](https://github.com/element-plus/element-plus/blob/2.11.8/docs/en-US/guide/theming.md)。

若用 Element Plus，建议把 Ajv／服务端错误映射到字段展示，避免再手写一份完整 Schema 约束到 rules；多控件字段的辅助标签仍由应用负责。来源：[固定 Form 文档](https://github.com/element-plus/element-plus/blob/2.11.8/docs/en-US/component/form.md)。前者是减少规则漂移的工程建议。

它可与路线 A 的自定义 renderer 或路线 B 组合。是否采用、怎样覆盖指定原型视觉及依赖成本，仍交用户决定；本次没有做组件外观或键盘交互验收。

## 5. 日期、时间与校验版本接缝

业务时区已经固定为 Asia/Shanghai；日期须为真实日历日期，时间按该业务时区解释，date-time 必须有明确 UTC offset。来源：[既定 form-v1 规格](../../正式应用设计/动态表单与交互请求生命周期设计规格.md)。下列事实用于落实既定语义，不重定业务时区。

1. **不能混用 ajv-formats 的版本说明。**固定 [v2.1.1 README](https://github.com/ajv-validator/ajv-formats/blob/v2.1.1/README.md)规定 time 时区可选、date-time 时区必需；固定 [v3.0.1 README](https://github.com/ajv-validator/ajv-formats/blob/v3.0.1/README.md)规定两者均需时区，并另有 iso-time。JSON Forms v3.8.0 声明的是 `^2.1.0`，不能把当前官网的 v3 行为直接归给该依赖范围。
2. JSON Forms 默认创建 Ajv 时使用 allErrors、strict:false 并安装 formats；支持传自定义实例。默认配置不能证明平台已经限制未知关键字、启用全部业务校验或符合前后端一致要求。来源：[固定 validator](https://github.com/eclipsesource/jsonforms/blob/v3.8.0/packages/core/src/util/validator.ts)、[校验文档](https://jsonforms.io/docs/validation/)。
3. formats 的 full／fast 模式有差别；v2.1.1 文档说明 fast 对日期时间只做简化结构校验，不能凭这种模式满足真实日期要求。来源：[固定 formats README](https://github.com/ajv-validator/ajv-formats/blob/v2.1.1/README.md)。
4. Element Plus DatePicker 区分显示 format 与绑定 value-format，默认收发 Date 对象。控件显示“上海时间”不等于线格式已有正确 offset；需显式映射并验证，不能直接依赖浏览器本地时区。来源：[固定 DatePicker 文档](https://github.com/element-plus/element-plus/blob/2.11.8/docs/en-US/component/date-picker.md)；映射要求来自既定业务规格。

落地前应固定 Ajv／formats 实际版本与配置，用真实日历日期、闰年、非法时间、缺 offset 的 date-time 及不同浏览器时区共用样例验证。需要自定义格式适配时，前后端必须保持同一 form-v1 解释；不能静默换方言或关闭格式断言。

## 6. 可供本轮选择的建议与后续准入

- **工程方向建议：**Vue 3 + TS + Vite + Vue Router + Pinia；具体锁定版本在实施时逐项核验，不因本文锚点就自动采用其整组依赖。
- **renderer 取舍建议：**在一期有限字段不扩围的前提下，优先评估 B，直接对应 form-v1；若预期通用布局／表单扩展收益足以覆盖适配及 preview 维护成本，再选择 A。这个推荐不是用户决定。
- **基础组件建议：**Element Plus 是可评估的 PC 控件来源；A／B 的选择与基础组件库分开确认，复用控件不等于采用其整套页面视觉。

正式实施的最小验证应覆盖：独立类型检查与生产构建、受控组件目录、未知版本／组件拒绝、完整字段类型及格式、可信候选和重名、后端字段错误、只读历史、草稿冲突与修订迁移，以及既定 PC 视口的长表单、滚动和焦点行为。草稿、确认、重启与断流行为仍按 #19／#20 验收，不由库演示替代。

本次结论仅达到“工程选项有官方事实支持”的研究阶段；没有依赖交付物核验、组件集成通过或正式 Web／框架／会议闭环证据。
