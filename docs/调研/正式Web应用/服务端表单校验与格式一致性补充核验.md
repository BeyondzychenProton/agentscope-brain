## 3. draft-07、format 与资源加载的实际边界

### 3.1 方言和格式断言

3.0.6 有独立 `Draft7.getInstance()` 方言，使用 `SpecificationVersion.DRAFT_7`、默认格式目录和对应关键字；`SchemaRegistry.withDialects` 可以只注册指定方言并拒绝未知方言。所读 Registry 导入 `tools.jackson.databind.JsonNode`，不能用 Jackson 2 的类型调用同一节点接口。[Draft7][draft7][限定方言注册及节点类型][registry]

`BaseFormatValidator` 对 draft-07 默认开启格式断言；`formatAssertionsEnabled=true/false` 可以覆盖默认值。故不能把“JSON Schema format 都默认只是 annotation”套到本候选 draft-07 上。为固定项目行为，候选接法应显式保持格式断言开启，前端保持 `validateFormats:true`；配置为 false 会放过非法格式。[服务端断言源码][format-base][Ajv 固定配置文档][ajv-options]

项目仍必须在结构接纳时只允许既定 `date/time/date-time` 等受控值，不能把启用格式断言理解为自动建立了 `form-v1` 的组件／关键字／format 白名单。[既定 #19](../../正式应用设计/动态表单与交互请求生命周期设计规格.md#3-表单契约-form-v1)

### 3.2 form-v1 接纳先于库编译

draft-07 自身支持的 `$ref`、组合条件、嵌套结构和注解远多于本项目白名单。因此候选管线是：**校验协议版本、字节／数量／层级和关键字／format／组件白名单 → 接纳固定结构与修订 → 库校验回答 → 字段和会议业务校验**。这属于落实既定 #19 的项目责任，不是采用 networknt 后新增任意 Schema 能力。[3.0.6 Draft7][draft7]

3.0.6 配置默认 `failFast:false`、`PathType.JSON_POINTER`、`typeLoose:false`；候选应显式保持这些约束，并使用返回 `List<Error>` 的验证接口。官方说明 Boolean／Flag 输出会自动启用 fail-fast，因此不能为节省输出改用它们后仍声称收集全部可确定错误。Ajv 使用 `allErrors:true`，保留 `coerceTypes:false`、`useDefaults:false`、`removeAdditional:false`，避免替用户代填／转换或删除输入。[3.0.6 配置][config][3.0.6 输出行为][readme][Ajv 配置][ajv-options]

### 3.3 外部 Schema 加载：源码和 README 存在差异

3.0.6 的固定 `SchemaLoader` 源码明确：**默认不抓取远程资源**；只有显式 `fetchRemoteResources`／`getRemoteFetcher` 或外加 ResourceLoader 才会进入相应加载路径，内建 classpath／meta-schema 解析仍存在。该版本 README 的 security 表仍称默认会按需从互联网加载。本文以实际固定源码为行为依据，不能照搬该表断言默认联网。[3.0.6 Loader][loader][存在差异的 README][readme]

项目仍应封闭加载配置：模型结构不允许 `$ref`／`$id` 或替换 `$schema` 方言；只使用预装 draft-07，不启用远程 fetcher；通过 Loader 的 allow／block 接缝限制到应用已知内建资源。前端也不注册远程 `loadSchema`。这需要以“外部／本地任意引用均被结构接纳拒绝、HTTP 请求计数为 0”验证，不能以默认值代替项目边界。[Loader 的 allow／block 与开关][loader][Ajv loadSchema 条件][ajv-options]

### 4.1 Q18 严格线格式候选及与既定契约的关系

本轮拟讨论的候选是：`date = YYYY-MM-DD`、`time = HH:mm:ss+08:00`、`date-time = YYYY-MM-DDTHH:mm:ss+08:00`；四位年、固定宽度、大写 `T`、秒精度，仅 `+08:00`，不接纳缺 offset、其他 offset／`Z`、闰秒、小数秒、空白／尾随字符。这是**待确认的项目表示规则**，不是 networknt／Ajv 默认规则。

已复核 #19：第 3.1 节要求真实日历日期、上海解释、date-time 明确 offset、保存原始合法回答与规范化值，**未明确要求接受任意 offset、闰秒或小数秒**。该节“最多 6 位小数”明确属于**数字字段**，不能解释成时间字段必须接受微秒。因此 Q18 与现有明确字段值约定没有直接冲突，但它确实缩小了标准 RFC 3339 可表达范围，须作为 `form-v1` 统一表示经用户确认并同步，不能事后静默截断已有回答或修改已展示修订。[#19 第 3.1 节](../../正式应用设计/动态表单与交互请求生命周期设计规格.md#31-结构组件及资源边界)[不可变修订约束](../../正式应用设计/动态表单与交互请求生命周期设计规格.md#33-展示修订与并发草稿)

DatePicker／TimePicker 的显示值、用户输入草稿、线字符串与服务端规范化值是不同对象。若该候选采用：date 不因浏览器时区移日；time 保留上海时钟含义；date-time 按该固定 offset 定位。其他 offset／小数秒应按契约拒绝，而不是先自动转换／截断后冒充原回答合法；上海页面展示仍不依赖浏览器所在时区。

### 4.2 Java 严格解析与 Ajv 断言须同时保留

候选接法为：完整字符串的宽度／字面量检查，随后用 Java `ResolverStyle.STRICT` 校验真实日期及 0—23 时／0—59 分秒，并核实 offset 正好为 `+08:00`；最后仍按接纳的 Schema 开启 format 断言。Java 的 STRICT 处理字段解析和真实日历解析，不会凭一个开关自动限制所有输入只使用上述字面形式；预设 ISO formatter 也可能允许更宽的表示。[Java STRICT][java-strict][Java formatter][java-formatter]

上面的 `YYYY-MM-DD` 只是协议的可读写法；**不能逐字作为 Java pattern 使用**：Java `Y` 是 week-based-year，`D` 是 day-of-year，日历年应使用 `u`、日号使用 `d`，例如所需的日历部分对应 `uuuu-MM-dd`。这一点需进入年末／年初的共享 fixture。[Java pattern 定义][java-formatter]

前端保持 Ajv `validateFormats:true` + ajv-formats **full**，另在 `form-v1` 值适配层实施完全相同的严格表示规则；可以补充受控格式适配，不能为了对齐而取消格式断言，也不能把本项目不允许的 `pattern` 关键字偷偷开放给模型。

不能宣称两端库的全部接受集合天然相同：

- Ajv 的 time 正则允许 `+08`、`+0800`、`+08:00` 等写法；date-time 分隔函数也允许 `t` 或空白。库可接受的写法不等于项目已经选定其线表示。[固定前端函数][ajv-formats]
- networknt **3.0.6 固定源码**的 time 使用 `parseUnresolved(value,new ParsePosition(0))`，没有在该方法中检查解析位置是否已经消费整串；存在“有效前缀后跟额外字符是否被放过”的静态风险，需要明确探针。**本次未运行，不能称已经复现。** Q18 候选的完整字符串检查不能省略。[固定服务端时间源码][time]
- ITU 与 Java 回退的闰秒、小数精度等行为需要按实际依赖路径比较，不把 Java 的解析器默认行为直接归给 ITU 路径。[日期时间分支][date-time]

因此，若最终采用该候选，需要在库校验前后补齐一致的严格线表示和业务时间映射；可采用受控格式适配，但不能静默更换 `form-v1` 含义或关闭 format 断言。

## 5. 错误路径可以对齐，不能直接透传英文文案

Ajv `ErrorObject` 提供 `keyword/instancePath/schemaPath/params`；networknt `Error` 提供 `keyword/instanceLocation/evaluationPath/schemaLocation`，另有 `details.property/index` 和结构化参数。两端的英文文案、错误顺序和 Schema 路径不是同一协议。[Ajv 错误类型][ajv-errors][networknt Error][errors]

| 情况 | Ajv | networknt 3.0.6，已重核固定源码 | 可供实现的归一化方向，尚非已定 DTO |
| --- | --- | --- | --- |
| 字段 `title` 太短 | `instancePath=/title`、`keyword=minLength` | `instanceLocation=/title`、`keyword=minLength` | 共同字段路径及稳定平台错误码；中文文案由项目生成 |
| 缺少 `title` | 父对象路径，`params.missingProperty=title` | 父对象路径，`details.property=title` | 在父路径上追加正确转义的字段名；不能把所有 required 错误都显示到表单顶部 |
| 多出 `extra` | 父对象路径，`params.additionalProperty=extra` | 父对象路径，`details.property=extra` | 指向多余字段或保留表单级错误；不自动删除输入 |
| 数组项错误 | 如 `/participants/0` | 对应 instanceLocation 包含数组位置 | 指回受控多选字段及项；聚合重复项错误时保留明确原因 |
| 根类型／结构错误 | 空 instancePath | 根 instanceLocation | 明确表单级错误，不误指到第一个控件 |

required／additionalProperties 的补字段信息由两端固定实现确认，不能只拿父对象 JSON Pointer 当完整字段路径。[Ajv required][ajv-required][Ajv additionalProperties][ajv-additional][服务端 required][required][服务端 additionalProperties][additional]

共享 fixture 应比较**有效性、平台错误类别、归一化字段／数组路径和归一化值**；错误集合按确定规则比较，避免比较原始英语文案和库的遍历顺序。字段名含 `/`、`~` 时，若 `form-v1` 标识规则允许，必须正确使用 JSON Pointer 转义；若禁止，则两端应在结构接纳阶段一致拒绝。

服务端候选的价值是复用标准数据约束与结构化错误；可信候选有效性、权限、会议可用性、跨字段时间顺序、草稿／提交边界仍由平台负责。本文不改变 [SDK pending 终结研究](SDK挂起终结与检查点接缝补充核验.md)的状态：安全终结适配仍待固定正式 SDK 后选择和隔离探针，未证明时继续 `RECONCILING`。
