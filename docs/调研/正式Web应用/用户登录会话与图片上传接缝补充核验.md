## 1. 登录空闲期限与绝对期限是不同规则

**框架事实。** Spring Session 3.5 的 `Session` API 将 `maxInactiveInterval` 定义为请求之间允许的最大不活动间隔；另有会话创建时间、最后访问时间和属性。它并不把“从本次登录成功起固定经过 N 小时”定义为该字段的含义。本次定位到固定 `3.5.6` 源码，只核验 3.5 系列语义，不锁定项目补丁。[Spring Session：固定 Session API 源码](https://github.com/spring-projects/spring-session/blob/3.5.6/spring-session-core/src/main/java/org/springframework/session/Session.java)

**项目推论。** 若采用固定绝对登录期限，应由服务端保存可信登录签发／到期事实并在受保护边界校验，不把普通访问或 SSE 心跳当作续期；不能只把空闲 timeout 设为同一数值就宣布实现绝对到期。既有 Session 可能在认证前已经存在，不能不加区分地把其创建时间当成本次登录成功时刻。框架空闲上限与绝对窗口须协调，避免空闲策略提前打断产品承诺；更早的退出、账号／安全版本失效仍须立即生效。

## 2. 并发登录、退出和 SSE 的持续查权

**框架事实。** Spring Security 6.5 支持配置并发 Session 上限；可选择达到上限后使旧会话失效，或拒绝新的登录。自定义认证路径须明确接入相应会话策略，不能只照抄一个配置字段就推定已生效。其认证上下文持久化用于后续 HTTP 请求。[Spring Security 6.5：会话管理及并发控制](https://docs.spring.io/spring-security/reference/6.5/servlet/authentication/session-management.html)

默认退出处理可使当前 HttpSession 失效、清理 SecurityContext／repository 及 CSRF token；保留 CSRF 时可用带有效 token 的 POST 发起退出。默认处理不等于本项目已完成所有客户端草稿及连接清理。[Spring Security 6.5：退出处理](https://docs.spring.io/spring-security/reference/6.5/servlet/authentication/logout.html)

**项目限制。** 是否允许多个浏览器并行登录、是否互踢，以及退出的会话范围仍须产品确认。改密后的旧会话失效继续按既有安全版本规则实施。HTTP 请求通过认证，不等于已经建立的 SSE 会在每个批次自动重新鉴权；本项目必须显式落实 #20 的读取／发送批次前和空闲心跳时查权、到期／退出后停止订阅，不能依赖一次握手时的 Authentication 或客户端关闭连接。

## 3. 后端 multipart 接收图片具备框架基础

**框架事实。** Spring MVC 6.2 启用 multipart 解析后，可将 `multipart/form-data` 的字段／文件绑定为请求参数、`MultipartFile`／文件列表；Servlet 解析下也可接收 `jakarta.servlet.http.Part`。元数据部分可通过 `@RequestPart` 转换并进行 Bean Validation。[Spring Framework 6.2：Multipart](https://docs.spring.io/spring-framework/reference/6.2/web/webmvc/mvc-controller/ann-methods/multipart-forms.html)

**项目候选。** 浏览器经同源后端上传，后端接收内容、完成平台验证，再经对象存储适配写入私有原件，具备 MVC 接入基础；对象提供方仍未选择。本页未核验任何厂商 API，也没有实施上传。

**项目限制。** multipart 解析／Bean Validation 不自动验证图片真实格式、JPEG／PNG 白名单、字节／像素限制、摘要、目标归属或当前发布能力；客户端 Content-Type／文件名不等于原件已经可信。暂存票据、状态、恢复引用、TTL、清理与接纳互斥，以及正式图文接纳必须由平台实现。`MultipartFile`／Part 或容器暂存文件本身不是可跨刷新／重启核验的业务暂存记录，上传成功也不能自动创建 Run。
