## 3. Spring Security 7.1.2 口令编码事实

### 3.1 前缀与允许的编码器映射

固定 `7.1.2` 的 `DelegatingPasswordEncoder` 使用 `{id}encodedPassword` 格式，编码时按 `idForEncode` 选择编码器并添加前缀；默认未映射或缺失 id 会由 `UnmappedIdPasswordEncoder` 抛出 `IllegalArgumentException`，不是自动接受明文或自动推断算法。只有显式设置 fallback 才会改变该行为。[固定 DelegatingPasswordEncoder 源码](https://github.com/spring-projects/spring-security/blob/7.1.2/crypto/src/main/java/org/springframework/security/crypto/password/DelegatingPasswordEncoder.java)

本项目可在已选认证路线内使用显式映射：`bcrypt → BCryptPasswordEncoder(12)`，数据库只保存带 `{bcrypt}` 的编码结果及首次改密标识。只接受本项目允许的编码 id，不能把官方示例中的 `noop` 映射当成应启用的项目策略。未知 id 的异常在登录接口应变成受控认证失败，不能泄露原存储哈希；本文没有构造或输出任何真实凭据。

### 3.2 strength 与默认值

`BCryptPasswordEncoder` 固定源码明确默认 strength 为 **10**，可通过构造器显式设置，合法范围为 4—31；`BCryptPasswordEncoder(int)` 默认使用 `$2a` 变体，也可显式选择受支持的 `$2a/$2b/$2y`。因此 **cost 12 是本项目拟定的初始值，不是该版本框架默认值或本研究声称的官方推荐阈值**。实际耗时须在目标机校准，不预先承诺延迟。[固定 BCryptPasswordEncoder 源码](https://github.com/spring-projects/spring-security/blob/7.1.2/crypto/src/main/java/org/springframework/security/crypto/bcrypt/BCryptPasswordEncoder.java)

### 3.3 UTF-8 72 字节界限不能按字符数替代

固定 `BCrypt.java` 先把字符串编码为 UTF-8；`hashpw` 只在 `for_check=false` 的新编码路径拒绝超过 **72 字节**的输入，校验路径经 `hashpwforcheck(..., true)` 处理。因此平台应对初始口令、改密及登录输入统一实施自己的字节边界检查，不能假设框架匹配入口与新编码入口会以同样方式拒绝超长输入；不能通过静默截断口令绕过边界。[固定 BCrypt 源码](https://github.com/spring-projects/spring-security/blob/7.1.2/crypto/src/main/java/org/springframework/security/crypto/bcrypt/BCrypt.java#L543-L579)

整体稿拟定的“至少 12 个 Unicode 码点、UTF-8 不超过 72 字节”是项目口令策略；码点数与 UTF-8 字节数需分别计算，不能拿 Java `String.length()` 或一个前端字符计数同时替代两者。这些阈值供整体评审，不是该框架自动提供的完整口令策略，也没有完成浏览器／服务端一致性或目标机耗时测试。

## 5. 新发现的同坐标 networknt 收敛门槛

### 5.1 SDK 原生工具校验也依赖该库

AgentScope v2.0.4 的固定 `agentscope-dependencies-bom` 声明 `com.networknt:json-schema-validator:2.0.0`，core 发布 POM 把它作为普通 compile 依赖引入。它与已采用的应用校验库 `3.0.6` 是**相同 groupId／artifactId／Java 包名**，不能像 Jackson 2／3 那样声称各保一套版本即可自然并存。整体候选应明确为同一应用 classpath 收敛到 networknt **3.0.6**，因此也会影响 SDK 原生工具参数校验。[固定 SDK 依赖 BOM](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-dependencies-bom/pom.xml)、[core 发布 POM](https://repo.maven.apache.org/maven2/io/agentscope/agentscope-core/2.0.4/agentscope-core-2.0.4.pom)

固定 `ToolValidator` 默认建立 draft-2020-12 Registry，经 `getSchema(String)` 载入，再调用 `validate(String, InputFormat.JSON)`；返回错误通过 `getInstanceLocation()`、`getMessage()` 格式化。它内部另外用 Jackson 2 清理可选 null 字段，但没有直接把 Jackson 2 `JsonNode` 传给 networknt 入口。应用 form-v1 的 draft-07 Registry 应单独配置，不复用 SDK 的默认方言或其可选 null 归一化行为。[固定 ToolValidator 源码](https://github.com/agentscope-ai/agentscope-java/blob/0b6743b263ba8e39eb417e35048026f1e0196548/agentscope-core/src/main/java/io/agentscope/core/tool/ToolValidator.java)

这些符号的静态同名同签名，支持保留 Q16 已定路线作为待验证组合；它**不是整个库的二进制兼容保证**，也没有证明错误输出、方言行为或传递类库能够直接运行。本次不引入 shade／fork 或额外模块来掩盖差异。

### 5.3 首道实施准入

在同一个真实解析后的 classpath 中，必须同时验证 AgentScope 已发布 core JAR 的 `ToolValidator` 默认方言调用和应用 draft-07／form-v1 校验：合法／非法参数、required／type／format／null／错误路径、类加载及依赖版本均需观察。不得通过关闭 SDK 工具校验绕过失败；若编译或运行不通过，阻断该组合并重新设计修正，不先称接入成功。本次没有执行这一探针，以上不改变 Q16 的已采用状态。
