## 2. 实际执行范围

使用本机 MySQL 8.0.45，为 7／17／21／29 表范围各自初始化一次性数据目录、随机本机 TCP 端口和空 schema。未使用用户登录路径、既有库或真实用户数据。实例只监听 127.0.0.1；建库前核对 `@@datadir` 必须等于本轮自建目录。

客户端使用 `--no-defaults`，并把 `MYSQL_TEST_LOGIN_FILE` 指向本轮临时目录中不存在的文件，隔离 `.mylogin.cnf`。该环境变量的覆盖语义见 [MySQL 8.0 官方环境变量说明](https://dev.mysql.com/doc/refman/8.0/en/environment-variables.html)。

事务性约束探针及关联基线／异常场景均回滚；并发探针需要真实提交，随后删除本次合成标识并检查全库行数为零。四个临时实例均已关闭，所创建目录已清理。执行器只在实例身份核验成功后发送 shutdown；核验前失败时只终止自己持有的子进程树，不按端口或进程名关闭服务。

全库范围还实际完成：

1. 包含全部 29 表的完整合成基线：12 组全库＋9 组身份＋11 组记忆查询共 32 个结果全为零；随后聚合异常使全库 12 组全部命中。
2. 29 个独立定向异常分别从有效基线注入并回滚，每例要求指定巡检组命中。覆盖 Session 来源缺失／跨用户／跨员工／自环／多节点环，升级发起人及首 Run／激活 Run 错配，缺少 CONSUMED 确认的 READY_TO_SEND／SENT／SUCCEEDED／UNKNOWN 操作，以及平台身份引用其他用户。
3. 2 个额外合法场景的 12 组结果全零：来源资料已更新而快照仍固定旧修订、PLATFORM_USER 身份正确引用操作者。完整基线同时容纳历史停用版本、撤销授权及 NO_CHANGE 来源修订不同于原发布的情况。
4. 新增 5 项四客户端并发性质：草稿修订 CAS 仅一胜者、同来源修订仅一发布、同管理员成功请求仅一收据、失败事件均可保留、授权版本 CAS 与 grant／审计同事务提交。与既有输入序号分配、记忆任务领取、记忆激活条件更新 3 项合计 8 项。
5. 08 号新表／审计探针自身通过 86 拒绝、9 正向：包括同一管理员请求键换员工或换动作仍冲突、历史相同内容可生成第三版、失败可重复、JSON 对象与空值、中文／空资源／255 字符路径及等价路径冲突。

拒绝探针核对全部错误码及约束／索引名称；正向输出必须与预期 PASS 数完全一致，意外错误不能被 `--force` 隐藏。上述正向、巡检和定向场景分别计数，不把它们合并冒充 29 项应用测试。

[隔离实例边界单元测试](../../../db/tests/test_隔离实例边界.py)另通过 5 项：数据目录不匹配、身份查询失败、启动超时、初始化失败、已核验实例关闭。测试使用假进程，验证未核验时没有协议 shutdown／建库，以及仅终止持有的进程、临时目录清理和客户端环境恢复。

## 5. 证据边界与下一步

本轮证明已列出的结构、SQL 约束、逻辑关联与并发性质。SQL 种子直接构造发布和 NO_CHANGE 收据，因此不能证明真正发布服务会保持停用、不生成半包、重试原收据或正确处理提交结果不明。相同内容摘要可重复只证明结构允许 A→B→A，不证明应用已执行该流程。

完整包、依赖及 JSON 规范化摘要未重算；资源文本的 SQL SHA2 重算已验证。Session 来源链巡检遇环会停止，超过 MySQL 递归上限时查询报错，不能解释为零异常。会议手机号的历史引用仅核对存在，不把当前所有者反推为历史操作者；真实发送边界必须复核当前身份、版本、权限及一次性确认。

应用事务、真实 JdbcStore／AgentState／Memory／Workspace 读写与恢复、对象存储原件、受控模型和真实 MCP 仍未验收。机器结果中的对应标志均为 false；合成 KV／对象引用不证明外部内容存在。#9 不能据此作为整体运行验收关闭。
