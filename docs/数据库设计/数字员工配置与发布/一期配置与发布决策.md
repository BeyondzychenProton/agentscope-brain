# 数字员工一期配置与发布决策

> 更新：2026-10-20（上海时间）。对应决策议题：确定数字员工定义、发布版本与用户授权关系（Issue #6）。本文记录已确认的一期范围；不是建表规格，也不表示后端已经实现。

## 配置与发布主流程

管理员修改一份员工草稿，保存后手动发布。发布时检查必填配置和引用有效性，一期不增加审批、强制测试通过等门槛。

- 每个数字员工保留一份可修改草稿；保存草稿不影响正式服务。
- 管理员直接维护模型及必要参数、员工指令、Skills、MCP 与允许使用的子工具。
- Workspace、Memory 采用平台统一约定，一期不增加独立配置页面。
- 修改能力配置需重新发布才对正式使用生效。后续新会话使用新版，已有 Session 及其 Run 继续固定原发布版本。
- 发布版本必须能够找到当时使用的具体内容；仅保存指向可变文件的路径不满足这一要求。
- 一次“发布员工”自动固化本次模型配置、指令、Skill 内容和 MCP 工具绑定，一期不增加独立的 Skill、工具发布操作；凭证继续单独管理。
- Skills 使用 MySQL 管理：员工草稿保存完整文本包，正式正文和参考资源拆为两张不可变明细表，员工发布 JSON 保存快照引用。运行时通过按固定发布版本限定的只读 `AgentSkillRepository` 装载，不强制先生成本地目录；其他 Skill 来源不得覆盖发布内容。
- 管理员使用本人绑定手机号走正常调用链路，一期不增加专门的测试隔离机制。原有不同用户、不同员工的数据隔离要求继续有效。
- 回滚功能移出一期范围。

## MCP 接入与员工绑定的分工

| 内容 | 一期维护方式 | 责任 |
| --- | --- | --- |
| MCP 服务提供的工具及业务实现 | MCP 服务端代码 | 提供方开发维护工具 |
| 平台连接信息 | 后端配置文件 | 配置服务地址、连接参数及凭证引用 |
| 平台适配逻辑 | Java 代码 | 按已确认规则注入当前用户手机号、签名并执行操作确认等控制 |
| 员工可使用的 MCP 与子工具 | 网页 | 管理员选择已接入服务，勾选允许使用的工具，并随员工发布生效 |

一期流程：

1. 开发人员配置会议 MCP 的连接信息，完成身份和签名适配。
2. 平台连接服务，获取其提供的工具清单。
3. 管理员在员工配置页选择已接入的 MCP 服务及允许使用的子工具。
4. 发布员工后，所选工具进入该员工的正式配置。

一期不建设 MCP 连接信息的网页管理功能。员工配置页面不接收服务地址或密钥；实际密钥由凭证管理读取，配置只保存凭证引用。新发现的工具进入待选择清单，必须经过管理员选择并重新发布员工，才可被该员工使用。

配置文件维护连接信息属于接入方式，不改变先前已确认的工具绑定版本约束：已发布员工引用不可变的 `tool_binding_version`。后续物理设计仍需保证旧发布版本的连接目标及工具契约能够被准确定位。
