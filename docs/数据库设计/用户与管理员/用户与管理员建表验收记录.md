修订后的建表 SQL 在真实 MySQL 上执行成功。独立验收器返回：

```text
PASS：7 张表、74 个有注释字段、0 外键、0 存储过程；业务唯一约束、事务回滚和 9 项关联巡检通过
```

| 检查项 | 结果 |
| --- | ---: |
| 身份表 / 字段 | 7 / 74 |
| 缺少中文注释的表或字段 | 0 |
| CHECK 约束 | 11 |
| 外键 / 存储过程 | 0 / 0 |
| 验收后留下的测试数据行 | 0 |

结构验收检查每表的 `id BIGINT UNSIGNED AUTO_INCREMENT` 主键、`gmt_create/gmt_modified DATETIME(6)`、`is_xxx TINYINT UNSIGNED`、索引命名、VARCHAR 索引长度和注释覆盖。MySQL 会把**等于字段全长**的 VARCHAR 索引长度规范化为无前缀显示；验收器同时核对原始建表 SQL 中已显式声明长度。

事务性用例覆盖：同名用户共存、同一用户重复凭据拒绝、第二名固定管理员拒绝、错误单例键拒绝、同一用户第二个当前号码拒绝、缺少号码的会议检查通过状态拒绝、改号后旧号保留与探测状态失效、旧号重复登记拒绝、非法账号状态和非法布尔值拒绝，以及停用、重置密码、重新启用的状态与版本变化。预期错误码由验收器逐项核对；合成数据最后回滚。九项只读巡检返回异常数均为 0。

## 数据库与应用边界

- 数据库保证**最多一名**固定管理员、**每名用户最多一个**当前手机号，以及凭据和检查状态的每用户唯一性。部署初始化、开户和启动检查仍须保证“恰好一名有效管理员”及“每个可登录用户恰好一个当前手机号”。
- 依阿里巴巴规约不建立物理外键。`user_id`、`phone_id` 引用目标是否存在、会议检查是否引用当前用户的当前号码及匹配 `phone_revision`，必须由服务事务验证，并由[关联巡检](../../../db/tests/02_身份关联巡检.sql)持续发现异常。
- 密码哈希强度、首次改密限制、Web 会话撤销、Run 停止、普通用户的数字员工授权和会议工具判权均需要后续应用及目标环境集成测试。本次 `PASS` 只证明已列出的数据库结构与 SQL 场景。
- 固定管理员尚未初始化。正式开户及角色初始化不得使用测试中的占位密码摘要。

后续业务会话、数字员工配置、AgentScope 状态与记忆、Workspace 及多渠道关系继续以[已确认的身份模型](用户与管理员数据模型.md)为前提单独设计。
