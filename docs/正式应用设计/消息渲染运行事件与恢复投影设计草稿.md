## 2. 第一轮已确认决定

### Q1：固定种类、可版本化的展示内容块

| 内容 | 已确认表达方式 |
| --- | --- |
| 正文 | 文字与受控 Markdown，支持列表、表格、代码块和链接 |
| 图片 | 引用平台已有、经过鉴权的素材 |
| 结构化结果 | 受控列表、表格和结果回执，由服务端根据实际结果生成 |
| 表单及操作确认 | 引用 #19 的交互请求和不可变展示修订，状态读取服务端事实 |

这是浏览器的展示契约。展示对象的持久归属仍分别是正式消息、Run 过程、工具操作或交互请求；不能把所有卡片都写成正式员工消息。组件种类固定，新增表达能力通过契约版本扩展；实时显示和刷新后的读取采用同一套内容定义。

### Q2：执行过程只展示可核查的阶段和工具信息

- 阶段示例：正在查询空闲、等待补充信息、等待操作确认。
- 工具动作：查询目标、完整校验后的必要参数、开始时间及执行状态。
- 结果摘要：候选数量、预约真实状态、预约编号或结果待核对。
- 失败信息：可理解的原因及当前允许的后续动作。
- 原型中的“思考过程”改为受控阶段说明；模型原始 Thinking、系统提示、凭据和原始请求报文不传给用户端。
- 工具结果按平台核验事实展示，模型文字和 SDK 完成事件不能单独证明外部业务成功。

## 4. 第二轮已确认决定

用户回复“全部采用”，确认以下两项推荐。

### Q3：一期 Web 的对外事件协议

使用平台自有、版本化的业务投影协议，直接表达已有 Session／Run、内容块、交互和工具操作事实。平台负责事件定义、前后端状态合并、版本兼容和恢复；不能以“自有协议”推导实现工作更少或已经完成。

另一条可行路径是采用 AG-UI 1.0 事件标准及客户端，并补齐平台语义映射、业务 Run 与多个协议 run 的关联及恢复读取。2026-10-23 定向复核 [AG-UI HTTP+SSE 绑定](https://docs.ag-ui.com/spec/1.0/basic/transports/http-sse)和[中断续接规范](https://docs.ag-ui.com/spec/1.0/basic/patterns/interrupt-resume)：默认绑定不提供原流续入，中断后的续接开启新协议 run。该限制不表示 AG-UI 无法适配本项目，只表示不能省略平台自己的恢复契约。

本决定依据一期单一受控 Web 工作台和已经确定的交互语义；不选择前端框架、表单 renderer 或 Java SDK。本次没有选择 AG-UI 作为一期 Web 对外协议。

### Q4：实时展示与持久投影的关系

只向浏览器发布已持久提交的内容与状态。细小的模型文本增量允许短时合并后保存、再推送；保留累计正文、必要的有序文本变更以及关键阶段、工具、交互和最终状态。不要求保留原 SDK 的每个 token 事件或重放逐字动画。

这会增加生成到显示之间的等待，合并窗口和资源上限留待具体契约收敛。持久失败时不把尚未保存的内容发布为可恢复结果；服务端业务提交与投影事件之间的事务一致性、游标及快照衔接仍需后续确定。

## 5. 第三轮已确认决定

用户回复“全部采用”，确认以下三项推荐。

### Q5：普通 HTTP 动作接口与只读 SSE 订阅

消息提交、表单草稿／回答、操作确认、继续和取消沿用普通 HTTP 接口；另以 GET 快照和 GET SSE 读取持久投影。SSE 仅承担服务端向浏览器的更新，不因连接或重连执行模型、继续 pending 或发送工具操作。

浏览器对当前可见 Session 维护一条订阅，切换时退订原连接；同一会话多个标签页可以各自读取。订阅关闭只改变连接，不取消业务 Run。读取沿用服务端可信登录与归属校验；具体认证载体和代理配置由 #22 落实，不在本轮隐含选择。

### Q6：会话统一有序游标与事务变更批次

同一 Session 的消息、Run、工具、交互及累计正文变化共享一个持久递增序号，不同 Session 独立；重试 Run 也继续该 Session 序列。现有正式消息号和 Run 内事件号保留各自语义，不冒充该游标。

可见业务变更、对应投影及序号在同一平台 SQL 事务提交。同事务内多个对象变化作为一批供客户端整体应用；失败回滚不发布部分变化。会话序号分配受同一会话串行化约束，遵守已有全局锁顺序；不用时间戳、SDK 事件 ID 或普通自增主键推定提交顺序。具体表结构和跨表一致性证明留待最小结构契约。

客户端处理重复批次时去重，只有完整应用成功才前移自己的已应用游标；网络收到或 SSE 解析到事件不等于应用完成。

### Q7：生成内容与正式消息的稳定展示关联

服务端为生成中的内容分配稳定展示身份，正式消息提交事件明确指出其替换的预览。客户端采用正式内容完成该处展示，不再额外追加一份同文回复；若最终内容与预览不同，以正式提交内容为准。

同 Run 不同 SDK 调用的输出分别关联。工具前说明、前一等待阶段的过程文字继续作为过程保留，不把该 Run 的全部片段拼成正式回复；失败或中断的内容保留并标识其状态。具体字段与正式消息的提交／关联校验在后续完整契约中给出，不以 SDK replyId 猜测。

## 6. 第四轮已确认决定

用户回复“全部采用”，确认以下三项推荐。技术事实见[消息事件传输与一致快照补充核验](../调研/正式Web应用/消息事件传输与一致快照补充核验.md)；其中“官方事实”和“项目推论”分别记录，静态研究不当作运行证明。

### Q8：一致快照、水位与历史分页

首次打开或需要重建时，读取同一一致视图中的会话可见状态、近期正式消息、当前 Run 累计正文／关键过程、当前交互及最近成功保存的草稿，并返回同视图的已提交游标 `watermark`。客户端先完整装载快照，再读取严格大于该水位的持久增量；快照读取与订阅之间新提交的变化也能补齐。

平台 SQL 的快照对象与 watermark 须由同一 read view 构造；一期可使用显式 REPEATABLE READ 的只读一致事务。不能先读旧对象，再从另一个当前视图取最大事件号。实时动作的授权仍在动作入口重查，不因快照里的按钮可用就取得执行权。

旧正式消息按消息序号分页读取，每轮分页固定已观察到的正式消息上界；向前翻页不改变实时游标或重复加载新消息。当前任务状态与可响应交互完整恢复，不让翻页决定其有效性。具体分页大小、过程详情分页及负载上限待资源契约收敛；快照不等于导出整个会话的全部过程日志。

### Q9：断线、缺口与慢消费者的持久补读

断线后从应用已成功应用的游标补读；发现缺口或乱序先暂停应用后续批次并补齐。必要增量无法补齐或游标无效时，明确重读一致快照；不能静默跳号。

发送队列有界，慢消费者超限时关闭该订阅，再按同一持久读取路径恢复，不删除中间更新后继续发送。连续 SSE 失败时允许自动降为只读增量轮询；使用有界退避并可再次尝试 SSE。连接状态与业务 Run 状态分别显示，网络错误不把 Run 标为业务失败，也不自动重发用户动作。

快照、事件补读、轮询和重连始终只读；重新构建展示不能消除既有 RECONCILING 或 UNKNOWN，也不能替代用户明确继续。失败次数、退避和队列上限在资源契约确定。

### Q10：未知内容与不兼容事件的处理

已知事件中某个不支持的内容块显示纯文本占位及可读说明，禁用该块涉及的交互；其余可理解内容可继续阅读。表单未知版本／组件沿用 #19 的不可填写规则。

若不认识的是事件协议版本、变更种类或影响整个事务批次解释的结构，不跳过该批次、不前移游标，停止该消费链并尝试获取可兼容快照。仍无法兼容时保留最后已确认视图，明确提示更新客户端；该会话交互保持不可操作。重试与快照次数有界，不形成无限重建循环。

只将被契约标为可忽略的可选扩展视为无语义影响；不能把未知状态码或未知动作当作成功／可执行。占位回退不执行 HTML、脚本、任意组件或原始载荷。

## 7. 第五轮已确认决定

用户回复“全部采用”，确认 Q11—Q14 及[完整契约候选](消息渲染运行事件与恢复投影契约候选.md)中的相应字段、初始上限和验证边界；整理后的本地契约见[正式规格](消息渲染运行事件与恢复投影设计规格.md)。以下保留当轮推荐原文，均已获确认。

### Q11：固定变更类型、对象完整版本和受约束正文追加

推荐批次外层固定协议／会话／流标识、前驱与本批序号、时间和 `changes[]`；使用候选中的八种变更类型。普通对象发布完整展示版本，仅正文用内容版本匹配的追加。未知关键结构按 Q10 停止应用。受控 Markdown、素材和详情引用按候选第 1 节执行，不接收任意可执行界面更新。

### Q12：历史卡片保留及一次正式收尾

推荐结束后的表单／确认／结果卡保留原修订、提案和回答／结果供只读回看；仅当前有效请求开放动作。正式消息、Run 成功及预览替换在核实框架状态后一次平台事务收尾；通过内容关闭状态和调用 fence 拒绝迟到片段、通过幂等回查阻止重复收尾。操作回执始终独立表达真实操作事实。

### Q13：最小持久结构及投影流代次

推荐 Session 增加投影流标识和最后序号，新增一张事务批次投影日志，并扩展现有 `run_progress` 的结构载荷和展示／调用关联；保留正式消息 `TEXT/MEDIA`、原工具账本及 #19 三类交互记录的职责。普通重启沿用投影流，受控恢复／重建若使旧游标失真则换流并明确重读快照。

### Q14：采用候选中的初始资源与恢复上限

推荐正文按 100 ms／4 KiB 合并，单 Run 正文 256 KiB，正式消息页默认 50 条／过程页 20 条，批次 1 MiB／快照与补读 2 MiB，连接队列 100 批或 4 MiB。其余结构块、心跳、退避、轮询、权限复核和有界兼容重建参数按候选第 4 节完整表格；超限明确收敛或固定版本详情读取，不静默截断为完整回复。
