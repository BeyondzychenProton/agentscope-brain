# 后端接口与事务锁序契约

> 日期：2026-10-25，Asia/Shanghai；议题 [#22](https://github.com/BeyondzychenProton/agentscope-brain/issues/22)。  
> 状态：2026-10-25 已随后端主规格通过用户整体评审的**接口与事务附录**。沿用 [#19 交互规格](动态表单与交互请求生命周期设计规格.md)、[#20 投影规格](消息渲染运行事件与恢复投影设计规格.md)、[#21 工作台规格](工作台交互与前端工程设计规格.md)和[后端逐轮草稿](后端工程与用户链路设计草稿.md)。新增路径、DTO、锁序及失败窗口为这些决定的工程细化，已随完整规格确认；尚无实际接口或事务运行证明。  
> 本文没有创建 API、应用工程、DDL 或初始化数据，没有通过真实框架／模型／会议验收。不增加管理员角色、管理 API、归档／版本操作界面或记忆管理 API。

## 1. 对外约定与零执行读路径

所有路径统一使用 `/api`；保留 #19／#20 已定路径，不混入 `/api/v1`。
业务 Session、Spring 登录会话、SDK 状态槽及一次 SDK 调用分别识别，不互相替代。
可信 UserId 只由当前认证取得；路径、JSON、上传票据和模型参数均不能选择 principal。
BIGINT 标识、行版本和序号在线格式中为十进制字符串，不能转换成可能失真的浮点数。
`requestKey/submissionKey/clientIntentId` 为稳定 UUID；公开资源 ID 和 cursor 为服务端受控定位。
所有时间戳用带 offset 的 ISO 时间；协议 occurredAt 使用 UTC；表单值另遵守 Q18。
JSON DTO 用 camelCase，SQL 列用 snake_case；未知动作、主版本、组件和结构拒绝。
已鉴权业务写带 CSRF 和稳定请求键；同键不同规范语义返回 `IDEMPOTENCY_CONFLICT`。
认证登录／改密／退出走会话和 CSRF 协议，不把口令或口令派生摘要写入通用幂等账本。
`allowedActions` 只是当前展示提示；收到动作后仍须重新查权、查版本和核对状态。
`sessionVersion/runVersion/dispatchVersion/responseVersion/uploadVersion/intentVersion` 对应各自持久控制记录的 row_version；#19 的 expectedRunVersion 需要补齐原 business_run 缺少的真实 CAS 列，不能使用投影 viewRevision 代替。

**所有业务 GET、SSE、补读及轮询均不调用 AgentScope、不执行模型、不调用会议工具。**
GET 不恢复 pending、不领取 dispatch、不修复业务状态、不创建提交墓碑、不执行重试。
图片代理 GET 可以使用 MinIO 客户端读取既定原件，不能创建／替换／删除对象。
认证基础设施可维护 Cookie／CSRF／访问元数据，但不得延长原固定 24 小时绝对期限。
只读响应不返回确认 token、密码、密钥、原始模型／MCP 报文或内部状态快照。
跨用户资源按 `404 NOT_FOUND` 处理；账号失效停止读取；撤销员工使用权后按既定规则保留本人历史读取。

## 2. 认证、当前用户与有效能力

| 方法与路径 | 输入 | 成功返回及边界 |
| --- | --- | --- |
| `GET /api/auth/csrf` | 无业务 principal 参数 | `200 {headerName, token}`；只建立／读取 CSRF 基础设施，不调用外部服务 |
| `POST /api/auth/login` | `{phone, password}`，CSRF | `200 AuthDto` + HttpOnly／Secure 登录 Cookie；失败不泄露号码是否存在 |
| `GET /api/me` | 当前 Cookie | `200 MeDto`；受限登录也只返回必要身份及改密阶段 |
| `POST /api/auth/password/initial` | `{currentPassword, newPassword}`，当前受限会话与 CSRF | SQL 改密及新认证上下文均成功后 `200 AuthDto`；保持本次登录原绝对到期时间 |
| `POST /api/auth/logout` | 当前会话与 CSRF | `204`；使当前登录会话失效，清理当前认证上下文；不使其他独立浏览器会话退出 |
| `GET /api/employees/{employeeId}/capabilities` | 本人有权查看的员工定位 | `200 CapabilityDto`；只读有效能力，不现场请求模型或会议 MCP 探测 |

`AuthDto`：`{authStage, userId, displayName, authenticatedAt, absoluteExpiresAt}`。
`authStage` 为 `PASSWORD_CHANGE_REQUIRED/READY`；不返回 Spring Session ID 供业务使用。
`MeDto`：AuthDto 加 `{maskedPhone, employees:[{employeeId, displayName, canStartRun, readOnly, unavailableReason, capabilities}]}`。
`CapabilityDto`：`{employeeId, capabilityContext, acceptsText, acceptsImages, imageLimits, allowedActions, unavailableReason}`。
`imageLimits`：`{allowedMimeTypes, maxImageCount, maxBytesPerImage, maxPixelsPerImage}`，来自有效固定配置。
`capabilityContext` 仅用于一致性定位，不能作为授权凭据或版本 UI 标签。
账号、凭据、当前号码和授权异常分别在服务端核实；不能用显示姓名或客户端手机号确定操作者。
受限登录只开放 CSRF、me、首次改密及退出，不开放素材、会话历史或执行。
普通退出／24h 到期终止该登录会话的新 HTTP 动作、读取和 SSE，不等同于取消已接纳 Run。
后台已接纳执行以可信 UserId 和捕获的安全／授权／手机号版本为依据，每个执行／工具边界复核当前账号与权限，不要求原浏览器 HttpSession 仍存活。
账号停用、安全版本或授权变化阻断后续边界；已发送写操作仍核对。明确取消一律走原 Run cancel；恢复 continue HTTP 必须当前有效登录。
首次改密更新 credential／securityVersion、撤销旧安全上下文并留审计，不实现后台重置功能。
正常成功直接进入工作台；换登录会话 ID 不重新计算本次登录 24 小时窗口。
改密 SQL 结果不明先按 credential／securityVersion 核对，不能自动重跑改密。
SQL 已改密但新会话保存失败，返回 `PASSWORD_CHANGED_RELOGIN_REQUIRED` 并安全退出。
无法证明 SQL 结果则返回 `AUTH_OUTCOME_UNCERTAIN`；不把旧安全版本会话恢复为有效。
认证数据库和基础数据不可用时返回受控不可用，不把模型／MCP 在线作为登录前置。

## 3. 普通会话列表、标题与新建意图

| 方法与路径 | 输入 | 成功返回及边界 |
| --- | --- | --- |
| `GET /api/sessions` | `employeeId, q?, pageCursor?, limit=50`，limit 上限 100 | `200 {items:SessionSummary[], nextPageCursor, hasMore}`；本人普通会话标题全范围查询 |
| `PATCH /api/sessions/{sessionId}/title` | `{requestKey, expectedSessionVersion, title}` | `200 SessionSummary`；原会话内改名，不新建消息／Run，不调模型 |
| `POST /api/session-intents` | `{requestKey, clientIntentId, employeeId}` | `200 IntentDto`；持久登记当前标签新建意图，不创建业务 Session |
| `GET /api/session-intents/{intentId}` | 本人 intentId | `200 IntentDto`；只读登记／绑定结果，不初始化 Session |

`SessionSummary`：`{sessionId, employeeId, title, sessionVersion, updatedAt, activeRun, allowedActions}`。
`activeRun` 可空；非空为 `{runId, status, processingStatus}`；业务状态与排队／连接说明分开。
搜索只匹配标题，不搜索正文，不只过滤浏览器已加载页；SQL 参数化并处理 LIKE 通配字符。
列表按 `updatedAt DESC, sessionId DESC` 排序；pageCursor 绑定本人、员工、查询条件和继续位置。
改名校验非空可读标题及已有 200 字符边界；UI 截断不改存储值。
首次输入确定性生成标题，纯图片采用可读默认名；不另调模型命名。
不提供 `POST /api/sessions` 创建空 Session，不加入归档／恢复／升级或版本历史 API。

`IntentDto`：`{intentId, clientIntentId, employeeId, preparationContext, intentVersion, status, acceptedSubmissionKey?, sessionId?, messageId?, runId?}`。
本人同 `clientIntentId` 重复登记返回同一意图，员工不一致则冲突。
local clientIntentId 仅定位当前标签草稿；服务端意图记录负责可信归属和第一次接纳互斥。
点击新建可以只保留本地页面；需要准备上传／发送时才登记服务端意图，不增加空业务 Session。
准备记录冻结 employee、release 和有效图片能力；preparationContext 是受控定位，不展示成版本管理标签，也不提供永久执行权。
首次接纳要求冻结发布仍是当前有效默认发布，能力和归属仍一致；否则 `PREPARATION_STALE/RELEASE_CHANGED` 并保留草稿，不静默换发布或移植暂存。
意图一旦绑定首条接纳结果，不被另一个 submissionKey 用来再造 Session。
同提交键回查原结果；不同提交键命中已绑定意图返回 `INTENT_ALREADY_ACCEPTED` 和本人可读的原结果定位。
后续新消息须明确使用原 Session 目标，不把已绑定新建意图解释为追加消息。

## 4. 上传暂存与 MinIO 鉴权代理

`TargetDto` 恰取一种：`{sessionId}` 或 `{intentId}`；不能两者同传，也不接受任意对象地址。
已有 Session 使用其固定员工发布能力；新建意图使用冻结的准备发布／图片能力，正式接纳时再核实它仍是当前有效默认且验证上下文一致。

| 方法与路径 | 输入 | 成功返回及边界 |
| --- | --- | --- |
| `POST /api/uploads` | `{requestKey, target:TargetDto, fileName, mimeTypeHint, byteCountHint, clientSha256Hint?}` | `200 UploadDto`；创建受控票据和对象键，服务端起算 24h，不创建 Run |
| `POST /api/uploads/{uploadId}/content` | multipart：`requestKey, file` | 验证／持久收尾后 `200 UploadDto`；处理已开始但未完成时 `202 UploadDto` |
| `GET /api/uploads/{uploadId}` | 本人 uploadId | `200 UploadDto`；只读已保存上传／验证／核对事实 |
| `POST /api/uploads/{uploadId}/verify` | `{requestKey, expectedUploadVersion}` | `200/202 UploadDto`；明确核对原对象，不重新上传、不分配新对象键 |
| `POST /api/uploads/{uploadId}/discard` | `{requestKey, expectedUploadVersion}` | `200 UploadDto`；使未绑定暂存禁止新绑定，物理清理另行收尾 |
| `GET /api/uploads/{uploadId}/content` | 本人、未失效且允许预览的暂存 | 鉴权代理图片字节；不借读取完成业务验证或更改暂存状态 |
| `GET /api/media/{mediaId}/content` | 本人正式 message_media | 鉴权代理历史原件；不要求重新调用模型／会议工具 |

`UploadDto`：`{uploadId, target, uploadVersion, status, createdAt, expiresAt, verifiedMedia?, canBind, boundMediaId?, reason}`。
`verifiedMedia`：`{mimeType, byteCount, width, height, contentSha256}`；仅验证完成后返回。
状态技术码为 `ISSUED/UPLOADING/VERIFYING/READY/RECONCILING/BOUND/BLOCKED/CLEANED`。
`expiresAt` 为票据创建时间加 24h；刷新、上传重试及 verify 均不续期。
`canBind` 由 READY、原期限、当前归属／能力和禁止绑定状态共同决定，不信任客户端提示。
文件名、Content-Type、长度／摘要 hint 均非验证事实；后端检查 JPEG／PNG 真实类型、非空、字节、像素和 SHA-256。
MinIO ETag 不代替 SHA-256；对象键、storageProfile、bucket 及历史对象版本均由服务端受控确定。
上传准备／对象网络调用不持平台 SQL 行锁；写对象前后通过上传 fence 与短事务关联。
未知上传先查询原 uploadId，再由 verify／受控协调核对原对象；不能自动换对象键重传或立即删除。
所有必需图片 READY 后仍由用户点击发送；任一失败不自动退化成纯文字 Run。
BOUND 引用指向正式素材，不受暂存 TTL 清理；discard 不删除正式素材，也不取消已接纳 Run。
清理先持久 BLOCKED、排除绑定／在途接纳／结果未知，再删除对象；失败保留禁止绑定状态和可重试事实。
代理响应固定已验证图片类型、`X-Content-Type-Options:nosniff` 及 `Cache-Control:private,no-store`，不返回 MinIO 凭据或公开 bucket URL。原件先按已验证大小界限在有界缓存／临时文件核对版本、完整长度和摘要，再向浏览器输出；临时文件仅为可重建缓存，响应结束清理，不作为永久原件。
读取对象版本／字节／摘要不符明确报原件不可用，不能换用新对象或伪造恢复成功。

## 5. 普通提交、回查及明确封闭

普通提交控制与 FORM response 分离；唯一身份为可信 `UserId + submissionKey`。
首次正式接纳在一个平台事务中创建必要 Session、用户消息、媒体、内容块、Run 和投影。
前置登记仅保存控制身份／意图；不能把该阶段显示成“正式消息已接纳”。

| 方法与路径 | 输入 | 成功返回及边界 |
| --- | --- | --- |
| `POST /api/submissions` | `SubmissionPayload` | 新接纳 `202 SubmissionDto`；同键同语义返回原接纳定位及当前处理状态 |
| `GET /api/submissions/{submissionKey}` | 当前用户作用域下原键 | `200 SubmissionDto`；未观察到登记时为 UNOBSERVED，不推断未接纳 |
| `POST /api/submissions/{submissionKey}/close` | `{requestKey, expectedSubmissionVersion?}` | `200 SubmissionDto`；明确与接纳互斥封闭；先接纳则返回原接纳结果 |

`SubmissionPayload` 的完整形态：

```json
{
  "submissionKey": "稳定 UUID",
  "target": {"intentId": "服务端意图 ID"},
  "text": "完整普通文字，可为空",
  "uploadIds": ["按消息内容顺序排列的暂存 ID"]
}
```

已有会话把 target 替换为 `{sessionId}`；文字与素材不能同时为空。
规范语义覆盖目标／意图、完整文字、素材顺序及受控原件摘要；由服务端计算，不相信浏览器哈希。
普通 composer 的有序内容映射固定为 TEXT（非空时）后接 uploadIds 顺序的 MEDIA；不使用文件名或对象 URL 决定位置。
不把密码、确认 token 或密钥加入普通提交语义或日志；正式素材选择不能来自任意 URL。
登记后的目标／语义／素材集合不可原地改变；修改输入须先核对／明确封闭原键，再由用户明确用新键提交。

`SubmissionDto`：`{submissionKey, registrationStatus, submissionVersion?, acceptanceStatus, processingStatus, result?, reason?, allowedActions}`。
`result`：`{sessionId, messageId, runId}`，只有接纳后存在。
`registrationStatus`：`UNOBSERVED/REGISTERED/ACCEPTED/RECONCILING/CLOSED_UNACCEPTED`。
`acceptanceStatus`：`UNKNOWN/ACCEPTED/CLOSED_UNACCEPTED`；REGISTERED 本身不表示已排除在途接纳。
`processingStatus` 来源于原 Run／dispatch，不把 ACCEPTED 等同于模型开始或业务成功。
同键已接纳始终返回原结果，不受当前队列满、图片到期或后续 Run 状态影响。

**先封闭、后迟到提交**：没有登记行时，close 允许按 actor＋key 创建 CLOSED_UNACCEPTED 墓碑。
该墓碑的 target、语义摘要和 uploads 为空，准确表示“此键禁止再接纳”，不虚构曾有提交内容。
已有登记行／已接纳行的上述信息不可清空；同键不同语义按原记录拒绝。
close 与 POST 接纳都先确保同一唯一控制行持久存在，再在短事务内加锁重读。
接纳先提交：close 返回原 result；封闭先提交：所有迟到旧键永久拒绝。
GET 查无记录不创建墓碑；一次不存在行查询不能作为排他或未接纳证明。
正式消息已存在而控制记录缺失属于需核对异常，不自动重复插入或将原键封闭为未接纳。
提交控制／封闭墓碑不按图片 24h TTL 清理，不能让旧键复活；正式留存策略仍不在本期范围。

## 6. 既定交互、确认凭据与明确继续

下表保留 #19 既有路径及字段；字段校验、修订与草稿 CAS、一次响应约束仍以 #19 为准。

| 方法与路径 | 输入 | 成功返回及边界 |
| --- | --- | --- |
| `GET /api/runs/{runId}/interactions` | 本人 Run | 当前请求摘要、历史引用、类型／状态／修订／allowedActions |
| `GET /api/interactions/{requestId}` | 本人请求 | 当前展示、草稿／版本、回答摘要、处理状态及失效原因 |
| `PUT /api/interactions/{requestId}/draft` | `{requestKey, revision, snapshotHash, expectedDraftRevision, data}` | `200 {requestId, revision, draftRevision, data}`；不完整合法草稿可保存 |
| `POST /api/interactions/{requestId}/refresh` | `{requestKey, revision, snapshotHash}` | `200` 未变或新修订、迁移说明；不调用 SDK |
| `POST /api/interactions/{requestId}/responses` | FORM：`{submissionKey, revision, snapshotHash, expectedDraftRevision, data}`；确认：`{submissionKey, revision, snapshotHash, confirmationToken}` | 新接纳 `202`；FORM 返回 responseId／messageId／runId／acceptanceStatus／processingStatus；确认返回原操作／确认与响应状态 |
| `POST /api/interactions/{requestId}/continue` | `{requestKey, responseId, expectedResponseVersion}` | 仅经核实未领取的 FORM 响应；不新增回答／消息，不重消费确认 |
| `POST /api/runs/{runId}/cancel` | `{requestKey, expectedRunVersion}` | 原 Run 幂等取消：取消中／待核对／已取消，不新增用户消息 |
| `POST /api/interactions/{requestId}/confirmation-token` | `{requestKey, revision, snapshotHash}` | `200 {confirmationToken, expiresAt}`；原 token 专用领取，不换确认或延期 |
| `POST /api/runs/{runId}/continue` | `{requestKey, expectedRunVersion, expectedDispatchVersion}` | 原业务中有明确未开始证明且当前允许继续的 dispatch；返回原 Run／调度状态 |

FORM 响应结果：`{responseId, messageId, runId, acceptanceStatus, processingStatus, responseVersion}`。
确认响应结果：`{responseId, operationId, confirmationId, runId, responseStatus, operationStatus, sdkSyncStatus?}`。
正常 GET／草稿返回 200；回答新接纳 202；重复返回原接纳身份与当前状态，不虚构另一次接纳。
候选刷新 POST 可以调用必要的可信目录只读工具，记录原 Run／操作者和查询事实；不得执行 SDK、业务写工具或续接 pending。
候选查询在锁外执行，提交新修订前按原修订／请求键重新核验；查询结果不能直接覆盖已回答请求。
FORM 保存／提交／刷新和确认不接收客户端 SDK 对象、tool ID、operator、工具地址或长期 PermissionRule。
确认 token 领取检查本人、当前登录／CSRF、PENDING、原提案／摘要／版本及十分钟期限，解密后核对原 SHA-256。
token 响应 `Cache-Control:no-store`；明文／密文不进投影、草稿、正式消息、URL、普通审计或日志。
领取不消费确认，不新建提案，不延长期限，不调用模型／工具；重复领取返回同一原 token。
原 keyId 不可用、认证标签失败或摘要不符则不可确认，进入既定核对／终结，不签发替代 token。
Run continue 不替代 FORM continue；服务端从原事实确定继续类型，不接受浏览器指定任意任务或执行参数。
CLAIMED／可能已开始的调用、SENT／UNKNOWN 写操作、缺失状态或错代次不能借 continue 重发。
重启后的普通待执行／已消费确认后未发送事项，也必须先核实原账本和当前权限；没有明确未开始证明即待核对。

## 7. 既定快照、增量、SSE 与历史读取

以下路径全部 GET，不重建执行句柄或订阅 SDK 执行源流。

| 路径 | 输入 | 返回 |
| --- | --- | --- |
| `/api/sessions/{sessionId}/projection/snapshot` | `protocolVersion, messageLimit=50, processLimit=20`，两者上限 100 | 同视图对象、streamId／watermark／cursor、历史上界和分页引用 |
| `/api/sessions/{sessionId}/projection/events` | `protocolVersion, after, limit=100` | `{batches[], lastCursor, headSeq, hasMore}`，受既定字节预算约束 |
| `/api/sessions/{sessionId}/projection/stream` | `protocolVersion, after` | 只读持久批次 SSE；显式 after 是已应用 cursor |
| `/api/sessions/{sessionId}/projection/messages` | `protocolVersion, pageCursor, limit=50` | 固定消息上界的不可变历史页 |
| `/api/sessions/{sessionId}/projection/runs/{runId}/history` | `protocolVersion, pageCursor, limit=20` | 固定 asOfSeq 的过程页 |
| `/api/sessions/{sessionId}/projection/content/{contentId}` | `protocolVersion, contentVersion, partCursor?` | 固定版本正文／分块、长度、摘要及继续位置 |

投影批次：`{protocolVersion, sessionId, streamId, seq, previousSeq, cursor, occurredAt, changes[]}`。
changes 类型为 `SESSION_SET/RUN_SET/CONTENT_SET/TEXT_APPEND/CONTENT_CLOSE/MESSAGE_COMMIT/TOOL_SET/INTERACTION_SET`。
快照在显式 REPEATABLE READ 只读事务的同一 read view 中取得业务对象及已提交水位。
不能读完旧对象再从新视图取最大 seq；订阅从严格大于 watermark 的日志补齐。
增量页与其 headSeq 也来自同一读取视图；空增量保留原 lastCursor，不能凭 headSeq 提前推进。
cursor／pageCursor／partCursor 不透明且绑定本人可读范围、流、水位／版本及位置，不提供授权。
详情摘要核对该固定版本实际 UTF-8 响应字节；分块核对分块摘要及全量摘要，不能重排 JSON 后再计算或换成最新版。
SSE `projection.batch` 一帧为完整批次；Last-Event-ID 不覆盖应用已确认 cursor。
控制帧 `caught_up/reset_required/auth_required` 和心跳不分配业务序号。
每次读取／发送批次和空闲 15 秒心跳重新检查登录及权限；退出／到期后停止订阅。
文字 100ms／4KiB 合并、正文 256KiB、批次 1MiB／128变更、响应 2MiB、队列 100批／4MiB 沿用 #20。
连续 3 次 SSE 失败按 1／2／4 秒退避后只读轮询；健康轮询每 30 秒可试 SSE。
轮询活跃 2 秒、等待／无执行 10 秒；连续 5 次读失败暂停自动恢复，均不触发执行。
固定版本详情缺失明确报错，不用模型重建；不把日志受损后的展示重建当作业务修复。

## 8. 受控错误与客户端保留规则

错误体统一：`{code, message, retryable, fieldErrors?, currentVersion?, currentRevision?, currentDraftRevision?, allowedActions?, supportedVersions?}`。
`fieldErrors[]` 为 `{fieldPath, code, message}`；fieldPath 是归一化 JSON Pointer，required／additionalProperties 补齐具体字段。
正文／表单错误不返回原始库异常、SQL、对象地址、密文或模型／MCP 原始响应。

| HTTP | 受控码 | 客户端与服务端含义 |
| --- | --- | --- |
| 400 | `REQUEST_INVALID/TARGET_INVALID/UPLOAD_SET_INVALID` | 参数／目标结构错误；不执行，不清空输入 |
| 401 | `AUTH_REQUIRED/AUTHENTICATION_FAILED` | 平台登录不可用或登录失败；与会议工具身份错误分开 |
| 403 | `CSRF_INVALID/PASSWORD_CHANGE_REQUIRED/CONTINUATION_FORBIDDEN` | 不能继续业务写；不因本地缓存恢复访问 |
| 404 | `NOT_FOUND` | 不存在或不属于当前用户 |
| 409 | `IDEMPOTENCY_CONFLICT/STALE_REVISION/DRAFT_CONFLICT/ALREADY_ANSWERED` | 同键语义、修订、草稿或一次响应竞争 |
| 409 | `SESSION_CHANGED/INTENT_ALREADY_ACCEPTED/SUBMISSION_CLOSED/UPLOAD_STATE_CONFLICT/PREPARATION_STALE/RELEASE_CHANGED` | 目标／准备发布／控制状态已变化；保留原输入并回查 |
| 409 | `RECONCILING/RUN_BUSY/RUN_NOT_WAITING/RUN_NOT_CONTINUABLE` | 证据或状态不允许接纳／继续，同 Session 已有活动 Run，不自动重发 |
| 409 | `CURSOR_INVALID/STREAM_CHANGED/PROJECTION_VERSION_UNSUPPORTED` | 按 #20 重建一次兼容快照或停止，不创建 Run |
| 410 | `UPLOAD_EXPIRED/INTERACTION_INVALIDATED/CONFIRMATION_EXPIRED` | 原对象／修订／确认失效，不延长原期限 |
| 410 | `RESET_REQUIRED/CONTENT_VERSION_UNAVAILABLE` | 原读取范围不可用；不得换最新版本冒充原版本 |
| 413／415 | `UPLOAD_TOO_LARGE/UPLOAD_TYPE_UNSUPPORTED` | 拒绝不符合有效媒体能力的原件 |
| 422 | `ANSWER_INVALID/CANDIDATE_STALE/TITLE_INVALID` | 字段／业务错误；显示所有可确定错误并保留输入 |
| 503 | `EXECUTION_CAPACITY_EXCEEDED/VALIDATION_UNAVAILABLE/PROJECTION_READ_UNAVAILABLE/MEDIA_READ_UNAVAILABLE` | 本层暂不可用；普通容量拒绝须确定未接纳，不覆盖原键已接纳结果 |

改密部分成功使用 `PASSWORD_CHANGED_RELOGIN_REQUIRED`，无法核实结果使用 `AUTH_OUTCOME_UNCERTAIN`；安全退出，不自动重新改密。
提交／上传的网络超时不等于确定失败；冻结原键与内容，先原事实回查。
容量拒绝只说明该次没有接纳，不自动封闭原键；编辑／换键前仍须明确 close 排除迟到接纳。
HTTP 200／202、SDK End、确认 CONSUMED 和会议业务成功分别展示，不共用一个“成功”标志。

## 9. 全局锁序与控制行预持久

全写路径使用以下一个总序；每个短 SQL 事务仅取得其需要的**子序列**，同层多行按主键升序。

| 层 | 行／控制事实 | 约束 |
| --- | --- | --- |
| C0 | `runtime_capacity` 单例容量控制行 | 仅影响前台许可／普通等待计数的事务先取；不能持领域锁后回头补取 |
| L1 | `platform_user`，及其必要凭据／号码控制行 | 多用户按 userId 升序；锁内复核账号、安全／身份版本 |
| L2 | `digital_employee` | 多员工按 ID 升序 |
| L3 | 目标 `employee_release`／有效授权 | 固定发布与授权仍须核对；不锁后再反取员工 |
| L4 | 目标意图 `session_intent` → `ordinary_submission` | 已有 Session 的实体锁仍在 L7；未登记关闭墓碑允许只锁用户与提交键 |
| L5 | `media_upload` | 多素材按 ID 升序，而非按消息展示顺序；展示顺序另存 |
| L6 | `memory_profile` | 输入序号分配及 Run 启动记忆快照；不能持锁贯穿模型执行 |
| L7 | `business_session` | 多 Session 按 ID 升序；含消息号及 projection seq 分配 |
| L8 | `business_run`／必要消息控制事实 | 同 Session 一个活动 Run；新行也遵守写入次序 |
| L9 | `runtime_dispatch` | 排队／领取／重启继续门槛，不是客户端可改状态 |
| L10 | `runtime_sdk_call` → `runtime_state_terminalization` | 原调用与独立终结证据；可信调用键、状态槽／代次及 fence |
| L11 | `interaction_request` → `interaction_revision` → `interaction_response` | request／revision／response 各自同类多行升序 |
| L12 | `tool_operation` | 发送意图与原请求号，不逆序锁确认 |
| L13 | `operation_confirmation` | 固定授权一次消费；不回锁交互或操作 |
| L14 | `memory_update_job` | worker 不可先持 job 锁再倒取 profile／来源 Run |
| L15 | 过程／不可变展示／投影／审计插入 | Session 投影序号已在 L7 持锁；不能最后补锁 Session |

该总序保留旧主干以及 #19／#20 的 memory_profile→Session→Run→交互关系。crypto_nonce_cursor 预留使用完全独立、先提交的单行短事务；不与上表领域锁嵌套，不能持上述锁时等待或回头分配 nonce。
新增 C0 是全局容量并发的最小控制接缝；前台 2 与普通等待 16 不依赖单账号偶然串行。
先无锁定位来源／候选 ID，然后按总序锁定并重新校验；无锁定位不能充当权限或状态证明。
意图／普通提交先按 actor＋稳定键预登记并提交，后在接纳／关闭事务锁定同一实存行。
不存在行的一次 GET／FOR UPDATE 不证明不存在未来写者；唯一冲突须回读原行再走同一总序。
预登记、SQL 领取、外部 I/O、SQL 收尾分别是不同阶段；不得跨网络／用户等待持锁。
死锁或唯一冲突后的允许重试保持原请求键／语义，只重试未产生外部副作用的 SQL 阶段。

## 10. 写路径事务与锁序矩阵

| 路径 | 取得的主要子序列 | 同事务事实及提交后动作 |
| --- | --- | --- |
| 意图／提交预登记 | L1→L2/L3（已知目标时）→L4 | 唯一控制身份及固定目标／语义；不写正式消息／Run，不调 SDK |
| 普通首次／已有 Session 接纳 | C0→L1→L2→L3→L4→L5→L6→L7→L8→L9→L15 | 容量、消息／媒体／Run／序号、暂存 BOUND、提交结果、dispatch、审计和投影；提交后才可调度 |
| 原键 close | L1→L4；若确实影响计数则 C0 在最前 | 已接纳回原结果；否则永久墓碑；不生成用户消息／Run |
| 暂存签发／上传领取／验证收尾／清理禁绑 | L1→L2/L3→L4（需要意图时）→L5 | 票据、fence、验证或禁绑事实；MinIO I/O 在事务外；不倒取 Session 锁 |
| 会话改名 | L1→L2/L3→L7→L15 | 标题／版本及可见投影，同请求键竞争不能覆盖较新标题 |
| FORM 草稿／候选修订 | L1→L2/L3→L7→L8→L11→L15 | 草稿 CAS／新不可变修订与投影；目录只读查询在锁外，不调用 SDK |
| FORM 回答接纳 | L1→L2→L3→L6→L7→L8→L9/L10（已有记录时）→L11→L15 | 原始／规范化回答、正式 USER 消息／输入序号、ACCEPTED 响应、待续接及投影；不受 16 普通等待额度拒绝 |
| 确认接纳 | L1→L2→L3→L7→L8→L9/L10（需要时）→L11→L12→L13→L15 | 外壳响应 CONSUMED、原确认消费及操作待发送同事务；不新增 FORM 消息 |
| 执行领取／显式继续 | C0→L1→L2→L3→L7→L8→L9→L10→后续所需子序列 | 许可、唯一领取、前 checkpoint／fence；提交后才开始对应 SDK／工具阶段 |
| 等待就绪／消费与下一卡／正式收尾 | C0（影响许可时）→L1→L2/L3→L6（涉及学习登记时）→L7→L8→L9→L10→L11→L12/L13→L14→L15 | 核实外部状态后落平台事实；正式员工消息、Run 成功、内容提升／关闭和批次原子提交 |
| 工具发送领取／结果核对 | C0（影响许可时）→L1→L2→L3→L7→L8→L9/L10→L11（关联交互时）→L12→L13→L15 | 发送前持久 SENT、原确认与权限复核；提交后网络发送；结果另事务收尾，UNKNOWN 不重发 |
| 取消／过期／暂停／恢复收尾 | C0（影响计数时）→L1→L2/L3→L7→L8→L9→L10→L11→L12→L13→L15 | 阻止新领取、卡失效、内容封闭／投影及容量一致更新；待核对不伪装 CANCELLED |
| 记忆登记／领取／应用核对 | L1→L2/L3→L6→L7/L8（来源需要时）→L14→L15 | 来源资格／代次／版本／唯一领取；独立单 worker；KV／模型调用在锁外 |
| 初次改密 | L1→身份审计 | credential／securityVersion 更新；Session JDBC 后续单独保存；涉及 Run 控制另起遵循 C0 的事务 |
| SYSTEM_BOOTSTRAP 离线预置 | C0（仅容量行初始化时）→L1→L2→L3→配置／来源审计 | 稳定系统来源及成功收据；只在初始化来源分支允许操作者为空，不建管理员或 HTTP 入口 |

凡影响容量的等待退出、终态、取消、暂停、恢复、领取与接纳均先取 C0 并同事务维护计数。
纯交互状态事务如不改变计数不取 C0；执行到一半发现需要它必须释放并重开事务，不能倒锁。
前台同时最多 2 条受控执行链；普通 ACCEPTED 待执行最多 16，普通新接纳容量满时不生成半条消息／Run。
普通意图／提交预登记不占待执行额度；正式接纳和领取分别在 C0 下入队、将普通等待计数转为执行许可计数，不重复计数或产生负数。
等待用户释放执行许可但保留 Session 活动 Run；已接纳 FORM、已消费确认及恢复事项不占普通新任务额度。
续接优先于普通待执行，不抢占、重领已经开始的调用；重启所有原业务先核对并由用户明确继续。
后台记忆独立 1 worker，每 5 秒扫描到期任务；保留 5 次领取、30 秒翻倍至 15 分钟、±20% 抖动、10 分钟租约及先核对已应用规则。

## 11. 跨存储失败窗口与补偿边界

| 窗口 | 持久证据／回查 | 允许处理；禁止行为 |
| --- | --- | --- |
| MinIO PUT 未开始／未完成 | 原 uploadId、受控对象键、上传 fence | 核对原对象；不自动换键，不接纳未就绪素材 |
| 对象已写但上传 SQL 收尾不明 | 对象版本／字节／摘要＋原暂存记录 | 验证后条件收尾；不把对象存在当正式消息已接纳 |
| 暂存 READY，普通接纳提交不明 | 原 actor＋submissionKey、消息唯一键、暂存绑定、Session／Run／投影 | 返回原结果或待核对；不换键重送、不清理可能已绑定原件 |
| 暂存已禁绑，删除对象失败／结果未知 | BLOCKED／清理 fence、原对象定位 | 只核对／重试该删除；不重新开放绑定，不删除 BOUND 原件 |
| SDK 已领取、尚未证明是否开始 | dispatch／sdkCall／fence／前 checkpoint | 保持占用／待核对；lease 到期或无结果不能视为未开始 |
| SDK 已接纳结果或返回等待事件，状态保存失败 | 本次调用结果／异常、Store 保存记录和独立读回 | 不开放新卡、不标 CONSUMED、不空输入探测；RECONCILING |
| SDK 保存成功，平台收尾失败 | 本次调用键、状态后版本／摘要、匹配结果／pending 变化和平台旧事实 | 有确定证据才幂等补齐原收尾；不能仅凭 pending 消失补成功 |
| 平台已消费确认，发送尚未领取 | 原 CONSUMED 确认、操作待发送、原 dispatch／安全版本 | 重启后明确继续并再鉴权；不重新消费确认，不伪装未确认 |
| 已持久 SENT，进程退出／网络超时 | 原 operation／provider requestId／真实资源核对 | 可能已发出，UNKNOWN 核对；不能因取消／超时自动重发 |
| 无执行 pending 终结写入不明 | 排他／fence、前后状态、匹配终结结果和等待 metadata | 只核对受支持目标；无法证明继续 RECONCILING，不清空历史释放 Session |
| 业务 SQL 已提交，Spring Session JDBC 保存失败 | credential／securityVersion 和本次认证阶段 | 旧版本阻断、按认证受控错误重新登录；不回滚已提交密码或假装登录成功 |
| 业务 SQL／投影已提交，HTTP／SSE 发送失败 | 原业务收据、投影 streamId＋seq | 回查／补读原事实；网络重试不执行模型或再写工具 |
| Memory KV 与 SQL 激活／任务应用错开 | generation／documentRevision、任务标识、KV 版本／摘要 | 沿原两阶段核对；旧代次不复活，不因记忆失败推翻业务成功 |

“补偿”只表示以原事实为依据的条件收尾／隔离，不表示对外部会议业务发送反向操作。
平台 SQL 与 SDK Store、MinIO、Memory KV、Spring Session JDBC 分别有提交边界，即使同一数据库也不冒充统一事务。
每次 SDK 调用独立绑定 actor／release／slot／callKey 的运行实例与 Store Adapter，不共享可变 currentUser。
固定本次初读版本后仅允许 CAS_FAIL；禁用 OVERWRITE、merge 和自动冲突重载。终结前证明旧调用已静止／退出，不能只凭 fence 与在途 Agent 并行改状态。
只有新 Session 首条已接纳 Run 的受控首调用路径允许初始空状态，保存证据关联首 call；旧 Session 状态异常缺失不得重建为空状态。
读取恢复只展示已持久事实；受控协调可安排允许的只读核对，但启动扫描不执行原业务模型／会议写操作。

## 12. 整体评审及实施准入

- 核对每个写路径的请求键／规范摘要、目标归属、锁子序列、影响行数、审计与同事务投影。
- 验证接纳／封闭首次插入竞争、意图只绑定一次、暂存绑定／到期清理竞争及原键永久拒绝迟到接纳。
- 验证 C0 并发容量不超 2／16；同键回查不受满队影响，已接纳回答／确认不被普通额度丢弃。
- 用可计数假 Model／工具验证所有 GET 零执行、POST 候选刷新仅可信目录只读、取消／终结不唤起 SDK。
