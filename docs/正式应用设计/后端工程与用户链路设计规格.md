## 1. 交付范围与已有输入

- 单企业、Web 唯一入口、一个会议室数字员工、单节点低并发；数据库预置一个普通用户账号、显式使用授权和一套完整有效发布配置。
- 当前任务只交付用户链路所需的后端：真实登录／受限首次改密／退出、会话标题搜索与改名、图文接纳、运行、动态表单、独立写确认、事件读取与恢复、后台记忆和私有原件。
- 管理员角色、管理页面、管理 API、开户／重置／改号／授权／发布管理、维护 CLI 均移交后续任务。本次不为满足旧字段或巡检而创建管理员、第二账号或用户 ID=0。
- 一期前端不交付记忆管理、归档列表／操作、版本标签／历史／升级入口；后端既有用户归属、固定发布、归档、记忆与恢复规则保留。本稿不新增这些管理 Web 接口。
- 多渠道、多企业、高可用、正式历史留存／物理销毁策略继续延期；临时上传的 24 小时是待发送原件的准备期限。

权威输入为 [#19 交互生命周期](动态表单与交互请求生命周期设计规格.md)、[#20 投影与恢复](消息渲染运行事件与恢复投影设计规格.md)、[#21 工作台与前端](工作台交互与前端工程设计规格.md)及既有[数据库规格](../数据库设计/README.md)。本轮用户对单账号、系统初始化、Boot 4、时间线表示等明确更新优先于旧稿相应表述，其他已定业务规则直接沿用。

## 4. Module 与 Interface

| Module／建议包 | 对外 Interface 的职责 | 隐藏在实现中的内容 |
| --- | --- | --- |
| `identity` | 当前可信用户、受限改密、退出与用户执行资格 | Security／Session、密码哈希、版本复核、Cookie／CSRF |
| `release` | 装载本人当前能力、校验固定发布快照 | 数据库预置、摘要、Skill／绑定／存储引用、只读缓存 |
| `conversation` | 准备新建意图、接纳／封闭普通提交、列表与改名 | owner、幂等、序号、正式消息、Session／Run 原子写 |
| `media` | 准备／核验／绑定／读取／废弃上传 | MinIO、真实图片验证、24h、对象与 SQL 错开、清理互斥 |
| `interaction` | 表单结构、草稿、回答接纳与允许继续 | form-v1 白名单、CAS、候选、Schema／业务错误 |
| `operation` | 具体提案、确认消费、执行领取与原操作核对 | 本人身份、token、稳定 requestId、MCP 签名／业务回执 |
| `runtime` | 派发／续接／取消原 Run，核验 checkpoint，安全终结 | SDK 调用、fence、版本化 Store、状态适配和执行容量 |
| `projection` | 一致快照、固定分页／详情、有序批次与 SSE | SQL read view、watermark、不可变内容、读取预算与查权 |
| `memory` | 登记成功 Run 学习、领取与应用有效任务 | 既定代次／修订、KV、原生提取／合并、重试与审计 |

Controller 只解析 HTTP、取得可信 actor、调用用例和映射受控结果；不直接拼 SDK 对象或绕过 Module 改表。业务 Module 通过 MyBatis-Plus Mapper 实现短事务；普通 CRUD 可复用通用 Mapper，锁定读取、复合条件更新、序号与幂等使用显式 SQL。

运行实例按每次 SDK 调用绑定不可变的 UserId、员工发布、业务 Session／Run、状态槽／代次、callKey 与 fence。不得在共享单例上设置可变 currentUser／currentSession；可共享经过核验的不可变发布和无会话状态的客户端。前端、SDK、MinIO、会议服务均有真实不同的测试 Adapter，接口围绕用例与不变量设计。

## 5. HTTP 与数据编码

业务接口统一 `/api`，保留 #19／#20 已定路径；完整目录与 DTO 见接口附录。公开资源 ID 不透明，数据库 BIGINT 标识在线上用十进制字符串，客户端不以 JS Number 比较；actor 从登录态取得，不接受请求自选 owner／操作者手机号。

业务写动作携稳定 UUID 请求键；普通提交与 FORM 提交保留各自幂等空间，参数同名不等于同一协议。动作键、交互 requestId、日志 traceId 和会议 provider requestId 各有用途，不能混用。登录／改密／退出走认证会话及 CSRF 协议，不把密码或口令派生摘要塞通用业务幂等账本。

业务语义摘要使用版本化的确定编码：键排序、UTF-8、数值按既定受控规范、数组保序，文本不擅自 trim／Unicode 归一化，缺字段与显式 null／false 分开。摘要包含操作、固定目标和完整内容／有序素材引用；确认语义用确认记录和提案摘要，不包含明文 token。发布包和 #20 固定内容仍采用各自已经确认的摘要算法，不能用通用 JSON 重编码替换固定字节摘要。

Q18 约束 form-v1 的完整字段值；数据库审计／事件时刻仍保存 UTC DATETIME(6)，平台时间戳可保留微秒并按明确 UTC 表示传输。业务显示为上海时间，排序和恢复以序号／游标／版本为准，不从字符串时间猜执行顺序。

## 6. 普通用户登录

- 使用数据库当前手机号记录与密码哈希认证一个普通用户；姓名不参与身份判断。缺账号／凭据／有效号码来源属于预置错误，不从模型、浏览器角色值或默认 UserId 补齐。
- 采用 HttpOnly、Secure、SameSite=Lax、Path=/、无 Domain 的生产登录 Cookie（名称 `__Host-ASSESSION`）；同源 HTTPS。开发回环环境可用独立名称及开发 Cookie 配置，生产与开发配置不可混用。
- CSRF token 与 HttpOnly 登录 Cookie 分开；前端通过认证接口取得 CSRF 值，写动作带请求头。登录、改密和退出后正确更新 token／会话上下文，认证返回不缓存，不把凭据写入 sessionStorage 草稿。
- 单次认证固定 24h，从服务端可信认证成功时刻计算；刷新、SSE、轮询和会话 ID 轮换不续期。Session 空闲配置与 24h 协调，服务端每次受保护 HTTP、每个 SSE 批次及空闲心跳核验原绝对期限和账号／安全版本。
- 同一浏览器标签共享登录会话；普通退出使当前会话失效，其他独立浏览器登录继续有效。退出／到期不等同取消已接纳 Run；后台依据可信 UserId 和安全／授权／手机号版本查权，明确取消另走原 Run。
- 初次改密前只开放当前受限身份、CSRF、改密和退出，不能读取业务会话／图片／订阅或创建 Run。正常改密后建立新安全版本的会话并进入工作台，保留本次原绝对截止时间。

本稿口令初始工程值：DelegatingPasswordEncoder 的 `{bcrypt}` 编码，cost=12；新口令至少 12 个 Unicode 码点、有效 UTF-8 不超过 72 字节，登录和改密采用一致的字节上限预检，不接受 noop／未知 encoder ID。仅存带算法标识的哈希；本机／目标机耗时尚未校准，不能声称 cost 已满足实测预算。

改密在平台 SQL 中更新凭据、安全版本和审计后，再撤销旧 Session／建立新 Session。Spring Session JDBC 有自己的事务，不宣称和业务 SQL 原子：旧版本检查始终阻断旧认证；若新会话建立失败，准确返回密码已改、需重新登录；若 SQL 提交不明则查凭据版本，不盲称未修改或重设密码。不实现管理员重置或找回流程。

## 7. 数据库预置与启动

采用数据附录的 SYSTEM_BOOTSTRAP 来源和稳定来源编号，仅生成可审核的初始化数据契约；本轮不执行。完整预置包括账号／哈希／首次改密标识、当前号码及可信来源、员工及有效授权、发布清单、Skills 正文／资源快照、模型／MCP 绑定引用、图片能力和 MinIO storage_profile。

初始化原件和配置中不嵌凭据；秘密来自独立环境／受控配置引用。初始化记录同来源同摘要可核对，冲突不覆盖既有发布／用户历史；系统收据以非空来源范围维持唯一。应用启动校验并装载，不自动开户、修复历史、重新发布或把空管理员表当错误。

启动必查数据库／实际表结构与修订、单账号、来源、授权和当前发布关联，发布／Skill／绑定摘要及必须的秘密引用／加密 keyId、受控存储配置。基础缺失、损坏或配置自相矛盾时拒绝就绪并给内部可诊断受控码，不猜另一版本。合法的账号停用、授权撤销或发布停用是当前策略状态，不作为结构损坏，不在重启时重新授权／重置；按当前身份与允许动作保留应有的登录限制及本人历史只读语义。

不把模型、会议 MCP 或 MinIO 网络探测成功作为整个应用启动前置。临时网络失败不禁止登录和已有文本历史读取；相关能力返回可理解的不可用，原件读取失败明确显示，不声称图文完整恢复。会议工具仍须目标版本与可信手机号探测通过及逐次签名判权；探测不可用不阻止普通登录。

发布／配置对运行只读。每个 Session 固定原发布，旧会话不因默认指针或配置变化迁移；所有运行和工具边界按当前许可与原版本核验。Key、endpoint、bucket 可通过新受控 profile 更新，但旧 profile 不改指其他原件位置。

## 8. 会话、图片与普通提交

点击新建仍可只在标签页生成 clientIntentId；需要上传或发送准备时，服务器登记 session_intent，不创建业务 Session。意图固定 owner、员工、原默认发布及图片能力，并最多绑定一个正式 Session。首次接纳时原发布须仍为当前有效默认；准备失效返回可读原因并保留草稿，不静默换版或移植暂存。

图片通过后端 multipart 接收，按当前有效能力核验真实 JPEG／PNG、字节、像素及 SHA-256，再写 MinIO 私有对象。对象键由服务器分配且不复用，不用文件名／摘要覆盖历史；SQL 不保存原件、Base64 或临时签名 URL。具体数量／字节／像素限额必须由预置发布与已核验模型能力给出；缺失不虚构默认图像能力，实施验收不能以禁用图片冒充一期图文通过。

media_upload 保存稳定上传 ID／幂等键、owner、原 Session 或意图、固定能力、对象与验证事实、状态和原 expiresAt。24h 从票据创建起算，刷新／重试不续期；GET 只回查，未知上传先核原对象，不能按文件名换键重传。明确 verify／discard 等写动作走条件状态迁移；物理删除排队执行。

ordinary_submission 在接纳前登记冻结语义，UserId + submission_key 唯一。普通 composer 映射为 TEXT 块（文字非空时）加 uploadIds 顺序对应的 MEDIA 块。接纳事务统一写首次 Session（如需）、正式 USER 消息／有序块、media 绑定、Run、调度事实和投影；原始输入一经正式接纳不因后续模型失败删除。无可用容量时不产生半条正式消息；同键成功始终返回原标识及当前状态。

GET 回查没有记录仅表示未发现，不能排除迟到接纳。受鉴权 POST 封闭和原键接纳互斥；接纳先完成返回原结果，封闭先完成永久拒绝该键后续接纳。未登记原键可以形成仅 actor + key 的不可开放墓碑，不虚构曾收到内容；已有登记目标／摘要不可变。封闭确认未接纳后才允许用户明确重试，不自动换新键。

已正式绑定的原件退出临时 TTL 清理；清理先禁止绑定、排除在途接纳和提交不明，再删除 MinIO 对象并记结果。暂存到期不等于立即物理删除；清理失败可重试但不能恢复绑定资格。历史图片由 `/api` 鉴权代理按稳定素材 ID 读取，每次复核本人归属。

本人普通会话列表支持全范围标题搜索、稳定分页与改名（200 字符存储上限），不只搜索当前页。首次标题由正文确定性生成，纯图片用默认名，不为命名调用模型；改名不改路由／归属。当前没有归档、版本历史或升级操作接口。

## 9. 前台执行与 SDK 状态

runtime_capacity 的短事务控制前台最多 2 个执行许可及最多 16 条普通新任务等待，许可状态关联 runtime_dispatch；业务 Run 活动占用与执行许可分开。所有计数增减先锁容量控制行 C0，再按全局主干；不能在锁住 Session／Run 后倒取 C0，不能跨模型／网络持锁。

普通任务持久等待，初态仍 ACCEPTED；有许可并完成条件领取才开始执行。待用户输入不占执行许可，但不释放原 Session；已有交互续接优先，已接纳回答／已消费确认不受普通等待 16 条限制，不抢占或重复当前调用。容量不足的首次普通输入返回确定未接纳或待核对事实，保留草稿，不用内存队列丢任务。

执行许可与业务占用分别收敛：已证明本地调用及 writer 静止时，即使 checkpoint 尚待核对，也可在 C0 事务释放该执行许可，但原 Run／Session 仍 RECONCILING；无法证明执行停止则不能只因租约到期释放。重启前须有单实例旧进程终止事实，不能用新 epoch 本身证明旧 writer 已停止。

每次执行登记独立 sdkCallKey、类型、可信归属、slot／generation、fence、状态前版本及允许的保存策略，再调用 SDK。运行实例和 Store Adapter 绑定该调用，不共享可变身份。状态 Store 采用锁定 JDBC 版本化 MySQL 接口；每调用冻结初读版本，只允许 CAS_FAIL，不启用 OVERWRITE、合并或冲突后的自动重载执行。

首次新 Session 只在首条已接纳 Run 的受控路径允许建立初始空状态并记录证明；存量 Session 状态缺失是异常，GET／恢复不能创建空状态冒充原状态。框架 schema 来自锁定源码核验，平台不凭旧文档硬编码另一 Store 的物理列。

Store 接入层关联该调用的保存前后版本、状态摘要与独立读回。等待事件、ExternalExecutionResultEvent、pending 消失或单次版本增加均不能单独作为就绪／消费证明；条件齐备后才让 FORM WAITING／CONSUMED 对用户生效。SDK Store 与平台 SQL 独立提交，错开或证据丢失进入 RECONCILING，不猜完成。

正常最终回复先得到完整候选并保存必要过程，再证明 SDK 状态可恢复，最后一个平台事务写正式员工消息、Run 成功、内容关闭／提升、替换关联及投影。每 Run 至多一条正式员工回复；重复收尾回原事实，关闭后迟到 delta 被调用 fence 和内容状态拒绝。

## 10. 表单、时间与取消

模型结构必须先通过 form-v1 白名单和资源预算，再交 networknt draft-07 校验完整回答和业务条件。库不能绕过候选归属、人员有效性和会议可用性；外部／本地任意 Schema 引用均拒绝，保持 format 断言、无隐式代填／转换、收集全部已知字段错误。

完整时间表示：日期如 `2026-10-25`；时间如 `09:30:00+08:00`；日期时间如 `2026-10-25T09:30:00+08:00`。固定宽度、大写 T、秒精度，仅 +08:00；不接受小数秒、闰秒、Z／其他偏移、宽松分隔或尾随内容。控件到分钟时显式补 00 秒，不静默截断已提供的小数；不完整草稿规则保留。

草稿与提交均按 revision／snapshotHash／draftRevision 条件处理。FORM 接纳生成原 Run 的正式 USER 回答，分配输入序号，不创建另一个 Run，不改变最初 input_message_id／版本／记忆快照，不把正式回答重复作为普通消息喂给 SDK。

回答 ACCEPTED、SDK CLAIMED、持久 CONSUMED 和工具成功分开；消费证明与下一张卡就绪或最终收尾按既定事务提交。接纳后没有许可只等待，不丢弃回答；已领取但执行／保存不明不因租约到期重送。

取消先使当前卡不可响应并阻止新领取；运行中仅协作中断，等待态不能靠旧句柄或空输入清理。专用状态适配器必须先证明旧调用已静止／退出和归属一致，再以版本 CAS 保留 ToolUse／历史、追加匹配终结结果、清对应等待关联，独立读回。fence 不授权与在途 Agent 并行改状态。

首版适配只覆盖核验过的固定平台输入工具唯一 pending；其他 ASK／混合批次、多 pending、损坏或未知外部写结果不能自动修复。先经隔离计数模型／工具证明副作用增量为零及重启／竞争正确后启用；未证明或失败继续 RECONCILING，原 Session 不接纳新 Run。

## 11. 具体操作确认与凭据恢复

表单收集不是预约授权。固定提案绑定具体操作、目标、规范参数、可信用户及安全／授权／手机号版本；只有本人有效登录下的明确确认可消费。原期限 10 分钟，一次消费与待发送操作同事务；消费不证明已发送或会议成功。

本稿恢复格式固定为：随机原 token 32 字节（SecureRandom），对外 Base64URL 无 padding 为 43 字符；既有 SHA-256 对解码后的原始 32 字节计算。AES-256-GCM 使用独立 32 字节 key、12 字节 nonce、128 位 tag；密文含 tag 共 48 字节，格式版本 1，keyId 为最多 64 字符的受控 ASCII 标识。

认证附加数据固定为以下有序 JSON 数组的无空白 UTF-8 字节：`[1,keyId,interactionPublicId,operationId,ownerUserId,operationDigest,expiresAt,securityVersion,phoneRevision]`。除首项整数 1 外均为字符串；数字 ID／版本用无前导零十进制，UUID 用小写标准形式，摘要用小写 64 位 hex，expiresAt 用固定 6 位小数的 UTC ISO 时间，keyId 限 `[A-Za-z0-9._-]{1,64}`。签发前已知公共交互 ID；原 token 摘要、加密副本、原期限及交互绑定同事务保存后才允许确认，不依赖 JSON 对象键遍历顺序。

nonce 固定为每 keyId 的 4 字节前缀＋8 字节单调计数。加密前先在独立短事务中锁定 crypto_nonce_cursor、递增并明确提交预留；该事务不持领域锁，也不与确认事务嵌套。只有确认预留已提交才加密；预留失败／提交不明时不使用该候选，确认事务回滚或进程崩溃仅烧掉号码，永不回收重用。(keyId,nonce) 唯一键只是最后校验，不以“先重复加密、再捕获入库冲突”保证唯一；异常重复阻断新签发并核对。

每个 keyId 最多预留 2^32−1 次，达到阈值拒绝新预留并要求新 keyId／密钥，不允许整数环回。

普通重启沿已提交计数继续；计数丢失、回退或从备份恢复后，必须先启用全新 keyId／密钥和新的分配行，旧 keyId 只解密，禁止恢复旧计数后继续旧密钥加密。受控恢复使用独立配置的恢复代次与新 keyId 作为开放签发的门槛；无法证明连续性时保持签发不可用，不能把随机重置前缀当作已证明安全。

本人通过专用 POST，在当前登录、CSRF、归属、提案、PENDING／期限／版本检查后解密并复核摘要，返回相同 token，响应不缓存；GET 快照／投影不含秘密。

Keyring 独立秘密配置，不与密文同库保存、不复用 MCP HMAC 秘密。按原 keyId 保留有效确认所需密钥并参与联合恢复；原 key 缺失、标签／摘要不符或旧行只有摘要时不可恢复，不重签替代，按原失效／安全终结收敛。token 明文／密文不进入普通日志、审计正文、URL、聊天或草稿。

## 12. 工具调用与真实会议结果

会议 Adapter 从可信 UserId 查当前手机号，不能用模型、对话文本或请求参数选择操作者。每个 MCP HTTP 请求按固定目标和凭据引用生成新时间戳签名；平台授权、会议身份探测、上游权限与本次确认分别校验。原件／人员候选和工具目标均受控。

发送前再次核验原版本、当前用户和工具许可；发送领取先记持久状态和稳定 provider requestId。已发送或可能发送的超时／取消转 UNKNOWN 并核对原请求，不能换号重发。具体取消会议必须走独立的用户确认和上游权限，不把取消 Run 当取消会议。

工具成功回执与 Run 成功分开；模型后续失败不覆盖真实会议成功。SDK 同步可另记进度，不得将未同步解释为尚未确认或再次消费。源契约没有的核对能力不虚构，无法自动核验时保留明确未知。

## 13. 投影与读取

所有可见业务写入、持久过程、Session 分号及不可变批次同一平台事务提交，提交后通知只唤醒补读。固定版本内容的实际字节、摘要和关联需可重建，不能只保留一份可变 display_text。

快照使用单一 REPEATABLE READ 只读 read view，同视图取得业务对象和水位；随后补读严格大于水位的批次。分页／详情绑定本人、流、固定上界／版本；SSE 仅读持久日志，所有 GET 的业务模型、SDK 和会议工具执行数为零。候选刷新 POST 的受控外部目录只读查询不混入 GET。

## 14. 后台与恢复

记忆用独立 1 worker、5s 扫描到期任务；只学既定成功来源，有效 generation／authorizationVersion、条件领取及应用后核对。默认最大领取 5 次、30s 翻倍至 15min、±20% 抖动、租约 10min 沿用原规格；不按扫描频率重做全部任务，不给失败任务新增人工重试接口。

前台 2 和后台记忆 1 分别计数；平台模型服务／数据库总量仍需目标环境校准。取消／过期／只读核对使用独立轻量协调，不被记忆模型计算占住；协调扫描只安排允许的读回和状态收敛，不自动启动业务推理。

启动先建立本实例 epoch，校对容量和遗留 dispatch／call／pending／操作事实。原业务不因队列、租约、GET、状态缺失或恢复自动执行；确证未领取的普通任务／已接纳回答由本人明确继续，已领取／保存不明保持 RECONCILING。已发送工具继续原操作只读核对。已授权的记忆持久任务按自身既定去重恢复，不等同重放业务 Run。

SQL／MinIO、SQL／SDK、SQL／Session JDBC、确认摘要／加密副本各有失败窗口；每个窗口的可读事实、回查键、可安全完成动作及禁止动作见接口附录。联合恢复还须覆盖历史 storage_profile 和独立密钥材料；恢复目标沿用最多丢失 15 分钟、4 小时恢复服务，实际演练由 #23 验收。
