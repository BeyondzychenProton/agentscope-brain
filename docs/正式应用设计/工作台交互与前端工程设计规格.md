## 1. 范围与权威输入

一期为单企业、Web 唯一入口、一个会议室数字员工、单节点低并发。沿用已确认的身份、员工授权、固定发布版本、Session／Run、素材、操作确认、状态与恢复规则。界面消费服务端事实，不建立另一套执行授权或成功判断。

- 视觉以[指定参照](../../reference/正式Web应用/海卓大脑原型-v1.0.2-20261021.html)为基线，保留配色、留白、侧栏会话、主聊天和底部输入；参照的角色切换、管理员、共享等演示功能不自动纳入范围。
- 完整验收面向 PC Chrome／Edge 稳定版，视口 1280×720、1366×768、1920×1080；手机／平板完整适配后置。
- 页面覆盖普通用户登录、首次／重置后的受限改密、工作台；无管理员 Web 登录、管理页面或管理 API。
- 用户明确排除一期“我的记忆”前端页面、入口及查看／编辑／清空交互。既有后台记忆、学习、隔离和恢复模型保留，不自动新增记忆管理 API 承诺。
- [#19 交互生命周期](动态表单与交互请求生命周期设计规格.md)和 [#20 消息／事件／恢复投影](消息渲染运行事件与恢复投影设计规格.md)是既定契约，实施仍未完成不构成重新决议理由。

## 2. 页面、导航与会话

### 2.1 登录与页面进入

普通用户通过手机号和密码登录，无角色选择；首次或重置后只进入受限改密，成功后进入工作台。路由可采用 `/login`、`/password/initial`、`/chat/new`、`/chat/:sessionId`；这些是界面组织建议，不能替代服务端鉴权。认证凭据的具体机制由 #22 定义，不将口令或确认凭据存入聊天草稿。

平台登录失效时停止读取及订阅、清理当前标签应用范围的草稿、回登录；其他标签在获知失效后各自清理。账号有效但员工授权被撤销时，本人历史仍可按既有规则只读，新 Run 和写动作不可用。账号停用不得继续查看。会议 MCP 401／工具 FORBIDDEN 与平台登录失效分开提示。

### 2.2 会话列表与新建

侧栏显示最近会话，按本人普通会话列表的标题搜索，搜索范围包含尚未在浏览器加载的条目；正文搜索不在一期。已归档数据的筛选、管理与恢复不在一期用户前端提供。分页、查询参数及列表更新由 #22 落实，不用仅过滤当前页冒充全量搜索。

普通新 Session 在首条消息接纳事务中创建。点击新建只显示空白编辑页，以当前标签的本地新建意图定位草稿；正式接纳后关联返回的 Session／消息／Run。未接纳前不在正式列表产生空 Session。来源：[普通输入接纳 §4.1](../数据库设计/会话运行与消息/一期会话运行消息数据库设计草案.md#41-接纳输入与重试)。

首条文字确定性生成短标题，纯图片使用可读默认名；不为命名另调模型。可手工改名，服务端遵守既有 200 字符存储边界，前端视觉截断不改存储原值。标题不是身份、路由或发布版本键。

会话更多菜单提供改名；一期不提供归档／恢复操作及已归档入口。后台归档的既有含义仍为列表整理、不取消 Run、不删除消息／图片，不因为撤下前端功能而改写数据或迁移既有记录。切换、关闭页面只改变展示订阅，不取消执行。

### 2.3 一期不展示版本元素

用户页面不显示 V1／V2 等发布或会话版本标签，不交付版本历史、成功版本链、升级提示、“在新版继续”及失败／放弃尝试的查看入口。普通历史消息和当前会话的任务状态仍按原规则展示。

已固定发布版本、版本链、状态隔离及[业务升级契约](../数据库设计/会话运行与消息/业务会话运行消息与跨渠道续传设计规格.md#43-数字员工定义升级)保留为后端既有设计；本次仅移出一期前端交付，不能自动升级旧会话、改写其归属或放松恢复检查。当前会话不可运行时按服务端允许动作和可理解原因提示，不另暴露一套版本管理流程。

## 3. 工作台结构与运行说明

主体保持侧栏、头部、消息流及底部交互区。头部显示用户可理解的任务状态，不显示“连接正常”等常驻连接标记。连接与业务状态在内部保持独立；断线等实际异常通过顶部状态条说明，不能因此认定任务已失败或重发。字段问题就地显示，任务／工具失败留在对应消息和过程，避免反复阻断弹窗。

执行过程只在聊天流内折叠展示，不开发右侧详情抽屉。阶段说明、必要参数和结果摘要按需展开；更新时保留用户的展开状态。“动态思考过程”已明确为实时执行说明，例如正在理解预约需求、正在查询会议室；不展示原始 Thinking，不用计时器伪造阶段、百分比或成功。

阶段、工具操作和回执来自已持久投影。实际工具成功而后续模型答复失败时分别显示成功回执及 Run 失败；未知结果不解释为未执行。历史消息／旧交互只读，查看、展开与恢复读取均不触发执行。

## 4. 底部区域与动态表单

### 4.1 区域切换与布局

| 当前事实 | 底部呈现 | 普通输入与动作 |
| --- | --- | --- |
| 可接受普通消息 | 文字／图片 composer | 依服务端能力及允许动作发送 |
| 正在处理／请求未就绪 | 真实处理说明，可保留普通文字草稿 | 不因卡片已出现而开放提交 |
| 当前 FORM 就绪 | 表单暂时代替普通 composer | 保留原聊天草稿，可查看／修改草稿但不发送普通消息 |
| 固定操作提案等待确认 | 独立确认卡，目标和参数不可原地修改 | 表单回答不是预约授权；须再次明确确认 |
| 接纳／消费／外部写结果待核对 | 只读状态及服务端明确允许的核对动作 | 不自动重发或生成新键，不假装普通输入已恢复可发送 |
| 任务已安全结束 | 恢复普通 composer 与草稿 | 回执／交互保留为只读历史 |
| 当前内容／权限只读 | 明确只读提示 | 不提供有效执行按钮 |

表单继续位于底部，整个容器最多占当前聊天可用高度的一半；标题和动作区固定，字段区按服务端分组内部滚动，最后一次提交整份回答。小视口仍须能看到固定按钮，不用页面级横向滚动或将表单移到侧边。

### 4.2 受控表单 renderer

采用项目有限 `form-v1` 组件映射及 Ajv draft-07 校验；Element Plus 提供基础输入／选择／日期等控件，项目负责分组、人员稳定引用、绑定、字段错误及只读展示。不采用 JSON Forms Vue，不加入通用设计器、任意 HTML／脚本或未知组件。

字段类型、32 字段／8 分组等边界及不可变修订遵守 #19；上限包含全部字段。未填写与明确 false 分开，不为了显示控件而默认代答。前端预检不替代服务端完整校验、候选有效性、权限和会议可用性检查。

上海业务时间始终可见，浏览器本地时区不改变业务含义。锁版后的 ajv-formats time／date-time 均要求时区。2026-10-25 #22 Q18 已进一步确认：完整日期如 `2026-10-25`，时间如 `09:30:00+08:00`，日期时间如 `2026-10-25T09:30:00+08:00`；时间类固定上海 `+08:00` 和秒精度，不接纳小数秒、其他偏移／Z、闰秒或宽松写法，不静默截断。前后端必须提供共享格式／时间映射及错误路径 fixture，保留 Ajv 格式断言并补充相同的受控表示检查；草稿不完整规则不变。服务端校验采用 networknt 3.0.6／Jackson 3.1.7，具体实施仍由 #22／#23 承接，尚未运行一致性验收。

校验失败保留全部填写，显示所有已知错误，定位首个错误。表单就绪或阶段更新不抢焦点；用户正在输入时，应保留草稿与当前输入体验，通过明确提示让用户进入就绪表单。

### 4.3 草稿与并发比较

FORM 草稿由服务端保存，不改成普通文字的 sessionStorage 策略。保存只检查允许字段、类型和边界，可不完整，不调用模型或写工具；成功／失败／有未保存输入如实显示。

保存和提交均检查 `revision + draftRevision`。发现冲突时保留本地填写，用比较弹窗按可读字段显示“我的填写／服务端已保存”，用户选择采用服务端草稿或把兼容本地值重新应用到最新草稿。重新应用仍条件保存，再冲突则再比较；不是强行覆盖，也不自动提交回答。

新修订说明结构／候选变化、可迁移和不能迁移字段；旧值仍可复制，已接纳回答永不重新开放。回答已接纳、SDK 消费、业务处理和下一交互是不同事实，界面分别显示。

### 4.4 固定提案与过期

确认卡固定展示目标、参数及可理解摘要，不增加面向用户的版本标签；版本及摘要绑定仍由后端原确认契约检查。当前确认只授权该次操作，十分钟期限、一次消费、失效及执行前再鉴权遵守原契约。刷新重取凭据不能重置原期限或已消费状态；确认消费不能显示成预约成功。

到期禁止确认，显示已过期／正在结束旧任务；核实安全终结后恢复普通输入，旧提案仍只读保留。不自动生成新提案、续期或调用模型。取消按钮走统一取消任务入口，不合成表单回答或同意；结果未知时继续核对原操作，不把本地取消当作会议已撤销。

## 5. 文字、图片与发送恢复

### 5.1 普通文字草稿与键盘

按可信登录用户与业务 Session，在当前标签页用 sessionStorage 尽力保留普通文字；空白新会话按本地新建意图定位。恢复前核验当前登录与资源归属；关闭标签后不承诺可靠恢复，不扩展为跨设备／跨标签同步。退出、失效、身份切换按应用前缀清理，不能用全站 clear 或声称一个标签已清空所有标签。

存储异常保留当前可编辑输入，明确说明刷新恢复不可用，不虚报已保存。服务端确认接纳后才清理对应草稿；结果未知保留原内容。

普通输入 Enter 发送、Shift+Enter 换行；中文输入法 composition 及候选确认按键不发送。发送仍须满足当前允许动作、图片就绪及无待核对提交等条件。动态表单字段内 Enter 不直接提交整表或确认预约；明确按钮保留标准键盘激活。弹窗关闭只关闭展示、保留输入，不取消任务。Tab 顺序、可见焦点、标签及关闭后回到触发点需验证。

### 5.2 图片准备与主动发送

支持文件选择、粘贴、拖入；首版前端白名单 JPEG／PNG。发送前可看缩略图、准备状态并移除。数量、字节和像素上限来自当前员工发布版本的有效能力；前端展示及预检、服务端最终核验。没有有效图片能力时明确说明，不静默略图。

全部必需素材上传且验证就绪后，仍由用户点击发送，统一接纳文字和图片；上传结束不自动创建 Run。任一必需素材失败时保留文字与准备状态，针对失败项处理，不自动转纯文字。上传票据与对象键受服务端控制；待发暂存引用不冒充正式 message_media。

### 5.3 刷新与提交结果不明

| 图片／提交状态 | 恢复与操作 |
| --- | --- |
| 只有本地 File、尚无可核验上传引用 | 同标签刷新后提示重选；不把文件名或 blob URL 当原件 |
| 已上传、尚未发送 | 当前用户／标签页／原目标或新建意图保留引用；重新核验归属、有效性和原件就绪，失效项重选 |
| 上传结果未知 | 先查原上传，不自动换对象键重传或删除 |
| 用户点击发送、接纳结果未知 | 冻结内容及稳定 submission_key，保留待核对卡／可读内容，先查询原接纳事实 |
| 原提交已接纳 | 关联原 Session／消息／Run，清理对应草稿，不再新增同一次消息 |
| 已确定未接纳 | 允许用户明确重试；不能用瞬时“查无记录”代替排除在途接纳 |
| 本地恢复记录丢失／身份失效 | 准确说明恢复边界；不凭本地缓存恢复访问权或执行 |

普通草稿不保存原图、base64 或临时签名／blob URL；可保留受控引用和必要定位信息。读取原件重新鉴权，签名 URL 过期按原件规则重取，不能因此认定原图丢失。去重沿用 UserId + submission_key，不把 #19 交互 requestKey 直接移植成普通消息字段。

## 6. 内容渲染与阅读体验

采用 markdown-it 15.0.3 + DOMPurify 3.4.17，普通用户输入仍为纯文本。markdown-v1 覆盖列表、表格、代码块和 http／https 链接；显式关闭原始 HTML、Markdown 图片加载及任意执行组件，集中限定标签、属性和规范化后的 URL 协议。默认库配置宽于项目协议白名单，不能直接当作平台规则。

净化后不再交给会重新解释不可信 HTML 的插件。图片用独立可信素材组件；代码只展示和复制，不执行／预览，复制失败反馈真实结果。净化不可用／抛错时回退纯文本。未知内容或不兼容协议按 #20 占位／只读停止，不降级执行未知载荷。

先整批应用投影，再按 contentId／contentVersion 解析累计正文并净化，不能逐网络片段转 HTML 拼接；未闭合结构可先按文字展示。原累计文字是可重建展示输入，净化 HTML 不成为业务权威。

用户接近消息底部才跟随新输出；上翻阅读保持位置并提示“有新内容”，由用户点击定位。可取初始 72 CSS px 接近底部阈值，在正式 PC 浏览器测试后调整并记录。阶段更新、表单就绪不抢焦点，不重建整个页面导致输入／展开状态消失；稳定内容节点及控件应保留。任何展示节流不跳过业务批次或提前推进应用 cursor。

## 7. 工程基线与责任划分

Vue 3 + TypeScript + Vite + Vue Router + Pinia；Element Plus 基础控件；有限 form-v1 renderer + Ajv；markdown-it + DOMPurify。精确初始版本见下表及[官方资料核验](../调研/正式Web应用/聊天Markdown与前端锁版补充核验.md)。

| 范围 | 精确初始基线 |
| --- | --- |
| 运行／包管理 | Node 24.22.1，npm 11.19.1 |
| 界面与状态 | Vue 3.5.44，Vue Router 4.6.3，Pinia 3.0.4，Element Plus 2.14.7 |
| 构建与类型 | Vite 8.3.5，@vitejs/plugin-vue 6.0.10，TypeScript 6.0.3，vue-tsc 3.3.13，@types/node 24.10.1 |

版本已作为设计初始基线采用，目前仅核验直接 peer／engines 声明范围。正式工程创建时写精确直接依赖、求解完整传递依赖并保存锁文件，完成类型／构建／DOM 和浏览器验证；若发现静态声明未覆盖的冲突，在已选技术路线内修正并记录依据。此选择不代表已安装，不自动修改本机运行时，不授权 Git 提交／推送或部署。

| 层次 | 责任与边界 |

| features | auth／chat／interaction／media 用例；区分提交、保存、取消、继续与只读查询 |
| stores | Pinia 存展示投影及按会话定位的 UI 状态；不猜测业务成功 |
| projection／reducer | 契约／版本检查、规范化对象、整批原子应用、应用游标；纯逻辑为主，不含网络或工具执行 |
| transport | HTTP／SSE 编解码、重连、补读和只读轮询；恢复连接不重启任务 |
| rendering | Markdown 解析／净化、链接规则及独立可信图片／表单／回执组件 |

页面组合用例，用例协调 transport／store，数据经 projection／reducer 后渲染。正式 SDK、工具、存储和可信身份均在后端；前端不直接订阅执行 SDK 源流。

## 8. 向 #22 的接口交接

以下是已确认前端所需能力，具体接口名、状态码、字段和持久接缝由 #22 收敛，不能称为现有 API：

1. 普通登录／受限改密／退出和当前用户／员工可用能力；有效图片限制、固定发布版本与服务端允许动作。
2. 本人普通会话列表的全范围标题搜索／分页及改名；不因本前端交付自动要求归档／恢复、版本历史或升级操作 Web API。既有后端归档／版本规则按原设计维护。
3. 普通消息新建意图、上传票据／暂存引用、上传状态／有效期／恢复核验、图文统一接纳及同 submission_key 的接纳回查；明确排除在途接纳后才可判未接纳，清理与接纳互斥。
4. #19 既定的草稿、CAS 冲突、新修订、FORM 接纳、具体确认凭据刷新／原期限、取消与明确继续；前后端共享时间／格式及错误路径 fixture。
5. #20 既定快照、水位、批次／分页／固定版本详情、SSE／补读／只读轮询、重启与权限变化投影；HTTP 动作和读取链路分离。内部固定版本、revision／contentVersion 等仍用于一致性校验，不转成版本标签或管理入口。

前端展示文字不能成为服务端状态枚举。按钮以当前权威允许动作及版本为准；所有写动作在服务端再次鉴权，历史查看或恢复引用不恢复执行权。

## 9. 验证与证据层级

| 层级 | 必须观察的行为 | 证据边界 |
| --- | --- | --- |
| 纯逻辑 | 重复／缺口／乱序／坏引用、整批失败不推进 cursor、正式回复替换、Schema／时间映射及错误分类 | 固定 fixture，验证用户可观察行为，不只镜像实现 |
| 组件与浏览器 | 净化实际 DOM／协议过滤、代码复制成败、图片链路、32 字段长表单／固定动作区、IME／焦点／阅读位置、草稿及冲突 | 类型检查与构建单独通过；DOM 模拟器不替代目标浏览器 |
| 真实后端集成 | 身份／授权、上传就绪、同键接纳、确认消费、断线／重启、SDK 持久状态、UNKNOWN 不重发 | #22 实施；客户端演示或 SQL 单表验证不覆盖 |
| 产品闭环 | Chrome／Edge PC 矩阵、真实图文对话、FORM、具体预约／取消、会议系统结果、重启读取及隔离 | #23 编排实施切片与真实证据，模型文本／HTTP 200 不单独等于会议成功 |

统一原型只用于检查界面协同，使用合成身份、阶段、版本、上传引用与预约结果。它不安装已选框架或 Markdown 库；渲染样例为固定安全 HTML，不能记为 parser／净化集成。原型可在当前标签用专用键保存模拟快照与文字，方便评审刷新；这不是服务端 FORM 持久化或真实身份隔离证明。体验顺序、实际检查与未验证边界见[统一原型评审记录](工作台统一原型评审记录.md)。
