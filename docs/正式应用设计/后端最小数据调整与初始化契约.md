## 2. 通用字段、类型与落库规约

所有新表含 id BIGINT UNSIGNED 自增主键、gmt_create／gmt_modified DATETIME(6) 及中文表列注释。
关联 ID 同型；公开 UUID 使用 BINARY(16) 保存并由统一编码器输出，不能作为 principal 或授权凭据。
状态／版本名使用有界 ASCII 字符串；摘要使用 BINARY(32)；正版本使用 BIGINT UNSIGNED。
数据库时间用 UTC；Q18 的 +08:00 秒格式用于完整业务日期／时间值，不将数据库时间整体改成字符串。
JSON 只允许约定顶层和容量；Schema、归属、跨行一致性仍须服务校验及巡检，不由 JSON 列自动保证。
不建物理外键、级联、触发器或存储过程；引用完整性由短事务和巡检维护。
新增行版本 row_version 从 1 开始；条件更新须核对影响行数，不能以最后写入覆盖 CAS 冲突。
business_run.row_version 是 expectedRunVersion 的真实 CAS 依据；投影 viewRevision 不代替业务 Run 行版本。
不可变快照的正文／摘要／归属不允许原地更新；可变头指针、草稿、状态与不可变内容分开。
普通日志、投影和审计不保存口令、token 明文／密文、密钥、原始 SDK 状态或完整敏感工具报文。

## 4. C0：runtime_capacity

单例字段：singleton_key＝1、foreground_limit＝2、normal_waiting_limit＝16、occupied_count、normal_waiting_count、boot_epoch、row_version。
CHECK 保证单例常量、限额为正、计数非负且不超相应限额；PRIMARY／单例唯一限制最多一行。限额当前预置为 2／16，是受控应用配置初始值，不把数字永久写死在 CHECK；变更仍需校验现有计数，不自动清零。
部署准备保证该控制行存在；缺失或计数无法核验时拒绝新执行，不凭空以零覆盖已有工作。
计数依据是有效 dispatch 归属／许可状态，不是线程池大小、内存队列长度或所有非终态 Run 数。
等待用户、已接纳回答、已消费确认与 RECONCILING 不自动占用“16 条普通新任务”等待额度。
前台许可控制最多 2 条受控业务执行链；后台记忆另有单 worker，不宣传为全系统模型调用总并发＝2。
所有取得／释放许可、普通等待计数增减、暂停／取消及恢复计数的事务先锁 C0，再按业务主干加锁。
事务内同时修改 dispatch 状态／计数；提交结果不明回查原调度事实，不能盲目再加减。
重启在 C0 下核对计数、建立新 boot_epoch 并暂停旧调度；旧业务任务仍按明确继续／核对门槛处理。
新 epoch 只提供拒绝陈旧领取的条件，不能独立证明旧 SDK writer 已停止；状态写回 fence 另须验证。
C0 只持有短 SQL 事务；不在其锁内等模型、MCP、上传、框架 KV、网络或用户。

## 5. runtime_dispatch：持久调度而非内存排队

| 字段组 | 最小字段／约束 |
| --- | --- |
| 身份 | dispatch_key UUID、user_id、employee_id、session_id、run_id、employee_release_id。 |
| 目的 | dispatch_kind：ORDINARY／CONTINUATION；work_kind 区分原始运行、FORM 续接、明确继续、确认后工具模块交接。 |
| 来源 | 稳定 source_kind／source_id／source_version、request_key／request_sha256；可空 response_id、operation_id。 |
| 容量归属 | status、permit_state、boot_epoch、claim_fence、claim_token、claimed_at、finished_at、row_version。 |
| 核对 | sdk_call_id 可空、reason_code、原领取证据及结果引用；不保存 SDK 对象或 token。 |

调度状态固定为 WAITING／CLAIMED／COMPLETED／CANCELLED／RECONCILING／PAUSED；它们不进入 business_run.status。
permit_state 明确 NONE／HELD／RELEASED；仅 HELD 计入 C0.occupied_count，释放须幂等且有原领取凭据。
ORDINARY＋WAITING 且已纳入普通等待归属的行计入 normal_waiting_count；其他行不得通过空值绕过计数。
唯一键覆盖 dispatch_key、稳定逻辑来源＋动作；同一来源重试返回同一调度事实，不生成第二次执行。
活动调度条件唯一键限定同一 Session 至多一个实际持有执行许可的调度；与活动 Run 唯一键共同检查。
索引覆盖 status／优先级／创建顺序、Session／Run、boot_epoch／许可状态及待核对扫描。
已有续接优先，优先级由服务端类型确定；客户端不能声明“高优先级”，也不抢占已领取调用。
普通接纳须先在 C0 下确认即时许可或 16 条等待容量，再将消息／Run／dispatch／提交结果／投影一起提交。
额度耗尽不得留下半条正式消息／Run；原提交控制记录按准确事实保留，草稿不清空。
同键已接纳回查先识别原事实，不因当前容量耗尽而改答“未保存”。
FORM 接纳后即使暂无许可也保留 ACCEPTED 响应；不能删除回答或要求重新提交来获得调度。
确认后交接仍调用工具模块的原领取／鉴权入口，不将已消费确认转成 FORM 再领取。
领取须在 C0 与领域锁内复核权限、原状态、来源及 fence；数据库领取不是调用已成功的证明。
过期租约、线程退出或重启不能使 CLAIMED 自动回 WAITING 并重放；先核对，不明保留占用／待核对。
业务占用与前台许可分开：本地调用及 writer 已证明静止时，可在 C0 事务幂等释放 HELD，原 Run／Session 的 RECONCILING 仍保留；无法证明停止不能只凭租约释放。新 boot_epoch 不能单独作为旧进程终止证明。
取消普通待执行项、用户等待释放许可、恢复读取与显式继续均按 C0 主干更新，不按页面断线释放业务事实。

## 6. runtime_sdk_call：可信调用与 checkpoint 证据

| 字段组 | 最小字段／含义 |
| --- | --- |
| 唯一调用 | sdk_call_key UUID 唯一、run_id、session_id、dispatch_id、call_no；(run_id,call_no) 唯一。 |
| 固定归属 | user_id、employee_id、employee_release_id、state_session_key、state_generation、sdk_version。 |
| 排他凭据 | boot_epoch、claim_fence、执行者标识、started_at、ended_at；状态槽必须匹配可信 Session。 |
| 输入来源 | call_kind、输入摘要、可空 response_id、原 pending ID／名称／冻结 ToolUse 摘要。 |
| 执行状态 | PREPARED／STARTED／RETURNED／VERIFIED／RECONCILING／FAILED_BEFORE_START；完整结果／异常类别。 |
| 状态前证据 | before_exists、before_store_version、before_state_sha256、受控只读证据引用。 |
| 状态后证据 | save_status、saved_store_version、saved_state_sha256、实际保存归属／收据引用。 |
| 独立读回 | readback_status、readback_store_version／摘要、verified_at、证据格式版本、受控结构证明。 |
| 首次空状态 | 可空 bootstrap_state_proof JSON，限定新 Session 首个已接纳 Run 的受控初始空状态证明。 |

PREPARED 不表示已经调用；STARTED 表示可能已执行，不能因没有最终回调而重新执行同一输入。
调用键由服务端生成，不能用 SDK replyId／事件 ID／句柄 runId 替代平台 RunId 或调用键。
state_generation 是平台状态槽／执行代次的受控映射，不使用 memory_generation 冒充，也不假设框架自动提供。
版本字段在未取得可靠能力前可空，不能把框架 UNVERSIONED／冲突返回值伪装成正版本。
每次调用独立构建绑定 Actor／Release／Slot／sdk_call_key 的 Agent 与 Store Adapter；冻结本次初读版本。
该调用仅允许 CAS_FAIL 保存；禁止 OVERWRITE、merge，以及冲突后自动重载状态并继续执行。
首次空状态仅允许新 Session 首条已接纳 Run 的受控路径，并将归属、初始不存在与初始化写入依据存为 bootstrap_state_proof。
旧 Session 缺失状态不能走首次初始化入口；缺失、冲突或初始归属无法证明时保留 RECONCILING。
保存成功必须关联到本调用的真实 Store 写入；独立读回不得走缺失时自动造空状态或命中进程缓存的入口。
VERIFIED 还需输入／输出及原 pending 的一致变化证明；版本增加、pending 消失或进程事件均不足以单独成立。
FORM response 的 CONSUMED、下一卡 WAITING 和业务正式收尾只引用已经核验的本次调用证据。
SDK Store 与平台 SQL 非原子；保存已完成但平台回填失败时通过原调用键核对，不再订阅执行源探测。
旧 fence／旧 epoch 写入须被拒绝；安全终结写入前另须证明旧调用静止／退出，fence 不构成并发改状态的许可。
pending 安全终结另外记录 terminalization_key、目标 pending、前后版本／摘要、fence、原因及无执行证明。
终结证明不得覆盖原 SDK 调用前后证据；固定保存到 runtime_state_terminalization，不计为一次模型 SDK 调用。字段至少包括唯一 terminalization_key、原 sdk_call_id、owner／Session／Run／slot／generation、目标 pending／冻结摘要、旧调用静止证明、fence／epoch、前后 Store 版本／摘要、原因、无执行及独立读回证明、状态和 row_version。状态 PREPARED／APPLIED／VERIFIED／RECONCILING；同一终结键只产生一次状态变换，APPLIED 仍需读回才能 VERIFIED。锁位于 runtime_sdk_call 之后、interaction_request 之前。
首批仅允许已定唯一平台输入 pending；混合 pending、ASK、错归属或未知外部结果仍 RECONCILING。
原 ToolUse／历史、匹配终结结果和等待 metadata 均须独立读回；无执行探针通过前不启用终结写入。
索引至少覆盖 sdk_call_key、Run 顺序、状态槽＋代次、dispatch、响应引用和未核验调用。

### 6.1 session_intent：新建意图与唯一 Session 绑定

字段：owner_user_id、client_intent_id UUID、employee_id、employee_release_id、有效图片能力快照／摘要、row_version。
另存 prepared_at、可空 bound_session_id／first_submission_id／bound_at、准备失效原因；不保存草稿原文或凭据。
唯一键 (owner_user_id,client_intent_id)；非空 bound_session_id 唯一，绑定事实一经提交不可改为另一个 Session。
准备阶段尚无正式 Session，暂存上传可引用 session_intent.id；重复准备校验同一冻结目标与能力，不静默重写。
首次正式接纳在领域锁内核验 frozen release 仍是当前有效默认；失效时拒绝接纳并准确保留原草稿及暂存。
不自动换发布版本、不移植暂存到另一个意图；已绑定意图不能通过另一 submission_key 再造 Session。
首条接纳同事务完成 Session 创建、意图绑定、普通提交成功结果、消息／素材／Run、dispatch／容量及投影。
重试原 submission_key 返回原结果；已有意图被其他键绑定时不能猜测本键成功，后续普通消息使用 existingSession 目标。
巡检冻结发布／能力与上传、正式 Session 是否一致，是否重复绑定，是否出现无首条已接纳消息的正式绑定。

## 7. media_upload：上传暂存及正式绑定

| 字段组 | 最小字段 |
| --- | --- |
| 票据身份 | upload_id UUID、user_id、upload_request_key、upload_request_sha256、row_version。 |
| 目标 | employee_id、固定 employee_release_id、可空 session_id／session_intent_id；二者按旧会话／新建意图区分。 |
| 原件定位 | 不可变 storage_profile、object_key、可空 object_version；服务端分配不复用键。 |
| 验证事实 | media_kind＝IMAGE、可信 mime_type、byte_count、pixel_width／pixel_height、content_sha256、展示文件名。 |
| 生命周期 | status、issued_at、expires_at、validation_version、绑定 message_id／message_media_id、reason_code。 |
| 清理 | deletion_fence、deletion_claimed_at、deleted_at、重试／对象核对结果；不保存临时签名 URL。 |

状态与接口统一为 ISSUED／UPLOADING／VERIFYING／READY／RECONCILING／BOUND／BLOCKED／CLEANED。拒绝、到期、用户废弃通过 BLOCKED＋reason_code 区分；删除子状态为 NONE／PENDING／CLAIMED／FAILED／DONE，不把删除失败改回 READY。未知上传使用 RECONCILING，不能靠一次 GET 假装验证完成。
唯一键覆盖 upload_id、(user_id,upload_request_key)、完整对象定位；同键不同目标／内容语义冲突。
expires_at 固定为票据创建时刻＋24 小时，上传重试／刷新／读取均不续期。
READY 要求原件真实存在且格式／长度／像素／摘要及固定能力验证通过；客户端 MIME 或 ETag 不能替代。
临时表允许尚无正式 message_id；正式 message_media 继续要求 message_id 非空，不能借它存暂存。
正式接纳事务检查 READY、原期限、owner／目标与摘要，写正式素材及 BOUND 关联；一个暂存原件至多绑定一次。
同一已接纳提交的重试读取原绑定，不重复创建素材；相同图片再次发送仍使用新的对象键。
BOUND 不受临时 TTL 清理；不能因上传票据过期或用户归档删除正式原件。
清理先持久禁止绑定并排除在途接纳／结果未知，再于 SQL 事务外删除对象；失败保持可重试删除事实。
上传／删除提交结果未知先按原 ID 和定位核对，不换对象键重传、不把瞬时查无引用当作可删证明。
索引覆盖 owner／目标、status／expires_at、删除状态及正式绑定；字段和状态转换需与正式引用联合巡检。

## 8. ordinary_submission：普通接纳与永久封闭

| 字段组 | 最小字段／约束 |
| --- | --- |
| 永久身份 | user_id、submission_key UUID；组合唯一且原键不复用。 |
| 完整意图 | 可空 target_session_id／session_intent_id、employee_id、固定提交语义摘要、有序上传引用／摘要。 |
| 处理事实 | status＝REGISTERED／RECONCILING／ACCEPTED／CLOSED_UNACCEPTED、row_version、acceptance_fence。 |
| 原结果 | accepted_session_id／message_id／run_id、accepted_at、closed_at、reason_code、原回查／封闭请求键。 |
| 墓碑标识 | has_registered_intent；区分完整意图记录与从未登记内容的原键封闭墓碑。 |

REGISTERED／ACCEPTED 及曾有完整意图的记录，其目标、语义摘要、暂存清单固定且不可空；纯文字清单为空数组。
语义覆盖目标及完整有序文字／图片引用，不以临时 URL、token、浏览器时间或自由拼接 JSON 排列决定。
未登记原键可直接建立 CLOSED_UNACCEPTED 墓碑：仅 user_id＋submission_key、封闭事实／原因／审计必需。
该墓碑的目标／摘要／清单可以为空，不表示凭空登记过内容；永不补成开放态，也不能用于授权读取未知目标。
已有完整意图封闭时保留原目标和摘要；ACCEPTED 必须有同属本人原消息／Run／Session 及接纳时间。
GET 查不到记录只说明当前未知；POST 封闭与接纳竞争同一永久控制行，不能以 GET 隐式封闭。
接纳先提交则封闭返回原结果；封闭先提交则所有迟到原键接纳拒绝，无论迟到请求携带哪份内容。
首次控制行插入竞争必须靠唯一键及受控重读归并；不能仅锁一条尚不存在的正式消息。
正式接纳的成功结果、消息／素材／Run、暂存绑定、dispatch／容量及投影同事务提交。
CLOSED_UNACCEPTED 不因上传 TTL 清理删除或复活；后续用户明确重试使用新键，原键保留封闭事实。
保留 business_message(user_id,submission_key) 成功唯一键；FORM 由 interaction_response 处理，不能混用普通封闭入口。
索引覆盖组合唯一、本人结果回查、接受结果引用及待核对扫描；同键语义冲突不修改原记录。

## 9. #19 的三类交互记录

### 9.1 interaction_request

字段：public_request_id、owner_user_id、session_id／run_id／employee_release_id、run_request_no、interaction_type。
关联字段：current_revision_id／revision_no、source_sdk_call_id、原 pending ID／工具名／冻结摘要、可空 confirmation_id。
控制字段：status、correction_count、authorization_version／security_version、row_version、invalid_reason。
状态保持 PREPARING／WAITING／ANSWERED／INVALIDATED／EXPIRED／RECONCILING，EXPIRED 只用于操作确认期限。
唯一键：public_request_id、(run_id,run_request_no)、活动请求的条件 run_id 唯一。
活动范围固定 PREPARING／WAITING／RECONCILING；ANSWERED 不再次开放，不能靠新增修订复活。
FORM 就绪必须有可信持久 pending／源调用／checkpoint；确认以原固定操作和确认等待事实为准。
两类请求共用唯一待响应边界，不能同时生成可响应 FORM 和操作确认。

### 9.2 interaction_revision

字段：(request_id,revision_no)、类型／契约版本、snapshot_sha256、不可变展示及必要固定来源引用。
FORM 固定 form-v1／draft-07 的 data_schema、ui_schema、prefill、候选与来源；确认保存 Adapter 固定展示和原确认引用。
上述展示不可变；该修订独立的 draft_data、draft_revision、最近保存请求键／摘要是可变草稿区。
唯一键 (request_id,revision_no)；草稿更新按当前请求指针、修订及 expectedDraftRevision CAS。
历史修订只读；新修订不修改冻结 ToolUse 的工具身份／收集目标，语义变化须先安全终结旧 pending。
服务端持久草稿不是正式 USER 消息；确认修订没有可编辑表单草稿。

### 9.3 interaction_response

字段：request_id、actor_user_id、submission_key／submission_sha256、accepted_revision_id／snapshot_sha256。
回答字段：raw_data、normalized_data、readable_text、可空 accepted_message_id、accepted_at。
消费字段：status、sdk_call_id／claim_fence、前后 checkpoint 证据引用、consumed_at、row_version、继续请求去重。
确认同步字段：可空 sdk_sync_status／sdk_sync_call_id／证据；不伪造 FORM 消费状态。
唯一键：request_id、(actor_user_id,submission_key)、非空 accepted_message_id；归属一致须联合校验。
FORM 状态保持 ACCEPTED／CLAIMED／CONSUMED／RECONCILING，接纳后必须有正式消息且 initial_run_id 为原 Run。
确认响应接纳即 CONSUMED，accepted_message_id 为空，与原确认消费及操作 READY_TO_SEND 同事务。
确认的 CONSUMED 只表示授权已持久消费，不表示工具成功；其后 SDK 同步不重复授权。
消费证明失败保留已接纳回答、消息及占用；不清空响应、不重复注入普通消息或重送匹配工具结果。

## 10. #20 投影及不可变内容版本

session_projection_event 字段：session_id、stream_id、seq／previous_seq、protocol_version、不可变 batch_payload、occurred_at。
唯一键 (session_id,stream_id,seq)，补读索引同序；自增 id 不作业务游标，seq 从 1 开始。
业务写入锁定 Session 后分配 seq，并在同一事务保存业务变化、完整批次和 last_projection_seq。
批次大小／项数在提交前验预算；不能先提交业务、后补事件或拆散不可分割收尾来绕预算。
多 Session 事务各有本地批次，无用户级全局事件流；通知只用于唤醒持久补读。
projection_content 字段：content_id UUID、owner／session／run、content_kind、stream_id、first_seq／first_position、current_version、状态。
状态 OPEN／CLOSED／PROMOTED，保存 close_reason、正式替换消息关联、row_version；首次锚点不可改。
projection_content_version 字段：(content_id,content_version)、base_version、payload_version、body_format／字节数／sha256。
载荷使用不可变 UTF-8 正文／结构快照或指向固定不可变源的引用；不能只存随业务行覆盖的 display_text。
唯一键 (content_id,content_version)；详情按指定版本读，不静默换最新版、截断或调用模型补造。
文字追加／关闭要求前驱匹配且版本＋1；封闭后禁止追加，提升到正式消息保存 replacesContentIds 关联。
run_progress 增 payload_version、content_id／content_version、sdk_call_key、受控来源、锚点／关闭／提升关联及投影流／序号。
正式消息继续 TEXT／MEDIA，Markdown 是 TEXT 的受控展示约定，不能把所有过程卡写成正式历史。
同 Run 正式员工回复唯一、成功状态、可恢复框架状态、预览替换与批次收尾必须一致。
snapshot／pageCursor／sourceRef 仍按本人资源、固定水位和不可变版本核验，引用不携带权限。
投影和详情不复制确认 token、加密副本、原始 SDK 状态、原始 Thinking 或第二份授权／消费账本。

## 11. 随机确认 token 的加密恢复副本

operation_confirmation 保留现有随机 token SHA-256、原固定操作／参数／身份版本、PENDING 等状态和十分钟期限。
token 原始值为 SecureRandom 生成的 32 字节，对外 base64url 无 padding 恰为 43 字符；SHA-256 针对解码后的原始 32 字节。
新增 crypto_format_version＝1、key_id（ASCII、最多 64 字符）、token_nonce BINARY(12)、token_ciphertext VARBINARY(48)、recovery_status。
算法固定 AES-256-GCM：独立 32 字节 key、12 字节 nonce、128 位 tag；ciphertext 包含 tag 共 48 字节，不取隐式默认长度。
nonce 为固定 keyId 前缀 4 字节＋单调计数 8 字节。新增 crypto_nonce_cursor：key_id 唯一、nonce_prefix BINARY(4)、last_reserved_counter BIGINT UNSIGNED、key_generation_ref、row_version 及通用时间字段。前缀与 keyId 绑定且不重指；计数从 1 分配，耗尽前更换新 keyId／密钥，不环回。
本稿将每 keyId 最多预留次数定为 2^32−1；达到阈值即拒绝新预留并要求新 keyId／密钥，不等到整数溢出。
加密前在独立短事务锁该行、递增并明确提交预留；不持其他领域锁，不嵌套确认事务。只有预留已确定提交才加密；预留提交不明则候选不得加密使用，回查后另作新预留。确认事务回滚、进程退出不回收已预留号码。
(key_id,token_nonce) 唯一键仅作落库校验，异常重复阻断签发并核对，不能先重复加密再把唯一冲突当作 nonce 唯一保证。普通重启沿已提交计数；恢复备份、计数回退／丢失或连续性不明时，先以独立恢复配置启用全新 keyId／密钥与新游标，旧密钥只用于解密，未完成则不开放签发。
AAD 使用固定 UTF-8 规范编码，包含 formatVersion／keyId／interaction_public_id／operationId／ownerUserId／operationDigest／originalExpiresAt／securityVersion／phoneRevision。
AAD 各事实在签发前确定且不可变，交互公共 ID 预先分配；AAD 编码格式随 crypto_format_version 固定，禁止自由 JSON 排列。
密钥独立于数据库；keyId 不重指不同密钥材料，保留原 keyId 解密和受控轮换／恢复能力。
原 token 的摘要、密文／nonce、原确认、原 expires_at 与交互绑定在同一签发事务建立；此前独立提交的 nonce 预留不回滚，任何失败不重置原期限。缺失不开放确认。
专用 POST 领取须当前登录、CSRF、本人归属、原提案、当前版本／权限、PENDING 及未过期检查。
解密验证认证标签后再核对原摘要；刷新返回相同 token，不新建确认、不延长十分钟、不重置消费。
密文损坏／密钥缺失／摘要不符时保持不可确认并进入既定安全终结，不从摘要恢复或重签替代。
旧仅摘要行不得伪造可恢复加密副本；密钥 keyring 是外部独立秘密配置，不持久在数据库。
明文／密文／nonce 不出现在投影、普通查询 DTO、URL、消息、草稿、审计或普通日志。
GET 保持只读且不领取；POST 领取响应禁止缓存，真实确认消费仍锁原确认／操作并查一次性状态，token 不代替业务鉴权。

## 12. bootstrap_batch 与 SYSTEM_BOOTSTRAP

bootstrap_batch 保存 id、source_ref（公共唯一编号）、bootstrap_scope、manifest_version／manifest_sha256、status、row_version。
另存 created_at／applied_at、初始化程序版本、受控结果摘要／失败原因、目标预置集合索引及审计关联。
状态固定为 PREPARING／APPLIED／FAILED／RECONCILING；source_ref 同键同 manifest 回查原批次，不同 manifest 拒绝。
当前只允许一个已应用的本期初始化范围；不能换 sourceRef 将同一数据库反复重置为初始密码。
manifest 覆盖预置普通账号／号码归属、凭据引用版本、授权、员工发布／绑定／Skill 清单与规范摘要。
公开编号／持久脱敏摘要不含口令、完整手机号、密钥或可恢复凭据；实际用户数据只在受控目标表按规则保存。manifest_version=1 的内容固定为 sourceRef、bootstrapScope、identityRefs（用户／凭据／号码记录 ID）、immutableTargets（员工发布／Skill／绑定／storage_profile 的稳定 ID 及内容摘要），不把当前密码哈希、首次改密标识、当前安全版本、可用性／授权状态放入不可变 manifest。
编码为键按 ASCII 升序的紧凑 JSON UTF-8，ID 为无前导零十进制字符串、摘要为小写 hex；immutableTargets 按 kind 再稳定 ID 排序，数组其余项按字段约定固定顺序，SHA-256 对最终字节计算。初始事务取得真实 ID 后生成最终 manifest，APPLIED 必须非空且摘要一致；PREPARING 未完成可空，不公开伪成功。
已 APPLIED 的同 sourceRef 只读回核验原不可变引用，不重复设置初始密码；首次改密和合法状态变化不应使初始 manifest 被判损坏。不同稳定初始化内容冲突，不能换 sourceRef 绕过同一期 bootstrap_scope 唯一约束去重置数据；该范围只允许一份批次。
来源事实不是一个登录主体；不创建系统用户、管理员绑定或第二账号，也不借用 UserId=0。
来源列统一区分 USER_ACTION 与 SYSTEM_BOOTSTRAP；后者关联 bootstrap_batch.id，sourceRef 经批次解析。
仅 SYSTEM_BOOTSTRAP 且批次来源完整时允许对应 actor 为空；USER_ACTION 必须为真实正数 UserId。
平台账号 created_by／modified_by、手机号 ownership_checked_by、草稿 saved_by、身份审计 actor 现已可空，补齐来源语义与条件约束。
不能仅在用户行留一份来源，就让其后所有空操作者无条件合法；每个受控预置事实都须可追溯到该批次。

| 既有表／列 | 最小变更责任 |
| --- | --- |
| employee_release.published_by | 可空仅限创建来源 SYSTEM_BOOTSTRAP；补 creation_source_kind／bootstrap_batch_id，保留其他正值与发布完整性。 |
| employee_release.availability_changed_by | 初始可用性来源单独关联；不能用永久创建来源放行日后无操作者的可用性修改。 |
| tool_binding_revision.created_by | 可空仅限系统预置来源；binding 不可变、目标与摘要要求不变。 |
| employee_use_grant.granted_by | 可空仅限原系统授予来源；ACTIVE／REVOKED 配对及后续真实操作者规则保留。 |
| employee_configuration_audit_event.actor_user_id | 可空仅限系统来源；同时调整正值 CHECK、来源约束、成功收据和巡检。 |

创建来源与最近修改／可用性来源分别记录；系统创建并不授权未来任意空 actor 修改。
identity_audit_event 的初始化事件保留 actor 为空、目标用户、动作、批次来源及准确时间；改密仍由实际普通用户发起。
配置审计沿对象动作记录发布等初始化事实，并标来源 SYSTEM_BOOTSTRAP；不伪造“管理员点击发布”。
现有 action_code CHECK 只允许原动作；若新增动作名称须同步规格，不能将来源码直接冒充动作码。
配置审计增加非空 receipt_scope_kind／receipt_scope_id：USER_ACTION 对应真实 actor，SYSTEM_BOOTSTRAP 对应 batch.id。
成功唯一范围使用 (receipt_scope_kind,receipt_scope_id,success_request_id)，成功 request_id 必须非空稳定。
失败允许追加多次但不得生成成功收据；不能继续依赖 (NULL actor,success_request_id) 防系统重复。
scope_id、actor 与 batch 的配对用 CHECK／服务／巡检证明，不能接收外部参数随意选择来源范围。
bootstrap_batch、平台预置行、固定摘要／引用及对应成功审计在一次受控平台事务完成 APPLIED。
该事务前完成规范校验／秘密引用准备；不在事务中探测模型、MCP 或 MinIO，不伪造外部服务 PASSED。
提交不明按 sourceRef＋manifest＋结果引用核对；不能新建批次、重置密码、提升发布或覆盖历史来“重试”。
启动校验 APPLIED 批次与本期预置不可变引用完整一致；基本数据缺失／损坏拒绝启动，外部服务在线状态不构成启动前置。合法账号停用、授权撤销、发布停用由当前允许动作处理，不作为结构损坏或理由在重启时重新授权／重置密码。
框架表／独立对象存储不被该事务宣称原子覆盖；外部未验收保持工具／能力受控不可用。
既有巡检中以 actor 连接 platform_user 的条件需加入系统来源分支，仍核验 batch／manifest／目标引用，不静默忽略 NULL。
本节只定义初始化数据契约，不提供执行入口、不执行初始化、不自动迁移存量库。

## 13. 联合约束与巡检清单

| 范围 | 必须检出的异常 |
| --- | --- |
| C0／dispatch | 计数与 HELD／普通 WAITING 归属不符、超限、旧 epoch 仍可领取、重复许可、无原 Run／来源。 |
| SDK／checkpoint | 调用跨 owner／Session／发布／槽位、无源响应、保存／读回不符、旧 fence 写回、无证据消费／终结。 |
| 新建意图 | 同 owner／clientIntentId 多行、同意图多 Session、冻结发布失效仍首接纳、旧 Session 缺失时重建空状态。 |
| 上传／正式素材 | 超期仍 READY 可绑定、BOUND 无正式引用、正式引用仍被临时清理、定位／摘要／owner／目标错配。 |
| 普通提交 | ACCEPTED 缺完整意图／结果、完整意图摘要被改、封闭键又接纳、无意图墓碑被补成开放态、消息与控制结果不一致。 |
| 交互 | 同 Run 多活动请求、当前修订跨请求、FORM 无消息／pending 证明、确认混入 FORM 消费、响应唯一性冲突。 |
| 投影 | Session head／批次不成前缀、内容版本断链、固定版本缺失、封闭后追加、成功回复／提升／批次不一致。 |
| 系统来源 | 无 batch 的空 actor、USER_ACTION 空 actor、伪造 receipt scope、批次结果／manifest 不符、重复成功收据。 |

首次落 DDL 须增正反约束探针及并发事务探针，原 29 表验收不覆盖这些新结构。
重点故障窗口：上传后 SQL 不明、封闭先于意图登记、接纳后未领取、SDK 已执行未保存／平台未回填、终结后旧 writer 到达、批次 APPLIED 提交不明。
隔离验证同时证明没有重复模型／会议写调用、没有丢失已接纳回答、没有凭据进入投影／日志。
自动补读、启动核对、容量重建不执行业务；终结适配器先通过无网络模型／计数工具／隔离状态库探针。
租约过期只触发允许的核对；记忆任务保留既定单 worker、5 秒扫描及重试默认值，不进入普通调度额度。

## 14. 整体稿固定项与实施验证边界

- runtime_capacity C0、领域主干、普通提交／上传／dispatch／交互／调用证据及 memory_update_job 的完整锁序由统一事务矩阵给定；不能各表独自排序。
- runtime_sdk_call 的真实保存收据、独立读回及旧 writer fence 如何落到选定框架 Store，必须按固定 SDK 验证；单表字段不是实现证明。
- 安全终结证据固定为 runtime_state_terminalization，原调用不被覆盖；证据格式版本从 1 开始。
