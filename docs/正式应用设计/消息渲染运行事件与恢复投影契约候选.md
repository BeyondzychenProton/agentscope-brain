## 1. Q11 候选：固定类型的事务批次与内容版本

### 1.1 外层及应用规则

对外协议定名为 `web-projection-v1`。一个已提交的平台 SQL 事务，对每个受影响的 Session 产生一个投影批次；同事务多对象变更通过 `changes[]` 一起应用。跨 Session 事务分别分配各自序号，不建立全局用户事件流。

| 字段 | 含义 |
| --- | --- |
| `protocolVersion` | 固定协议版本；不认识主版本时停止应用 |
| `sessionId` | 已鉴权的业务会话定位；不能用它选择当前登录用户 |
| `streamId` | 服务端生成的该会话投影流标识；与 Session、Run 和 SDK 调用分开 |
| `seq / previousSeq` | 本批次与直接前驱序号；所有 BIGINT 标识及序号在线上使用十进制字符串 |
| `occurredAt` | UTC 时间，仅作显示与排查，不决定顺序 |
| `changes[]` | 有序的固定类型变更；先校验整批，再原子更新前端状态与已应用游标 |

`streamId + seq` 唯一定位批次。重复的已应用批次忽略；直接前驱不匹配则补读，不能先显示后补齐。载荷在提交后不可改写。普通服务重启保留流标识；备份恢复或受控重建若可能使旧游标失真，须在重新开放前切换流标识，使旧游标明确失效。恢复业务事实的核对仍归既有恢复协议，换流不能清除 UNKNOWN 或待核对。

客户端应用版本是展示版本，不假设每个业务表都有 `row_version`。非文本对象可用本对象最近修改批次的 `seq` 作为 `viewRevision`；业务提交的 CAS 继续使用各事实本身的版本和状态，二者不可互换。

### 1.2 固定变更类型

| `kind` | 载荷和效果 |
| --- | --- |
| `SESSION_SET` | 当前生命周期、恢复状态及必要会话摘要的完整展示对象 |
| `RUN_SET` | Run 当前可信状态、原因、重试关系及受控阶段；不从 SDK End 事件推定成功 |
| `CONTENT_SET` | 一份稳定 `contentId` 内容的完整展示版本、种类、归属及排序锚点 |
| `TEXT_APPEND` | `contentId, baseContentVersion, contentVersion, delta`；只有当前内容版本匹配时才追加 |
| `CONTENT_CLOSE` | 本段生成完成、因等待而结束、失败、中断或已提升；带相同版本链的前驱／新版本，终结后不再追加 |
| `MESSAGE_COMMIT` | 已提交的正式消息、其有序内容，以及明确的 `replacesContentIds[]`；用户输入可无替换目标 |
| `TOOL_SET` | 根据固定操作提案与账本生成的必要参数和结果摘要完整版本 |
| `INTERACTION_SET` | #19 的请求／修订、保存草稿及回答摘要、接纳／消费状态的展示版本；确认凭据不在其中 |

对象采用完整展示版本；仅流式文字使用受约束的追加，不引入任意 JSON Patch 或可执行界面更新。非文本内容创建、结构变化及状态变化使用完整新版本，旧修订仍保持不可变。

同一 `contentId` 的 `contentVersion` 从 1 递增，正文追加和内容关闭均要求 `baseContentVersion` 与当前值相等，新版本为前驱加一；它们与快照／`CONTENT_SET` 中的 `contentVersion` 是同一版本链。终结状态额外阻断追加，不能只看版本相等。

### 1.3 内容与引用

内容共用 `contentId, contentVersion, kind, sourceRef, orderAnchor, status`。种类为 `TEXT`、`IMAGE_REF`、`LIST`、`TABLE`、`RECEIPT`、`INTERACTION_REF`；受控阶段和工具摘要由上述 Run／Tool 对象表达。`sourceRef` 使用服务端允许的资源类型及标识，不接受客户端或模型指定任意 URL。

- 用户普通输入按纯文本显示；员工正文采用 `markdown-v1` 受控渲染。支持列表、表格、代码块和链接，禁用原始 HTML、脚本和执行型组件；普通链接仅开放 `https/http`，图片必须经平台素材引用取得，不能通过 Markdown 图片绕过素材读取边界。生成中暂时不完整的 Markdown 可按文字显示，不能执行未完成结构。
- `LIST/TABLE/RECEIPT` 的值与展示标签为纯文本，格式来自版本化受控组件。业务结果由服务端 Adapter 的规范化事实生成；显示不完整的摘要或前若干行时明确标识范围，完整业务事实不因此被改写。
- 展示块的逻辑顺序使用正式消息号、该输入下的 Run／重试关系和内容首次出现的会话批次定位；后续更新同一块不改变其首次出现位置。FORM 回答的正式消息插入点由其接纳批次决定；不能按时间戳重新排序，也不能把长 Run 的全部过程简单塞到最终员工回复之后。
- 服务端 SDK 调用键、原生 reply/block/tool 关联保存在可信过程关联里。客户端不据这些字段决定 Run 或执行身份；一个 Run 多次 SDK 调用产生的过程分别保留。

大正文或结果详情可返回服务端生成的不可变内容引用，引用必须固定资源、展示版本和摘要；GET 必须读取该版本，不能改为读取“最新值”。历史只读详情可以先呈现明确的待加载引用，再按需读取；若引用内容构成当前文本追加的基线或当前交互的必要展示，须取回并校验完成后才应用相应更新或开放操作。详情读取可按固定版本分块，不能为符合响应上限静默改写正文；原件签名 URL 只在重新鉴权的素材读取链路临时生成。

## 2. Q12 候选：历史卡片与正式收尾

- FORM、操作确认、查询结果及操作回执在结束后仍保留可恢复的历史展示。查看原卡时使用原展示修订与当时固定提案；FORM 已接纳回答保留结构化值及其正式 USER 消息，二者通过响应标识关联。
- 只有当前、有效且就绪的请求修订可响应。历史卡、过期卡、已回答卡只读；旧事件或旧快照不能重新激活它们。新快照／批次更新服务端草稿基线时，未保存的本地输入仍作为独立草稿保留，依 #19 提示冲突，不用远端值覆盖正在编辑的内容。
- 回执表示该次操作的结果。例如后来又取消预约，原预约成功回执仍说明原操作曾成功，新的取消操作另有回执；不能把原回执悄悄改成当前预约全生命周期状态。
- 一个操作从 UNKNOWN 核对到确定结果时，更新该操作当前展示版本，并保留原过程记录。历史确认内容和原固定提案仍不改变；未知不能显示成“尚未发生”。
- 正式收尾先核实框架状态可恢复，再在同一平台事务提交正式员工消息、Run 成功、预览提升／替换关联及该 Session 投影批次。每 Run 至多一条正式员工消息的既有约束继续有效。重复回调和提交结果不明先回查原收尾，不新建另一条消息或重复批次。
- 封闭内容前处理已接纳的文字缓冲区，并以内容状态／SDK 调用 fence 拒绝迟到追加。最终内容可与预览不同，以正式内容为准；前一等待阶段及工具前说明不会一并提升。候选结果或状态保存不明仍保留为过程／待核对，不强行提升正式消息。
- 操作成功而后续模型失败时，操作回执仍显示真实成功，Run 另显示后续答复失败。取消先显示取消中，UNKNOWN 保留核对状态；进程重启后读取已保存的核对事实，GET 不执行恢复探测或模型。此处消费既有状态规则，不重开生命周期。

## 3. Q13 候选：最小持久结构增补

| 位置 | 拟增加的能力 |
| --- | --- |
| `business_session` | `projection_stream_id`、`last_projection_seq`，在 Session 串行化锁内分配；原消息号和行版本保留原义 |
| 新增 `session_projection_event` | 会话／流标识／序号、协议版本、不可变事务批次 JSON、时间及必要关联；唯一键覆盖 `(session_id, stream_id, seq)`，按该顺序补读；自身数字主键不作为提交游标 |
| 扩展 `run_progress` | 版本化结构载荷、稳定内容身份／版本、SDK 调用键、受控来源引用、终结及预览→正式消息关联；继续保存可恢复过程，原文字说明不是结构载荷的替代品 |
| 既有消息和业务事实 | 正式内容块保持 `TEXT/MEDIA`；工具事实仍归原操作账本；交互仍消费 #19 的三类记录及其结构调整 |

本候选没有第二套表单授权或业务操作记录。投影日志负责历史送达，不能替代业务来源；结构化过程记录负责保存运行输出和展示关联，不能充当 SDK 持久消费证明或执行领取账本。

事务需覆盖所有展示变化路径：普通消息／重试、FORM 接纳、旧回答消费与新卡就绪、确认消费、工具结果、取消／过期／核对、Session 状态及升级的来源和目标会话。受控维护脚本若改变这些事实，也须满足同事务投影与锁序；不能直接改业务行后依赖异步通知“最终补齐”。账号／授权等跨会话权限事实仍由当前身份检查裁定，不能靠历史 `allowedActions` 恢复权限。

SQL 内互斥遵守既有全局锁序；涉及多个 Session 时在统一阶段按固定 Session 顺序加锁。只持锁进行 SQL，不在锁内等待模型、网络或用户。事务提交后通知只唤醒持久补读，通知丢失不能丢更新。具体 SDK 领取、checkpoint、pending 安全终结与完整工程锁序由 #22 依既有规格落实，不据本候选宣称已经可用。

## 4. Q14 候选：初始资源与恢复参数

以下为项目初始推荐值，不是框架默认，也未经过性能验收。按实际 UTF-8 序列化大小检查；具体更改受控且不得静默放宽已展示的旧交互契约。

| 项目 | 初始值／规则 |
| --- | --- |
| 正文合并 | 最多等待 100 ms 或新增 4 KiB 即保存；关键状态／终结时立即收尾 |
| 单 Run 正文累计 | 256 KiB；超限停止后续生成，保留已提交输出并按既有安全终结／待核对协议收敛，不能把截断当完整回复 |
| 结果摘要／列表表格 | 摘要 8 KiB；单结构块 64 KiB，表格最多 50 行、20 列；超出时明确显示摘要范围或提供固定版本详情引用 |
| 历史页 | 默认 50 条正式消息、20 条过程项；请求上限各 100；达到字节预算时可返回较少条并给继续位置 |
| 批次与快照 | 单批次最多 1 MiB、128 项变更；快照／补读单响应最多 2 MiB；大内容用固定版本引用，当前交互须完整可读后才开放操作 |
| 连接队列 | 每订阅最多 100 批或 4 MiB，先达到者为准；超限关闭并持久补读 |
| 心跳与查权 | 空闲 15 秒发送无业务序号的心跳；每次读取／发送批次前及空闲心跳时复核当前登录和读取权限 |
| SSE 降级 | 连续 3 次连接失败后改增量轮询；重试退避 1、2、4 秒；健康轮询期间每 30 秒可试一次 SSE |
| 轮询 | 活跃执行每 2 秒，等待／无执行每 10 秒；连续 5 次读取失败后暂停自动恢复并提示手动重试 |
| 不兼容／坏结构 | 一次自动重建兼容快照；仍不能应用则保留已确认只读视图并提示更新，不无限循环 |

投影必须在同一业务事务提交前完成总预算校验。大于 4 KiB 的普通变更对象优先使用有界元数据和固定版本正文／详情引用，FORM 的结构和草稿仍遵守 #19 的独立上限；不可分割的业务收尾须事先保证变更项数和载荷可表达。不能先提交业务再补事件，也不能拆开一个原子批次来绕过预算。真实工具结果始终先按原操作协议保存，使用有界结果摘要及对应固定事实引用完成同事务投影，不能因展示预算把真实成功丢弃或改成失败；适配器不能证明有界表达能力时，属于发送前的实施准入缺口。

提交给浏览器的业务批次已持久化，客户端完整校验并应用后才更新自己的游标。SSE 的 `id` 为流／序号定位，`Last-Event-ID` 不能覆盖应用已确认位置；客户端负责关闭失败消费链并以显式已应用游标重连。心跳、重置、认证失败等传输控制帧不推进业务游标。

读取 API 候选为：`GET /api/sessions/{sessionId}/projection/snapshot`、`GET .../events?after={cursor}` 和 `GET .../stream?after={cursor}`；支持版本与会话／流游标匹配须先校验。普通 HTTP 动作继续使用 #19 等已定入口，动作结果不是 SSE 送达回执。精确分页／详情引用参数将在正式规格列出。

越权资源统一按既有不可见规则返回；登录失效停止订阅，当前账号不得因持有旧游标继续读取。员工使用权撤销后按既有规则保留可读历史，禁止新执行；所有写动作再次鉴权。确认凭据不进快照、批次、过程 JSON 或日志。其首次签发及刷新后重新取得的接缝由 #22 设计落实：当前 DDL 仅存凭据摘要，不能从摘要还原原文，也不能把 #19 的消费入口当作已经存在的领取能力；恢复凭据不得改变原确认、原十分钟期限或消费状态，能力未具备时不能宣称确认链路可用。#19 的字段、Schema、草稿和回答上限继续有效。

## 5. 正式收口时须验证的场景

以下尚未执行；正式规格须把输入、并发点和可计数预期交给 #23：

1. 同 Session 两个写者交错与回滚；业务、批次、序号一起提交，不出现晚到的小序号。
2. 快照读取期间提交新消息／新卡；从水位补读不漏、不重复，旧消息翻页不移动实时游标。
3. 重复、乱序、残缺 SSE 帧、多对象批次应用失败；游标仅在整体应用后前移。
4. 预览提升、最终文字修订、迟到 delta、重复完成回调；一条正式回复、一次替换，不复活旧预览。
5. 一个 Run 多次 SDK 调用、FORM 正式回答、下一张卡就绪；调用来源和可见顺序可复原，不重复执行 SDK。
6. 慢客户端、通知丢失、SSE 失败与轮询降级；持久补读完整，无法补齐明确重建。
7. 未知内容块、不兼容批次、错误内容引用；占位或只读停止有界，不跳过失败批次。
8. 操作已成功但后续模型失败、本地取消时上游结果不明；真实回执独立展示，UNKNOWN 不伪装失败。
9. 重启、日志重建或受控备份恢复；普通重启不换流，旧流游标失效时只重建展示，不重发模型／工具。
10. 撤权、账号停用、跨用户游标、失效素材链接及确认凭据检查；身份不由路径、事件或模型选择。
11. 大输出、长历史、超限批次／队列；显示范围明确，按已批准边界收敛，不静默丢正式内容。

Q11—Q14 已确认，完整规格及下游责任已另行整理；设计收口与实现／真实验收继续分别记录。
