## 1. 范围、决定与事实归属

一期维持单企业、Web、一个会议室数字员工、单节点低并发。采用平台自有 `web-projection-v1`；本轮没有选择 AG-UI 作为 Web 对外协议，也未选择前端框架、renderer 或 Java SDK。

普通 HTTP 承载消息、草稿、回答、确认、继续和取消等动作；GET 快照、GET 增量及 GET SSE 只读取已持久结果。浏览器断线、关闭、切换与重新订阅不取消 Run，不调用 SDK、恢复 pending 或发送工具操作。一次 Session 最多一个活动 Run、一次 Run 多次 SDK 调用及 [#19 的完整生命周期](https://github.com/BeyondzychenProton/agentscope-brain/issues/19#issuecomment-6359974007)继续沿用。

| 来源 | 能证明及投影的内容 | 不能据此推导 |
| --- | --- | --- |
| 正式消息及有序内容 | 已接纳用户输入、完整员工回复 | 所有过程卡都是正式消息 |
| `run_progress` 及可信 SDK 调用关联 | 累计正文、关键阶段、内容修订、封闭／替换经过 | 框架状态已持久消费、外部业务成功 |
| Run／Session | 业务运行、占用、取消中、待核对及可恢复性 | SDK End 等于业务成功 |
| 工具操作／确认账本 | 固定提案、一次确认、发送与真实操作结果 | 超时、取消或模型文字证明外部操作未发生 |
| #19 交互请求／修订／响应 | FORM 与操作确认、草稿、就绪、接纳和消费 | WAITING 事件即持久就绪；ACCEPTED 即 SDK CONSUMED |
| 投影日志 | 已提交展示变化的有序补读 | 可替代上述业务来源或执行领取账本 |

正式用户／员工消息不可原地编辑。FORM 接纳形成原 Run 下正式 USER 消息，操作确认不套用该规则；部分正文及中断片段保留为 Run 过程。

## 2. 展示内容与执行过程

内容共用 `contentId, contentVersion, kind, sourceRef, orderAnchor, status`。标识由服务端生成并持久关联；`sourceRef` 仅定位平台允许的事实类型，不接受任意 URL 或调用目标。

| `kind` | 受控表达 |
| --- | --- |
| `TEXT` | 用户普通输入为纯文本；员工正文为 `markdown-v1`，含列表、表格、代码块和链接 |
| `IMAGE_REF` | 经鉴权的消息素材引用；持久记录不存临时签名 URL |
| `LIST` | 服务端根据规范化事实生成的纯文本条目 |
| `TABLE` | 固定列定义和纯文本单元格，包含总量／显示范围说明 |
| `RECEIPT` | 某次工具操作的状态、必要业务标识及结果摘要 |
| `INTERACTION_REF` | #19 请求 ID、类型及不可变展示修订，配合独立的当前状态展示 |

组件目录固定，新增表达能力按契约版本受控扩展。Markdown 禁用原始 HTML、脚本及执行型组件，链接只开放 `https/http`；Markdown 图片不能绕过平台素材链路。未闭合的流式 Markdown 可按文字显示。列表、表格、标签、帮助及摘要均不解释成 HTML。

用户可展开的执行过程包含：真实阶段、工具目标及完整校验后的必要参数、开始时间、当前状态、结果摘要、可理解的失败原因和允许的后续动作。原型的“思考过程”改为受控阶段说明；原始 Thinking、系统提示、凭据、原始请求／响应报文及未完成工具参数不传给用户。

回执说明该次操作：后来取消预约不改写原预约成功事实，取消另有回执。UNKNOWN 核对到确定结果时更新该操作的当前展示，保留原过程；不能把未知显示成尚未发生。工具真实成功而后续模型失败时，分别保留成功回执与 Run 答复失败。

大正文／详情引用固定资源、展示版本和 SHA-256；摘要计算对象为该版本响应的实际 UTF-8 字节，客户端校验后解析，不对 JSON 重新排序后计算。历史只读详情可延迟加载并明确标识；当前文字追加基线或交互必要展示未取回／校验时，不应用依赖更新或开放操作。按需读取不得静默替换为最新版或截断原文。

## 3. 批次、版本与显示顺序

一个平台 SQL 事务为每个受影响 Session 产生一个不可变投影批次，`changes[]` 整批校验和应用。跨 Session 事务各有本地序号，不引入用户级全局事件流。

| 外层字段 | 约定 |
| --- | --- |
| `protocolVersion` | `web-projection-v1` |
| `sessionId, streamId` | 业务会话与投影流定位；均不能选择登录 principal |
| `seq, previousSeq` | 同一流中本批与直接前驱；首批为 `1/0`，零表示初始水位 |
| `cursor` | 服务端生成、绑定 Session／流／本批序号的不透明 URL 安全字符串，客户端原样回传 |
| `occurredAt` | UTC 时间，只用于展示和排查 |
| `changes[]` | 下列固定变更类型的有序集合 |

BIGINT 标识及序号使用十进制字符串；内容／流 UUID 使用服务端生成的稳定字符串。同流序号形成已提交前缀：后续写者在前一事务提交／回滚后才能分配下一号；普通自增主键、时间戳和 SDK 事件 ID 不提供这一保证。`streamId + seq` 唯一定位批次，不按到达时间排序。

| 变更类型 | 载荷及效果 |
| --- | --- |
| `SESSION_SET` | 当前 Session 摘要、生命周期和恢复状态完整版本 |
| `RUN_SET` | RunId、状态、原因、来源消息／重试关系和阶段完整版本 |
| `CONTENT_SET` | 稳定内容身份、归属、种类、顺序锚点及完整展示版本／固定版本正文引用 |
| `TEXT_APPEND` | `contentId, baseContentVersion, contentVersion, delta` |
| `CONTENT_CLOSE` | 内容的前驱／新版本及终结原因，封闭本段输出 |
| `MESSAGE_COMMIT` | 正式消息的发送方、消息号、来源／产出 Run、有序内容和 `replacesContentIds[]` |
| `TOOL_SET` | operationId、原固定提案、必要参数、真实状态、资源号和有界结果摘要完整版本 |
| `INTERACTION_SET` | requestId／类型／当前修订、展示摘要、草稿版本、响应摘要、接纳／消费状态及失效原因；不含确认凭据 |

普通对象发布完整展示版本，仅文字采用受约束追加，不使用任意 JSON Patch。每个内容的 `contentVersion` 从 1 递增，追加／关闭均要求前驱匹配且新版本为前驱加一；关闭状态额外禁止追加。内容状态为 `OPEN/CLOSED/PROMOTED`，`CONTENT_CLOSE` 另带 `COMPLETED/WAITING/FAILED/INTERRUPTED/PROMOTED` 之一的 closeReason；静态内容为 CLOSED，真实工具／交互状态保留在各自对象里。封闭内容不会因重连重新打开。

非文本对象 `viewRevision` 使用本对象最近变更批次的序号；它不是业务 CAS 版本，不假设 Run、工具表已有 `row_version`。只允许契约明示无语义影响的可选 `extensions` 被忽略；未知状态、动作、变更类型或主版本不视为成功。

显示顺序以内容首次出现的批次和批内位置为稳定锚点，正式消息同时保留消息号。更新同一对象不重排其首次位置；FORM 消息在接纳批次处进入原 Run 经过。重试仍归原输入但有新 Run，不把所有过程挪到最终答复后。服务端调用键及原生 reply/block/tool 关联保存于可信过程记录；最终 Msg 没有公共 replyId 时也不能把该 Run 的全部文字拼成最终回复。

序号比较按整数语义，不按字符串字典序，也不转为可能丢精度的浮点 Number；cursor 始终由服务端返回并由客户端原样保存。

## 4. SQL 提交、正式收尾与并发

持久过程与可见业务变更、Session 序号、对应投影批次在同一平台 SQL 事务提交，提交后才通知和推送。通知只唤醒持久补读，可丢失而不丢业务变化；不在持锁期间等待网络、模型或用户。

遵守既有全局锁序，特别是输入路径的记忆序号行→Session→Run→交互。多 Session 在统一锁阶段按固定 Session 顺序处理，不为投影新增相反锁序。来源／目标 Session 升级、受控维护脚本、表单接纳、旧消费＋新卡就绪、确认消费、工具结果和取消／过期／核对均须覆盖投影，不能仅覆盖正文。

正式收尾依次取得完整候选、核实框架状态持久且可恢复，再在一个平台事务中写正式员工消息、Run 成功、内容封闭／提升和预览替换关联、投影批次。每 Run 至多一条正式员工回复；重复回调或提交结果不明按原 Run／收尾事实回查，不再分配消息或重复成功批次。框架状态与平台 SQL 共用 MySQL 也不推定原子提交。

封闭前处理本次已接纳的文字缓冲，并用内容关闭状态和调用 fence 拒绝迟到追加。`MESSAGE_COMMIT` 在对应预览处完成正式展示；最终内容有差异时以正式内容为准，不额外追加同文回复。工具前说明和前一等待阶段过程不会一并提升。框架保存不明时候选仍是过程／待核对；已成功工具结果不被 Run 失败覆盖。

## 5. 一致快照、分页与固定版本详情

首次打开或重建使用显式 REPEATABLE READ 的只读一致事务，在同一 read view 中读取必要平台对象及最后已提交序号。快照包含：会话状态、近期正式消息、当前任务累计正文／关键过程、当前交互及最近成功保存草稿、当前相关工具结果摘要，以及 `streamId, watermark, cursor`。读取旧对象后再到另一个当前视图取最大事件号是禁止的。

先完整装载快照，再从严格大于 watermark 的批次追赶；快照与订阅间的新提交从持久日志补齐。历史消息以不可变正式消息为来源，固定快照观察到的消息上界，按消息号向前分页；翻页不改变实时游标。过程详情按固定流／水位／展示修订读取，不能混入当前最新可变业务行。

| GET 路径 | 输入 | 返回与约束 |
| --- | --- | --- |
| `/api/sessions/{sessionId}/projection/snapshot` | `protocolVersion`；`messageLimit=50`、`processLimit=20` | 同视图快照、watermark／cursor、历史上界、消息及过程 pageCursor、可读内容引用；两类 limit 上限 100 |
| `.../projection/events` | `protocolVersion, after, limit=100` | 有序 `batches[]`、`lastCursor, headSeq, hasMore`；head 与本页同读取视图，字节预算到达可少返回 |
| `.../projection/stream` | `protocolVersion, after` | 仅读取持久批次的 SSE；显式 after 为应用已确认位置 |
| `.../projection/messages` | `protocolVersion, pageCursor, limit=50` | 绑定 Session／流、消息上界和向前边界的不可变历史页 |
| `.../projection/runs/{runId}/history` | `protocolVersion, pageCursor, limit=20` | 固定 asOfSeq 的过程页；首次页游标由快照或已取得的 Run 展示对象给出 |
| `.../projection/content/{contentId}` | `protocolVersion, contentVersion`；可选 `partCursor` | 固定版本正文／详情；大内容返回确定的分块及下一个 partCursor，不读取最新值 |

各 `pageCursor/partCursor` 均为服务端不透明定位，绑定本人可读 Session、流、固定水位／版本及继续位置。首次详情引用携带预期总字节数、摘要和内容格式；分块附独立摘要，完整内容另核对全量摘要。内容 ID 与版本映射到持久源或不可变展示快照，不能仅查询会被覆盖的业务状态。历史输出缺失明确报错，不调用模型重建。

成功 GET 为 200；空增量保留原 lastCursor，不能凭 headSeq 提前前移。跨用户／不存在资源为 404；401 表示登录不可用。409 的 `CURSOR_INVALID/STREAM_CHANGED` 只触发鉴权后的快照重建，`PROJECTION_VERSION_UNSUPPORTED` 触发兼容停止；410 的 `RESET_REQUIRED/CONTENT_VERSION_UNAVAILABLE` 表示原范围无法读取。503 `PROJECTION_READ_UNAVAILABLE` 才按读取退避处理。均返回受控 code 和必要 retryable／supportedVersions，不返回他人资源或原始报文。

## 6. SSE、补读与客户端状态

浏览器对当前可见 Session 保持一条订阅；多个标签页各自只读。切换／关闭只退订。SSE `projection.batch` 的一帧为一个完整 JSON 批次，`id` 为流／序号定位；帧截断不应用。客户端先校验全批，再整体应用并前移应用游标，重复已应用批次忽略，前驱缺口或内容基线不匹配则暂停并补齐。

SSE 解析位置并非应用成功位置。客户端关闭失败消费链，以显式已应用 cursor 重连；浏览器的 Last-Event-ID 不得覆盖或推进该位置。服务端从持久日志顺序发送，内存发送队列和即时通知不是唯一数据来源。

传输控制帧不占业务序号：`caught_up` 标明已发送到本次订阅捕获的 head，只有对应批次已完整应用才结束追赶；`reset_required` 要求重读快照；`auth_required` 停止读取；心跳不推进游标。补读／初始化未完成时，交互处于加载或只读状态，不以半批对象开放动作。具体视觉布局归 #21。

| 客户端情况 | 行为 |
| --- | --- |
| 重复、残缺、乱序、基线不符 | 保留最后已应用位置，停止后续应用，按该位置补读 |
| 必要增量缺失、未来游标、流不匹配 | 明确重建一致快照；不是启动新 Run |
| 慢消费者超出队列 | 关闭本订阅后持久补读，不丢中间事件继续发 |
| SSE 连续失败 | 有界退避后改只读增量轮询；健康轮询期间有节制尝试 SSE |
| 未知内容块 | 纯文本占位、相关动作禁用，其余可理解内容可读 |
| 不兼容批次／坏引用 | 不跳批、不推进游标，一次兼容快照重建；仍失败则保留已确认只读视图并提示更新或不可用 |
| 本地有未保存输入 | 保留独立本地草稿，更新服务端基线并提示冲突，不静默覆盖输入 |

连接状态与业务状态分别显示。网络错误不是 Run 失败；读取恢复不能消除业务 RECONCILING／工具 UNKNOWN。FORM 的 PREPARING／WAITING／ANSWERED／响应 ACCEPTED、CLAIMED、CONSUMED、RECONCILING 及操作确认消费均逐一保留 #19 语义，不能合并成一个“完成”灯。

## 7. 生命周期与历史卡片

当前、有效、就绪的唯一请求修订可响应；历史／过期／失效／已回答卡只读，保留原修订、固定提案及已提交回答／结果。FORM 正式 USER 消息与原卡以 responseId 关联，SDK 仍只接收匹配工具结果，不重复注入正式消息。服务端草稿不是已接纳回答。

| 事实 | 展示及恢复 |
| --- | --- |
| FORM PREPARING 或 pending／checkpoint 未核实 | 可读准备说明，不可提交；不因收到 SDK 事件就变 WAITING |
| FORM 已接纳而未消费 | 显示回答已保存及处理状态；重启后是否可明确继续依 #19 核验，不重新填写／重送 |
| 确认响应 CONSUMED | 表示原确认已消费；发送及结果仍看操作账本，SDK 同步单独记录 |
| 主动取消 | 先显示取消中；外部已发送结果继续核对，不假定撤销 |
| Run 失败／中断 | 保留已接纳用户消息、部分正文和真实工具结果；不产生虚构的成功员工消息 |
| 服务重启／框架状态缺失 | 读取已保存的待核对／暂停事实；启动核对由受控恢复流程执行，GET 本身不执行探测 |
| 备份回退／日志重建 | 开放前核实来源一致性并受控换 streamId；旧 cursor 失效，换流不能解除未决操作 |

普通重启不换 streamId。同一 stream 的序号不回退；受控换流时原流仍可作为历史证据，新的实时流从明确初始化水位开始。当前日志若受损，快照重建只修复展示读取，不作为修复业务事实的证据。留存期限和自动删除策略仍不在本期范围。

## 8. 最小数据结构与接缝

以下为结构设计，当前 DDL 尚未落实：

| 位置 | 必需能力 |
| --- | --- |
| `business_session` | 新增 `projection_stream_id`、`last_projection_seq`；原消息号和 row_version 保留原义 |
| 新增 `session_projection_event` | id、session_id、stream_id、seq、protocol_version、不可变批次 JSON、occurred_at、gmt_create/gmt_modified；`(session_id, stream_id, seq)` 唯一及补读索引，自增 id 不作游标 |
| 扩展 `run_progress` | payload_version／结构载荷、稳定 contentId／contentVersion、sdk_call_key、受控来源引用、首次排序锚点、内容关闭与正式替换关联；关联投影流及序号以支持固定水位过程读取 |
| 既有消息 | 保持 `TEXT/MEDIA`；受控 Markdown 是 TEXT 的展示约定，不据此把所有卡片写进正式历史 |
| 既有工具与交互 | 原账本及 #19 三类记录继续是持久权威，投影日志不复制第二份授权或 SDK 消费账本 |

过程及不可变展示版本须能重建累计正文、历史结果与预览提升；不能只有一份会被覆盖的 display_text。版本关联、归属、内容关闭、正式消息唯一和业务成功一致性仍需服务事务与巡检，单表 CHECK 不足以证明。

#22 须落实所有写路径、锁序、固定 SDK 调用及 checkpoint 接缝、受控换流／恢复、固定版本内容读取和读权限。尤其确认凭据的初次签发与刷新后重新取得仍需专门接缝：当前表只有 SHA-256，不能从摘要还原原 token，#19 的消费入口也不是已经存在的领取能力。领取不得改变原确认、原十分钟期限或消费状态；未具备时不宣称确认闭环可用。

## 9. 资源、读取权限与兼容边界

以下是用户确认的项目初始参数，不是框架默认，尚未经过性能验收。字节数按实际 UTF-8 序列化大小；放宽契约需受控，不静默改变旧交互。

| 项目 | 上限／行为 |
| --- | --- |
| 正文合并 | 最多 100 ms 或新增 4 KiB 即保存；关键状态／终结时立即收尾 |
| 单 Run 正文累计 | 256 KiB；超限停止后续生成，保留已提交内容，按安全终结／待核对收敛，不把截断当完整回复 |
| 摘要／结构块 | 结果摘要 8 KiB；单结构块 64 KiB，表格最多 50 行、20 列；摘要范围明确或用固定版本详情 |
| 历史页 | 默认消息 50／过程 20，请求上限各 100；字节预算先到可少返回并给继续位置 |
| 批次／响应 | 单批 1 MiB、128 项变更；快照／补读响应 2 MiB，大内容固定版本引用 |
| 连接队列 | 每订阅 100 批或 4 MiB，先到者为准；超限断开并补读 |
| 心跳与查权 | 空闲 15 秒，无业务序号；每次读取／发送批次前及空闲心跳复核登录和读取权限 |
| SSE 降级 | 连续 3 次失败改轮询，连接重试退避 1、2、4 秒；健康轮询每 30 秒可试一次 SSE |
| 轮询 | 活跃执行 2 秒，等待／无执行 10 秒；连续 5 次读取失败后暂停自动恢复，提示手动重试 |
| 兼容重建 | 自动重建兼容快照一次，仍不兼容则只读停止，不循环 |

投影在业务事务提交前完成总预算校验。大于 4 KiB 的普通对象优先有界元数据＋固定版本引用，FORM 仍遵守 #19 独立上限；不可分割收尾事先保证项数和载荷可表达。不能先提交业务再补事件或拆开原子批次绕预算。真实工具结果在原协议的同一事务内保存，并以有界摘要／固定事实引用完成投影；不能因显示预算丢弃成功或改成失败。Adapter 未证明有界表达能力时属于发送前准入缺口。

每次读取均验证当前可信登录、账号与本人资源归属。旧游标、sourceRef 和 pageCursor 不携带权限；账号失效停止订阅。员工使用权撤销后依旧规则保留可读历史，禁止新执行；快照的 allowedActions 只是当前提示，所有写动作仍重新鉴权。确认凭据、身份凭据、原始报文不进入批次、快照、过程 JSON 或普通日志；素材签名过期须重新鉴权解析，原件缺失明确显示不可用。

## 10. 验收场景与下游责任

以下均待实施，不能用旧 SQL 验收或本次静态核对宣布通过。至少以可计数模型／工具替身及受控合成数据证明：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 同 Session 两写者交错、回滚与提交 | 已提交序号是前缀；业务／过程／批次不出现单边提交，重复收尾不增消息或批次 |
| 快照并发新消息、新卡、草稿变化 | 对象与 watermark 同视图；接续不漏不重，旧消息和过程分页不混入新版本 |
| 重复、乱序、残缺帧、批次中途应用失败 | 应用游标不提前前移，整批成功后才推进 |
| 最终文字修订、预览提升、迟到 delta | 正式回复一条、替换一次，已关闭内容不复活 |
| 原 Run 多 SDK 调用、FORM 回答及下一张卡 | 来源可追溯、顺序可恢复、一次接纳／领取，无重复注入或第二次授权 |
| 慢连接、通知丢失、SSE 失败与轮询 | 持久补读完整；所有 GET 的模型调用／SDK 执行／会议写发送数为零 |
| 未知块、未知批次、错误摘要或缺失内容版本 | 占位或只读停止有界，不执行载荷、不跳过失败批次 |
| 工具成功后模型失败，取消时结果不明 | 真实成功回执保留；Run 状态独立，UNKNOWN 不假装失败或撤销 |
| 重启、框架状态缺失、备份回退／重建 | 普通重启保持流；受控换流后旧 cursor 失效，不重发模型／工具、不清除待核对 |
| 双标签草稿竞争、旧修订、确认过期 | 本地未保存输入保留；旧卡不可操作，不延长确认或重复消费 |
| 撤权／停用、跨用户 cursor／引用、失效素材签名 | 读取与动作边界均成立，凭据不出现在投影及普通日志 |
| 大正文／长历史／超预算批次与队列 | 边界明确，固定版本详情可读，真实结果不因预算丢失，无假完整回复 |
