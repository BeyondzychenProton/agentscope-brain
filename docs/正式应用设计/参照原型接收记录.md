## 后续设计需要校对的差异

以下是参照与[已确认范围](README.md)及[既有会话、运行和操作规则](../数据库设计/会话运行与消息/业务会话运行消息与跨渠道续传设计规格.md)之间的校对点，不在本记录中另作设计选择。

1. 原型包含角色切换、管理页面和多个工作区。正式一期仍不开放管理员 Web 登录、管理页面或管理 API；普通用户身份由真实服务端登录取得。原型的“工作区”导航也不能直接等同于 AgentScope 的文件 Workspace。
2. 表单与卡片目前由专用函数及演示状态拼接，不能据此认定已有通用字段 Schema、服务端校验、一次性提交或可恢复的交互请求。
3. `demoWait()` 依赖进程内 Promise；刷新、断连、过期、重复提交、撤权和服务重启后的处理，仍由后续交互生命周期与事件投影议题明确。
4. `thinkHTML()` 显示预设的“思考过程”文本。它不证明框架或模型提供了相同内容；正式执行过程仍须区分阶段进度、工具动作、结果摘要与正式回答，并在对应议题中确定可展示内容。
5. `selectSession()`、`newChat()` 调用本地中断函数。不能把这种演示中断直接当作服务端 Run 取消，更不能据此认定已经发送的外部写操作被撤销。
6. 演示使用 `meeting.reserve` 等工具名及预置成功回执；实际工具、参数与核验能力以会议 MCP 合同及后续目标环境证据为准。原型不构成模型、Skill、MCP 或持久化接入证据。
7. 原型演示冲突后重试、选择备选房间后继续创建。正式工具操作仍按[通用操作设计](../数据库设计/会话运行与消息/通用素材与工具操作设计.md)处理：不能从演示推导自动重试许可；改房间或参数必须建立对应新提案并取得有效确认，结果不明时保持核对路径。
