## 2. Q1：实施主线（已确认）

用户于 2026-10-25 回复“同意”，接受“先验证关键风险，再按用户链路逐片贯通”的七阶段主线：

| 阶段 | 主要成果 |
| --- | --- |
| 0. 关键风险探针 | 实际依赖兼容、SDK pending 就绪／消费／安全终结及 CAS。 |
| 1. 基础与登录 | 新 SQL、初始化、单账号登录／首次改密、权限及前端基础工程。 |
| 2. 文字对话闭环 | 真实模型、Session／Run／消息持久化、流式投影、刷新重读、搜索改名。 |
| 3. 图文闭环 | 私有 MinIO、真实图片上传／读取、图文模型输入、提交回查及清理竞争。 |
| 4. 人机交互闭环 | 动态表单、草稿冲突、原 Run 续接、独立确认及凭据恢复。 |
| 5. 真实会议闭环 | 可信身份查询、本人确认预约、结果核验、独立确认取消、UNKNOWN 核对。 |
| 6. 联合总验收 | 跨阶段故障、联合恢复、后台记忆／Workspace 及完整 PC 浏览器矩阵。 |

第一项可体验的业务里程碑为“真实登录 → 文字对话 → 持久保存 → 刷新后准确恢复”。

每阶段同步完成必要的权限、并发和失败恢复验证；阶段 6 集中验证跨链路行为，不能将所有异常验证拖到最后。后台记忆与 Workspace 从运行阶段开始接入验证，联合阶段覆盖跨存储恢复。

外部输入缺失时，阻断对应真实验收，其他独立工作继续推进。具体阻断范围和阶段完成标记按下方已确认的 Q2—Q3 处理，不允许绕过既定准入门槛。

## 3. Q2：按依赖范围阻断（已确认）

用户于 2026-10-25 回复“全部采用”，确认：

- 实际依赖组合不兼容时，阻断使用该组合的后端接入；前端和独立 SQL 验证仍可继续。
- SDK 普通运行所需的状态保存、可信调用隔离或 CAS 未通过时，阻断阶段 2 的真实运行闭环。
- pending 消费／安全终结未通过时，阻断阶段 4 中依赖这些能力的交互功能；已经验证通过的文字、图片链路可以继续。
- 失败项回到设计修正，经相应探针通过后再开放对应功能；不擅自关闭校验、shade、fork 或变更已确认的 SDK 路线。

七阶段是业务主线与完成依赖，不意味着任何未完成探针都使全部独立工作停摆；也不意味着可跳过具体能力的准入证据。

## 4. Q3：隔离验证与真实验收分开（已确认）

用户于 2026-10-25 回复“全部采用”，确认：真实外部输入未齐时，允许用可计数、可复现的替身继续独立开发和隔离集成，分别记录隔离验证结果与真实验收结果。

例如会议环境未就绪时，可完成确认界面、操作账本和超时／未知结果的隔离测试，但真实预约、核验、取消仍为待验收；模型和 MinIO 输入不足时同样处理。替身不能冒充真实 SDK／Store 接缝已经通过，也不能冒充外部服务和业务效果。

后续独立工作可以继续；对应阶段必须取得所需真实证据后才能标记通过。未通过的阶段须列出缺失输入、失败项、阻断能力和可继续的独立工作，不把“开发或隔离验证完成”写成“阶段已通过”。

## 5. Q4：开发环境与真实上线环境（用户调整后确认）

用户于 2026-10-25 明确调整为两种环境：开发环境与真实上线环境，不另设独立的集成验收环境。

- 开发环境：用户提供模型接入，以及供测试使用的 MySQL、MinIO 资源。开发环境可以连接这些真实测试资源完成集成验证，并在其中安排隔离夹具、可计数替身与故障验证；不能将开发环境整体理解为全部使用模拟依赖。
- 真实上线环境：实际服务运行环境，具体主机、模型、MySQL、MinIO、HTTPS／代理及秘密配置列入后续实施输入。
- 两种环境的名称不决定机器数量或部署方式；本轮不预先指定新服务器、容器平台或额外环境。
- 会议 MCP 的开发／上线目标与版本、账号、可用测试会议资源仍需在相应实施输入中明确；本条不假定现有会议地址已经过目标核验。
- 两环境的完整验收、上线核验及恢复演练分工按下方 Q6；此前 Q4 建议中的单独“真实集成验收环境”不采用。

## 6. Q5：真实依赖最小能力提前预检（已确认）

用户于 2026-10-25 回复“采用”。后续实施中，外部输入齐备后尽早验证最小能力，不等待所属业务阶段末尾，也不改变七阶段的完成依赖：

- 真实预约／取消仍在阶段 5，满足本人独立确认与真实写入执行条件后进行。

预检只证明对应能力，完整 Web 链路仍需在所属阶段验收。当前只确认验证路线，没有执行外部预检、调用模型或进行会议写入。
