每阶段分别列出开发完成情况、隔离验证结果、真实验收结果和阻塞项；这些是交付记录，不新增产品运行状态。只有该阶段的准入、必需真实证据和退出条件全部满足才标记通过。不能把可演示、HTTP 200、SDK 事件、旧 SQL 通过或阶段后续工作已开始作为阶段通过依据。

## 4. 环境与前置输入

### 4.1 两环境分工

开发环境同时承担本地开发、自动化／隔离验证和真实测试资源集成。模型、MySQL、MinIO 测试资源由用户提供；计数替身仅用于确定性故障与副作用证明。故障注入、撤权夹具和破坏性恢复使用开发资源内的隔离测试数据或可重建副本，不增加第三种正式环境。

真实上线环境使用实际构建产物、同源 HTTPS 和目标资源。开发与上线资源、配置及秘密按环境隔离；开发 Cookie 与生产 Cookie 不能混用。开发回环 Vite 代理可用于日常调试；生产 Cookie／CSRF、SSE 代理及同源 HTTPS 在开发可用的相应配置中验证，并在上线目标再次核验。

### 4.2 实施输入清单

| 输入 | 最迟阻断点 | 核验与记录要求 |
| --- | --- | --- |
| 目标 OS／JDK 制品、构建运行时 | 阶段 0 的相应构建／阶段 6 上线目标核验 | 精确版本、官方制品与校验；前端精确依赖和完整锁文件，后端 effective POM／完整 tree。 |

### 4.3 提前预检

输入齐备时验证模型的文本流式、图像、工具调用、结构化输出及所需组合；MinIO 私有对象读写与完整性；MCP 目标版本／tools/list／只读身份和查询。身份链须经真实平台登录另外证明。预检不能替代阶段 2—5 的 Web、持久化与业务结果证据，真实写仍在对应执行范围内开展。

## 5. 阶段 0：关键风险探针

**输入：** #22 固定初始基线、构建制品、SDK v2.0.4 固定源码依据和隔离状态库。探针使用真实选定依赖／Store；模型与工具使用无网络、可计数实现。

**工作与退出条件：**

1. 保存实际 effective POM、完整 dependency tree、目标字节码／编译和 Boot／MyBatis 自动配置结果；核对双 Jackson、Reactor／Kotlin、MinIO 与 SDK 的实际组合。
2. 同一真实 classpath 中，networknt 3.0.6 同时通过 SDK 默认 ToolValidator 入口和应用 draft-07／format／封闭引用／错误路径验证。失败阻断该组合并回到设计，不自行 shade／fork／关校验。
3. 按选定 JDBC Store 实际结构验证新状态、版本保存及独立读回、可信调用绑定、错 owner／Session／发布／slot 拒绝、CAS_FAIL、旧 writer 拒绝、存量状态缺失拒绝；不以 OVERWRITE／merge／冲突重载执行绕过。
4. 验证 pending 就绪、回答消费和无执行终结的前后持久证据；覆盖事件已到但保存失败、证明丢失、终结提交不明、重启和旧 writer 竞争。仅支持既定唯一平台输入 pending，未知／混合／多 pending 不自动修复。
5. 计数证明终结过程模型调用与其他工具发送增量为零；不能证明旧调用静止／退出时不开放终结，保留 RECONCILING 与 Session 阻断。

Memory／Workspace 的 `JdbcStore.putIfVersion` 返回值与独立读回、自定义 namespace／文件路由、合并 watermark 重定向及原生写入口接管，先做固定版本接缝核验，阶段 2 完成真实存储往返与竞争证明。源码尚未复核或接口往返不成立时，阻断相应能力；不能以 KV 中存在一行代替隔离协议通过。

**证据：** 构建／依赖结果、可复现隔离用例、状态前后版本／摘要／独立读回、调用计数和失败结果。普通运行探针与 pending 探针分别给结论，按 Q2 阻断关联功能。

## 6. 阶段 1：全新库、预置、身份与前端基础

**输入：** 已通过的后端实际依赖、全新开发 Schema、真实单用户预置输入、发布／Skill／绑定完整配置和前端构建运行时。

**工作与退出条件：**

1. 生成并验证 #22 必要数据调整，分别核验平台业务表、SDK 表、Session JDBC 表；保留原数据库已定规则。新 CHECK／唯一性、CAS、跨行引用巡检及正反探针覆盖交互、投影、暂存／提交、调度／调用／终结、nonce 和初始化来源。
2. SYSTEM_BOOTSTRAP manifest、来源、预置事实与成功收据一致；重复初始化不重置密码、不覆盖历史、不补回撤权。只预置一个普通用户，不创建系统用户或管理员；结构缺失拒绝就绪，合法撤权不被启动修复。
3. 登录、受限首次改密、CSRF、密码编码／字节边界和改密部分成功窗口可验证；前端可以真实进入工作台。固定 24h 绝对期限、SSE／轮询不续期、多浏览器并行和仅退出当前认证会话均有服务端证据；使用受控测试时钟／夹具覆盖期限边界，不改短生产规则冒充验证。
4. 首次改密前拒绝业务访问；旧安全版本、撤权、跨用户引用通过隔离夹具验证。区分账号失效与员工使用权撤销，后者保留既定本人历史只读语义，禁止新执行。退出／到期不合成 Run 取消；对应运行与 SSE 查权在后续阶段补充集成证明。
5. 前端保存精确直接依赖和完整锁文件，独立类型检查与生产构建通过；路由、认证错误分层和基础工作台使用真实后端身份。模型／MCP／MinIO 临时不可达不禁止登录及允许的既有文本历史读取。

**证据：** 新 DDL 与初始化核验、结构修订和巡检结果、重复初始化差异、真实登录／改密与 Session 记录、权限负例、前端锁文件／构建。既有 29 表 SQL 结果仅作旧结构输入。

## 7. 阶段 2：真实文字对话与持久投影

**输入：** 阶段 1、普通 SDK 探针、实际模型与固定发布／Skills；实际 Memory／Workspace 存储配置和既定隔离规则。

**工作与退出条件：**

1. 真实登录后首次文字接纳，平台事务一致产生 Session、USER 消息、Run、调度与投影；同键重试返回原事实，同键异参拒绝。文字提交的原键回查／封闭及迟到接纳竞争先完成，图片绑定场景在阶段 3 扩展。
2. 实际 SDK 调用与模型流式结果可追溯，SDK 保存／独立读回与平台最终收尾分开证明；每 Run 至多一条正式员工回复，重复收尾、预览提升与迟到 delta 不重复或复活内容。持久过程只呈现可信阶段／动作／结果，不展示原始模型思考。
3. 真实 C0／dispatch 验证最多 2 执行许可、16 普通等待、同 Session 活动占用与许可分离；无容量不留下半条消息。各写路径遵守 C0 优先锁序，模型／网络不跨事务持锁。
4. 快照／watermark 同一 read view、事务批次为已提交前缀；分页和详情固定边界／内容版本。整批 reducer 在重复、乱序、缺口、残缺帧、坏引用和应用失败时不提前推进 cursor。
5. SSE 断线／慢连接／通知丢失／轮询降级、刷新及普通进程重启后重读持久事实；全部 GET／SSE／补读和启动核对的业务模型／SDK 执行／会议写计数为零。覆盖 #20 的正文／批次／队列／详情预算、未知协议有界停止、一次兼容重建、15s 查权及既定退避，预算提交前校验。未领取任务由本人明确继续，已领取／保存不明保持待核对；不因 lease 或新 epoch 猜测旧 writer 静止。
6. 普通会话全范围标题搜索、稳定分页、改名、切换和标签页文字草稿恢复通过；真实 IME／键盘、退出／失效清理及服务端权限一致。Markdown 解析／净化在真实 DOM 核验，链接过滤、禁原始 HTML／Markdown 图片、代码复制和纯文本回退符合 #21。
7. 后台记忆与 Workspace 从本阶段接入：Run 固定当前有效 generation／documentRevision／策略与内容快照，AgentState 槽不复用，Workspace 不跨 Session 泄漏；读／写／追加／枚举／检索／下载与路径规范化全入口验证。实际 `JdbcStore.putIfVersion` 写后读回、SQL 两阶段激活、namespace／水位隔离及原生 append／覆盖旁路拒绝均需实证，压缩拒绝写入不能破坏业务运行。
8. 仅成功 Run 的正式消息按既定输入顺序、有效代次／授权登记去重学习任务，独立 1 worker／5s 扫描；失败／取消不误学，Memory 失败不推翻业务成功。用内部夹具验证清空／更正、旧候选／缓存／任务及重授权不复活，保持有效空文档与缺失／损坏不同。只读业务恢复不启动业务推理，已授权记忆任务按自身协议恢复；不新增管理 UI／API 或失败任务人工重试入口。
9. 通过受控发布／配置夹具验证旧 Session 固定原发布与 Skill 正文／资源摘要，当前默认指针变化不迁移旧会话，Workspace／缓存／本地模板不能旁路覆盖固定定义；不新增版本管理 Web 界面或接口。

**证据：** 真实浏览器操作、平台消息／Run／调用关联、SDK 持久状态、实际模型结果、提交与投影并发结果、重读零执行计数、Memory／Workspace 隔离与版本证据。首个可体验里程碑在本阶段完成，图文／交互／会议仍待后续。

## 8. 阶段 3：私有图文与提交恢复

**输入：** 阶段 2 相关能力、真实开发 MinIO、模型图像能力和明确的图片数量／字节／像素限制。

**工作与退出条件：**

## 9. 阶段 4：动态表单、独立确认与安全终结

**输入：** 阶段 2、pending 探针、form-v1 前后端一致 fixture、独立 keyring；图文组合依赖阶段 3。真实会议写效果留在阶段 5，隔离工具仅证明确认协议。

**工作与退出条件：**

2. 共享 fixture 覆盖严格 +08:00 秒格式、类型／格式／业务错误和字段路径；不关闭 format、不隐式代填／转换，不完整草稿可保存。候选刷新 POST 仅允许受控目录只读查询，故障不伪造有效候选。32 字段／8 分组长表单、半高容器／固定动作区、已知错误及首错定位在真实浏览器观察。
3. 双标签草稿竞争保留本地输入；旧 revision／draftRevision／候选变化可解释拒绝。双击／同键／换键重复不增加响应、正式 FORM USER 消息、输入序号或 SDK 领取；FORM 续接原 Run，不改最初输入指针、不重复注入或新增学习任务。
4. 覆盖接纳后领取前退出、领取／消费／保存中退出、SDK 成功而平台未收尾；只有真实证明才标消费完成。已接纳回答／已消费确认的续接不被 16 普通等待限额丢弃。
5. 取消／过期／修正耗尽先使卡失效，再验证无执行 pending 持久终结；旧调用静止、CAS、独立读回和终结证据齐备才收敛。证明缺失、错槽、多 pending 或未知外部写仍保持 RECONCILING，原 Session 不开放新 Run。
6. 固定提案本人明确确认与 FORM 分开；原十分钟期限、用户／安全／号码／授权版本绑定、一次事务消费及操作待发送均证明。刷新凭据返回原 token，不改原期限或状态，GET／投影不含秘密。
7. nonce 独立短事务明确预留提交后加密，领域锁不嵌套；并发、确认回滚／崩溃、预留提交不明、密文／AAD 篡改、旧 key 缺失和重复领取均验证。回退后换 key 的联合演练在阶段 6。

**证据：** form fixture 两端结果、真实模型→校验→Web 卡→正式回答→原 Run 续接、计数零执行终结、并发／失败窗口和独立确认账本。确认消费不证明已发送或会议成功。

## 10. 阶段 5：真实会议闭环
