# 后端工程与开发规范

> 建立日期：2026-10-26。适用于正式 `backend/`；阶段 0 历史快照见 [归档说明](../archive/stage0-backend/ARCHIVE.md)。本规范规定工程组织与开发方式，不代替业务规格或阶段验收。

## 1. 权威输入与工程形态

- 领域命名使用 [GLOSSARY.md](../GLOSSARY.md)。业务行为、HTTP、锁序和数据规则分别沿用 [后端主规格](../docs/正式应用设计/后端工程与用户链路设计规格.md)、[接口与事务契约](../docs/正式应用设计/后端接口与事务锁序契约.md)、[数据与初始化契约](../docs/正式应用设计/后端最小数据调整与初始化契约.md)及当前工单。
- 一个 Spring Boot 应用、一个 Maven 模块、一个生产 Java 进程。业务模块采用 Java 包组织；不拆 Maven 子模块或微服务，不建立重复的 core/common/service 聚合工程。
- 唯一根包为 `com.agentscope.brain`，唯一启动类为 `AgentScopeBrainApplication`。前端后续位于仓库 `frontend/`，独立构建，与后端通过同源 HTTP／SSE 协作。
- 保持已经验证的 Java 17、Boot 4.1.2、AgentScope 2.0.4 等依赖基线。新依赖先核对必要性、实际依赖树及相关兼容测试；不用 SDK BOM 覆盖 Boot 管理的整个依赖平台。
- 本次只建立工程骨架。正式登录、初始化、业务用例、MinIO／模型／会议调用和上线仍按各阶段实施；禁止用包目录或启动成功宣称业务已完成。

```text
agentscope/

│   │       └── internal/              # 按需建立，模块实现

│   │           ├── application/      # 用例、事务协调

│   │           └── integration/      # SDK／MinIO／MCP 等适配
│   ├── src/main/resources/
│   │   ├── application-dev.yaml      # 开发 HTTP／Cookie 差异
│   │   ├── application-prod.yaml     # 生产 HTTP／Cookie 差异

│   ├── src/test/resources/           # 独立测试配置、合成 fixture
│   ├── config/application.yaml      # 共用资源实际值、公共基线与运行环境，Git 忽略
│   ├── scripts/                     # 工程检查；不承载业务管理 CLI
│   ├── target/                      # 可再生输出，Git 忽略
│   └── resource.txt                 # 本地资源交接，Git 忽略

├── db/tests/                        # 数据约束／并发／巡检 SQL
├── verification/                    # 工单证据按 issue-<编号>/，无编号工程记录放 engineering/
├── archive/stage0-backend/           # 历史探针快照，不参与正式构建

```

内部各层只在存在真实职责时创建，不为每个实体生成五层转发或成套空文件。当前先创建九个模块的职责声明，随着用例实施补充 `api/`、`internal/` 和资源文件。

旧探针、临时程序、SQL 导出、抓包、构建报告和本地秘密不能进入 `src/main/`。只在 `src/main/resources/` 放实际运行需要的无秘密资源；禁止把仓库根目录或 `config/` 整体添加为 Maven resources。

## 3. 九个业务模块

| 模块 | 对外接口负责的事 | 实现中管理的内容 |
| --- | --- | --- |
| `identity` | 取得可信平台用户、改密、退出、复核执行资格 | Security、Session JDBC、密码、安全版本、Cookie／CSRF |
| `release` | 读取当前可用员工能力与固定发布快照 | 授权关联、发布摘要、Skill／模型／工具绑定、只读装载 |
| `conversation` | 会话列表／改名、新建意图、普通提交接纳与封闭 | 正式消息、原键幂等、序号及初始 Run 原子接纳 |
| `media` | 上传准备、核验、绑定、鉴权读取与废弃 | MinIO 原件、图片校验、暂存期限、引用与清理竞争 |
| `interaction` | 动态表单结构、草稿、回答接纳与允许继续 | 结构白名单、Schema、业务校验、唯一响应与修订竞争 |
| `operation` | 固定提案、本人一次确认、执行领取和结果核对 | token／nonce、稳定请求标识、会议适配、UNKNOWN 与回执 |
| `runtime` | 原 Run 调度、续接、取消、检查点和安全终结 | SDK 调用绑定、fence、状态 CAS、容量和独立终结证据 |
| `projection` | 一致快照、分页／详情、持久批次与 SSE | 只读 read view、水位、展示版本、补读与读取预算 |
| `memory` | 成功 Run 学习登记、有效任务领取及应用 | 有效代次／修订、KV、Workspace 路由、提取／合并与持久任务 |

`SYSTEM_BOOTSTRAP` 初始化属于阶段 1 的受控 SQL／初始化契约，结构与预置脚本放 `db/`，身份与发布事实仍归所属模块；不因此创建管理员端、维护 CLI 或运行时自动修复模块。

## 4. 模块接口与依赖

1. 跨模块调用仅依赖对方的 `api` 包；对方的 Controller、Mapper、持久化对象、SDK 对象和 `internal` 类均不是共享接口。模块内部可直接协作，不为单一实现机械增加接口。
2. 接口以业务用例和不变量组织，明确可信身份、前置状态、幂等键、成功事实与错误结果。返回稳定结果或不可变值，不泄漏数据库连接、可变运行实例或 SDK 内部状态。
3. `web` 只解析协议、取得可信 actor、调用用例并映射结果；不直接调用其他模块 Mapper、拼接 SDK Agent 或发送会议请求。
4. `application` 协调本次用例；事务内跨模块写入需通过明确约定的接口参与同一平台事务并遵循既定锁序。不跨模块直接改表，不用异步通知替代必须原子的接纳事实。
5. `domain` 不依赖 Controller、Servlet、Mapper 或外部 SDK。只有实际需要可替换实现的地方才设适配接口，不先建立通用框架。
6. `identity` 提供可信身份，`release` 提供固定能力；写用例复核授权。`conversation`／`interaction`／`operation` 组织接纳，`runtime` 执行，`projection` 读取持久事实，`memory` 消费成功事实。协作通过窄接口，禁止形成循环依赖。
7. `projection` 和其他读取／恢复路径不得启动模型、业务 Run 或会议写操作。退出／过期不等同于取消已接纳 Run；结果不明只核对原操作，不创建第二次执行。
8. 时间、ID 或错误等少量重复能力先保持归属；确有多个业务调用者后才提取小型共享代码。不得建立装满业务规则的 `common`、`utils` 或全局万能 Service。

运行状态必须绑定可信用户、固定发布、业务会话／Run、状态槽／代次、callKey 和 fence；禁止共享单例持有可变 currentUser／currentSession。跨模块协作不能降低上述可信归属或 CAS 规则。

## 5. 共用资源与配置

2026-10-26 用户明确：开发环境与生产环境共用提供的资源。本条更新旧实施路线中“资源、凭据按环境独立”的假设；不改动已经关闭的历史设计 Issue。开发、生产仍分别记录实际配置与验收结果，Cookie 配置分别生效。

- [resource.txt](resource.txt) 仅保留在本机，不自动导入应用，不复制到可提交文档、源码、证据或截图。
- 2026-10-26 用户明确要求配置直接写入 YAML：共用服务的真实连接、账号、密码、公共参数和逐项中文说明统一放本机 [config/application.yaml](config/application.yaml)，不再使用资源环境变量占位符、example 模板或额外 import。该实际文件被 Git 忽略、不打入 JAR；`src/main/resources/` 只保留无秘密的 dev／prod HTTP／Cookie 差异。
- 运行环境直接在该 YAML 的 `spring.profiles.active` 中填写 `dev` 或 `prod`；当前明确填写 `dev`，上线改为 `prod`，禁止同时激活。使用默认启动命令时工作目录为 `backend/`；其他目录启动显式提供配置绝对路径。
- 共用 MySQL／MinIO 地址不表示数据区已隔离。执行前明确完整数据库名、bucket／前缀及已有数据；若实际共用同一数据区，按生产数据处理。当前资源交接没有确定数据库名、bucket 或环境划分，禁止补猜并连接。
- 同实例内的开发库、隔离 Schema 和对象前缀可作为逻辑隔离方案；必须实际建立、查权和验证后才记为隔离完成。本次只提供配置位置，不新建或修改在线资源。
- 保持 `spring.sql.init.mode=never`、`spring.session.jdbc.initialize-schema=never`。正式初始化经对应工单的受控过程执行，不在启动时建表、预置账号、重置密码、补授权或删除历史。
- Session 清理暂时关闭，待身份结构与生命周期实现后在所属工单配置；不能为测试方便删除共用 Session 或业务表。
- Redis 资源仅登记可用输入，当前架构仍用 Session JDBC；未使用前不增加 starter、不实例化客户端。
- 模型／MCP／确认密钥按所属阶段的独立秘密引用配置。日志只记资源别名、构建／发布指纹、错误分类和关联 ID，不打印连接口令、token、密文或完整配置。

## 6. 数据、事务与外部调用

- 平台建表、SDK 原生表、Spring Session 表分开管理。平台结构以 `db/schema/` 为唯一来源，不在 Java 注解、resources 和脚本各留一份可变 DDL。
- 普通 CRUD 可使用 MyBatis-Plus；锁定读取、CAS、幂等、序号和复合状态更新用显式 SQL，XML 位于 `mapper/<模块>/` 并与 Java namespace 对应。
- 用例组织短平台事务，锁序遵循已有契约。外部模型、MCP 和对象存储调用不占用长数据库事务；提交不明先独立核对事实。
- 平台 SQL、Session JDBC、SDK Store 与 MinIO 不假定原子。跨存储失败窗口、补偿条件和独立读回证据必须随功能实现。
- 公共标识及时间格式沿用接口规格；不把渠道 ID／手机号当平台用户主键，不由客户端指定可信 owner／操作者。
- 手工修改／清空记忆、未知会议结果、正式原件引用与备份恢复继续遵守已确认契约，不用工程整理改变业务含义。

## 7. 测试、证据与构建

- `src/test/java/` 与生产包对应，测试真实接口和业务不变量；需要的替身／合成数据放测试目录，不发布到生产 JAR。
- 默认 `verify` 只运行确定性的本机隔离测试，不要求资源交接文件、共享服务口令、真实模型或会议。当前装配测试只装载 `application-test.yaml`，使用 H2 和回环临时 HTTP。
- H2 验证装配与接口，不能代替 MySQL 的排序规则、约束、锁和并发证明。新增真实 MySQL／MinIO／MCP 验证显式选择隔离目标，独立记录执行范围与环境，不放入默认测试自动执行。
- 测试 profile 是自动化夹具配置，不新增第三个业务验收环境。真实开发与上线验收仍按既定路线分别记录。
- 新验收材料放仓库 `verification/issue-<编号>/`，无工单编号的工程整理记录放 `verification/engineering/`；记录契约、环境／构建指纹、复现、预期／实测、持久读回、调用计数及缺口。临时输出放 `target/`；原始报告先检查脱敏再留存。
- 依次运行 `scripts/检查工程规范.ps1` 与 `mvnw.cmd -B -ntp verify`。正式打包由 Boot 插件生成可执行 JAR，必须确认无 `Probe`、历史证据、本地配置、resource.txt 和测试夹具混入。
- 变更依赖或 SDK 适配时补跑相关兼容测试。测试已通过后，只在有新修改、失败或未决疑点时扩大复验，不重复跑无关套件。

## 8. 开发交付顺序

1. 读当前工单和相关规格，核对本地工作区，先明确本次属于哪个模块与数据事实。
2. 只创建本用例需要的接口和实现；跨模块协作先确定接口、事务和锁序，再写调用方。
3. 以隔离夹具验证正向、权限、幂等、并发与失败窗口；真实外部证据单列。
4. 运行工程检查、相关测试与打包，更新实际证据和已知限制。工单关闭数量、骨架启动和截图均不替代阶段退出条件。
5. 提交、推送、部署与真实会议写按对应执行指令进行；已关闭 Issue 保持原样。新增规范不能被解释成这些外部操作的授权。
